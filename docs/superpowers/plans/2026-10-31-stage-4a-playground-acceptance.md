# Этап 4а, часть 5: страница «Грид» и приёмка. План реализации

> **Для исполнителя:** шаги отмечены чекбоксами (`- [ ]`). Задачи выполняются по порядку; `pnpm check` обязателен перед каждым коммитом (код возврата проверяется отдельной командой).

**Цель:** закрыть критерии приёмки раздела 13 спека этапа 4а: воспроизводимый замер производительности на 100 000 × 12 (критерий 1), недостающие автопроверки (критерии 4, 5, 6 и смена размера), приёмка руками в Chrome в обеих темах и трёх размерах, итоги этапа и подготовка тега `v0.5.0`.

**Архитектура:** код грида меняется только если замер покажет провал критерия 1; всё остальное это playground (`grid-checks.ts`, новый `grid-perf.ts`), спек и приёмка в браузере. Замер вынесен из одноразовых скриптов в кнопку страницы: прежние цифры в спеке (разделы 18, 19, 20) получены разными способами и несопоставимы.

**Стек:** Solid 1.9, vitest 5 (jsdom), Vite production-сборка, Chrome (`claude-in-chrome`), дисплей 120 Гц.

**Спек:** `docs/superpowers/specs/2026-10-31-stage-4a-grid-core-design.md` (раздел 13 критерии, раздел 14, разделы 18–20 итоги частей 2–4); части 1–4: `…-stage-4a-pure-functions.md`, `…-stage-4a-table.md`, `…-stage-4a-sort-and-selection.md`, `…-stage-4a-menu-panels-states.md`.

## Глобальные ограничения

- Репозиторий публичный: ни ключей, ни токенов, ни `.env`, ни корпоративной почты в коммитах.
- Один класс/компонент/функция — один файл (kebab-case).
- ESLint: табы, одинарные кавычки, длина строки ≤ 140 вместе с комментариями, без комментариев в конце строки, `solid/reactivity`, `exactOptionalPropertyTypes`. Stylelint: нативная вложенность везде (глобальный `CLAUDE.md`), без литералов цвета в компонентах.
- В боевом коде нет проверок под jsdom; заглушки в `src/test-setup.ts`.
- pnpm запускается как `env -u HTTPS_PROXY -u HTTP_PROXY -u https_proxy -u http_proxy pnpm …`; dev-сервер playground на порту 5173 не трогать; вкладки Chrome закрывать; временные серверы останавливать только по PID после проверки `cwd` (`lsof -a -p <PID> -d cwd -Fn`), без `pkill`.
- Chrome: `browser_batch`, `wait` не больше 10 с, без JS-диалогов; прогон `.checks` занимает 15–25 с, страницу посреди него не перезагружать; навигация на тот же URL с хэшем страницу не перезагружает (для чистого состояния `location.reload()`).
- Тег не ставится и ничего не пушится без отдельного слова владельца.

## Состав части и решения

1. **Замер на странице, а не в консоли.** Кнопка «Замер прокрутки» запускает последовательность: для каждой скорости (1500, 3000, 20 000 px/с) три захода по 4 с, первый заход отбрасывается как прогрев; результат — медиана доли кадров длиннее 16,7 мс и худший кадр. Порядок скоростей фиксирован, перед заходом `scrollTop = 0`. Вывод в `<output data-grid-perf>`; цифры в спек идут только оттуда.
2. **Перед замером** выбираются конфигурации: `selectable` вкл/выкл, колонка `Select` вкл/выкл (флажок на странице), разная высота строк (колонка переноса) всегда включена. Критерий 1 проверяется на «боевой» конфигурации демо (все колонки, `selectable` вкл).
3. **Оптимизация только по цифрам.** Если медиана при 20 000 px/с выше 5 % или при 1500/3000 px/с хуже базы `9339745`, проверяются по очереди (каждый вариант замеряется отдельно, оставляется только дающий выигрыш больше разброса): `createSelector` для состояния выбора строки вместо чтения множества каждой строкой; более лёгкая разметка чекбокса в строке; ленивое создание `Select` (панель монтируется при открытии). Решения вносятся в спек как отступление.
4. **Автопроверки дописываются** для критериев 4, 5 (чекбокс, закрытие прокруткой), 6 (открыта при прокрутке, закрыта при выходе строки) и смены размера; то, что нельзя сделать синтетическими событиями (настоящие Tab, Esc зажатой кнопкой), идёт в приёмку руками.
5. **Приёмка руками** по таблице «тема × размер» с зафиксированным результатом; расхождения чинятся здесь же, если правка мала, иначе записываются в раздел 15 спека.

### Task 1: Замер прокрутки на странице

**Файлы:**
- Создать: `playground/src/grid-perf.ts` (функция `measureGridScroll(scroller, speed, durationMs)` и `runGridPerf(scroller, report)`).
- Изменить: `playground/src/demo-grid.tsx` (кнопка и `<output data-grid-perf>`, флажок `data-grid-select-column` для колонки `Select`), `playground/src/grid-checks.ts` (не затрагивается).

- [ ] **Шаг 1: `grid-perf.ts`.** Заход: `scrollTop = 0`, пауза 500 мс, затем `requestAnimationFrame`-цикл: на каждом кадре `dt = t - last`, `slow += dt > 16.7`, `scrollTop += speed * dt / 1000`; результат `{ frames, slow, worst }`. `runGridPerf` для каждой скорости делает 3 захода, первый отбрасывает, медиану берёт по доле, `worst` максимум; результат пишется строкой `скорость: доля % (кадров N, худший M мс)` через `report`.
- [ ] **Шаг 2: страница.** Кнопка «Замер прокрутки» (disabled на время замера), `<output data-grid-perf>`, переключатель колонки `Select` (для разделения стоимости ядра и содержимого). Колонки собираются `createMemo`.
- [ ] **Шаг 3:** `pnpm check` (код возврата отдельно), коммит `feat(playground): замер прокрутки грида на странице`.

### Task 3: Недостающие автопроверки

**Файлы:** `playground/src/grid-checks.ts`.

- [ ] **Шаг 1 (критерий 5):** Shift+F10 на чекбоксе строки открывает меню, закрытие настоящей прокруткой колесом через `scroller.dispatchEvent(new WheelEvent(...))` недостаточно: прокрутка меняет `scrollTop`, меню закрывается; пункт меню не меняет выбор.

- [ ] **Шаг 3 (критерий 4, частично):** для кнопки сортировки, чекбокса строки и `Select` в ячейке: выставить фокус программно клавиатурным способом (`element.focus({ focusVisible: true })`), прокрутить вправо так, чтобы элемент оказался под sticky-колонкой, затем `scrollIntoView` не вызывать: проверить, что `scroll-padding` грида выводит элемент из-под шапки и закреплённых колонок (прямоугольник элемента лежит внутри прямоугольника области прокрутки минус высота шапки и ширина закреплённых). - [ ] **Шаг 4 (смена размера):** `data-s-kit-size="lg"` и `"sm"` на обёртке демо: высота шапки и высота строк меняются, первая строка после прокрутки на 50 000 строк по-прежнему лежит сразу под шапкой (зазора и наложения нет), число `<tr>` в DOM остаётся в пределах окна.
