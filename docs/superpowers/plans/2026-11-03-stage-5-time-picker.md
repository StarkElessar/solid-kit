# TimePicker. План реализации

> **Для исполнителя:** REQUIRED SUB-SKILL: superpowers:executing-plans. Шаги с чекбоксами. Каждая часть заканчивается зелёной `pnpm check` (код возврата проверять отдельно) и своим коммитом.

**Цель:** TimePicker на `PickerField` с панелью колонок `TimeColumns` (спека `docs/superpowers/specs/2026-11-03-stage-5-time-picker-design.md`, далее «спека»).

**Архитектура:** чистые хелперы времени в `src/utils/time/` (по образцу `src/utils/date/`); `TimeColumns`: чистая модель допустимости и фокуса (`time-columns-state.ts`) плюс разметка и клавиатура; TimePicker собирает `PickerField`, текст, значение и `TimeColumns`. `PickerField` не меняется.

**Стек:** Solid 1.9, CSS Modules с нативной вложенностью, Vitest + `@solidjs/testing-library` (без jest-dom), `createControllableSignal`.

## Решения владельца (2026-11-03)

Вопросы 1–5 спеки подтверждены («да»): панель закрывается выбором в последней колонке; при пустом значении недостающая часть `00`; стрелки двигают только фокус; минуты при вводе с разделителем ровно 2 цифры; 12-часовой ввод без AM/PM принимается. Вопросы 6–10 по рекомендациям (значение вне шага допустимо; PageUp/PageDown на 6 строк; секунд нет; «Сейчас» включён; колонки). Уточнение разбора (записано в спеку): без суффикса в 12-часовом виде `12` это полдень, `0` и `13`–`23` принимаются как 24-часовая запись.

## Глобальные ограничения

Один компонент, тип или функция на файл; тесты рядом; нативная вложенность CSS (явный `&`), токены, без литералов цветов, классы в kebab-case; пропсы не деструктурируются; табы, одинарные кавычки, длина строки до 140 вместе с комментариями, без комментариев в конце строки кода, `simple-import-sort`, без non-null assertions, без jest-dom; не пушить и не ставить теги без слова владельца.
