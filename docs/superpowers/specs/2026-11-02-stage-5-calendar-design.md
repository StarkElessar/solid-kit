# Этап 5, часть 1. Calendar

Статус: спека принята владельцем 2026-11-03 (все рекомендации раздела 10), Calendar реализован (части 1–4), итоги приёмки в разделе 11. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md` (далее «зонтичный»), ссылки «раздел N» относятся к нему. Здесь только то, чего в зонтичном нет: устройство Calendar и хелперов дат под него. DatePicker, TimePicker и DateTimePicker получат свои спеки после Calendar.

## 1. Рамки

**Calendar** это самостоятельный встраиваемый компонент выбора одной даты. Он не знает про Popover и поле ввода: DatePicker (поле + Calendar в Popover, раздел 11.1) соберёт их позже, поэтому Calendar проектируется как контент, который можно положить куда угодно. Значения дат это ISO-строки без часового пояса (`'2026-11-02'`), пустое значение `null`; арифметика на `Date` в UTC, форматирование и названия через `Intl`, без библиотек дат (раздел 2).

**Решения владельца (2026-11-02):**

1. **Три блока: шапка, тело, подвал.**
2. **Шапка:** кнопка «назад», кнопка с названием периода («месяц год»), кнопка «вперёд». Кнопка с названием уходит вглубь: дни → месяцы → годы.
3. **Тело (дни):** всегда ровно **6 строк** по 7 дней, чтобы высота календаря не менялась. В первой и последней строках показываются дни предыдущего и следующего месяцев.
4. **Подвал:** по центру кнопка текущей даты; клик переносит календарь к текущей дате.
5. **Месяцы:** клик по названию периода в режиме дней открывает месяцы года. **Годы:** клик по названию периода в режиме месяцев открывает годы. В обоих режимах ячейки **растянуты на всю высоту и ширину** календаря (сетка 3 × 4).
6. Calendar потом используется в DatePicker.

**Вне объёма:** выбор диапазона, выбор времени, несколько выбранных дат, номера недель, не григорианские календари, RTL, анимация переходов между режимами, жесты на сенсорном экране (как на этапах 1–4).

## 2. Публичный API

```ts
value?: string | null;                 // 'YYYY-MM-DD'
defaultValue?: string | null;
onValueChange?: (value: string | null) => void;

focusedDate?: string;                  // дата, вокруг которой показан период и на которой стоит клавиатурный фокус
defaultFocusedDate?: string;           // по умолчанию value, иначе сегодня, зажатое в [min, max]
onFocusedDateChange?: (date: string) => void;

defaultView?: 'days' | 'months' | 'years';   // по умолчанию 'days'; сам режим внутренний

min?: string;                          // 'YYYY-MM-DD', включительно
max?: string;
isDateDisabled?: (date: string) => boolean;
disabled?: boolean;

locale?: string;                       // по умолчанию 'ru'
firstDayOfWeek?: 0 | 1 | 2 | 3 | 4 | 5 | 6;   // 0 воскресенье; по умолчанию из локали (раздел 4)
showToday?: boolean;                   // подвал с кнопкой «Сегодня»; по умолчанию true
today?: string;                        // «сегодня» извне: тесты и серверное время; по умолчанию локальная дата устройства
autoFocus?: boolean;                   // при монтировании фокус на выбранную или сфокусированную дату (для DatePicker)
labels?: Partial<CalendarLabels>;
```

- Тройки `value` и `focusedDate` через `createControllableSignal` (имя `Calendar`), колбэки получают новую строку. Остальное состояние (режим `days`, `months`, `years`) внутреннее: DatePicker монтирует Calendar заново при каждом открытии, и режим стартует с `defaultView`.
- Выбор даты вызывает `onValueChange(date)`; повторный клик по выбранной дате значение не сбрасывает (сброс это забота поля DatePicker: очистка).
- `focusedDate` вне `[min, max]` зажимается в диапазон. Недопустимая строка (не `YYYY-MM-DD` или несуществующая дата) это ошибка разработчика: dev-предупреждение и откат к значению по умолчанию.
- `CalendarLabels` (значения по умолчанию на русском, `DEFAULT_CALENDAR_LABELS`): `previous: (view) => string` («Предыдущий месяц», «Предыдущий год», «Предыдущие годы»), `next: (view) => string`, `chooseMonth` («Выбрать месяц»), `chooseYear` («Выбрать год»), `today` («Сегодня»), `calendar` (имя для читалок, «Календарь»).

## 3. Разметка и вид

Корень `data-s-kit`, `role="group"`, `aria-label` из `labels.calendar`; внутри три блока одним столбцом:

```
┌──────────────────────────────┐
│ [‹]     ноябрь 2026      [›] │  шапка, высота контрола
├──────────────────────────────┤
│  Пн  Вт  Ср  Чт  Пт  Сб  Вс  │  строка дней недели (только в режиме дней)
│  27  28  29  30  31   1   2  │
│   …  6 строк по 7 дней  …    │  тело: высота одна и та же во всех режимах
│  …   …   …   …   …   …   …   │
├──────────────────────────────┤
│           [ Сегодня ]        │  подвал, по центру
└──────────────────────────────┘
```

**Шапка.** Слева и справа иконочные кнопки (`aria-label` из `labels`), по центру кнопка с названием периода, которая занимает остаток ширины. Название: в режиме дней «ноябрь 2026», в режиме месяцев «2026», в режиме годов «2020–2029». В режиме годов уходить глубже некуда: название там обычный текст, не кнопка. Названия строятся из `Intl.DateTimeFormat(locale, { timeZone: 'UTC' })`: для режима дней берутся части `month` и `year` из `formatToParts` в порядке локали с литералом между ними, хвостовые литералы (русское « г.») отбрасываются; первая буква заглавная не делается (в ru месяц пишется со строчной). Шаг кнопок: дни ±1 месяц, месяцы ±1 год, годы ±10 лет; шаг двигает `focusedDate` (день ужимается до длины месяца: 31 января → 28 февраля). Кнопка отключается, если весь следующий период вне `[min, max]`.

**Тело, режим дней.** Строка с короткими названиями дней недели (`weekday: 'short'`, начиная с `firstDayOfWeek`) и 6 строк по 7 ячеек-кнопок. Ячейка дня не из показанного месяца приглушена (токен `--s-kit-color-muted`) и кликабельна: выбирает дату и переключает показанный месяц на её месяц (решение исполнителя, вопрос 2). Состояния ячейки: сегодня (контур `--s-kit-color-primary`), выбрана (заливка `--s-kit-color-primary`, текст `--s-kit-color-primary-contrast`), наведение (`--s-kit-color-hover`), отключена (`--s-kit-disabled-opacity`, не кликабельна), сфокусирована (кольцо фокуса, внутренний вариант раздела 5.1). Размер ячейки это `--s-kit-control-height` (28 / 32 / 40 px, раздел 5), ширина календаря 7 ячеек плюс внутренние отступы; высота тела = строка дней недели + 6 строк: **она вычисляется один раз и общая для всех режимов**.

**Тело, режимы месяцев и годов.** Сетка `grid-template: repeat(4, 1fr) / repeat(3, 1fr)` внутри той же рамки тела: ячейки растянуты на всю высоту и ширину, строка дней недели в этих режимах не рисуется, а её высота отдаётся сетке, поэтому общий размер календаря не меняется при переходе между режимами. Месяцы: короткие названия (`month: 'short'`, первая буква заглавная); выбранный месяц (месяц `value`, если год совпадает) и текущий месяц (контур) подсвечены. Годы: 12 ячеек, десятилетие по центру плюс по одному соседнему году с каждой стороны (2019, 2020…2029, 2030), соседние приглушены, как дни чужого месяца. Клик по месяцу переводит в режим дней этого месяца, клик по году в режим месяцев этого года (уход вглубь обратным ходом); `value` в этих режимах не меняется.

**Подвал.** Кнопка «Сегодня» (`Button`, вариант `tinted`, размер контрола) по центру. Клик ставит `focusedDate` в сегодня (зажатое в `[min, max]`), переводит в режим дней и переносит фокус на ячейку этого дня; **значение не меняется** (решение владельца: «переносит к текущей дате»; вопрос 1 про DatePicker). Отключена, если сегодня вне `[min, max]` или отключено `isDateDisabled`. С `showToday={false}` подвал не рисуется.

**Стили.** Только токены и CSS Modules с нативной вложенностью, без литералов цветов; кольцо фокуса через общий механизм раздела 5.1 (корень Calendar получает `data-s-kit-focus-inset`: ячейки стоят вплотную к границам контейнера). Новые токены: `--s-kit-calendar-cell` (размер ячейки дня, по умолчанию `--s-kit-control-height`), `--s-kit-calendar-gap` (зазор сетки, 2 px).

## 4. Хелперы дат (`src/utils/date/`, по одной функции на файл, у каждой тест)

Чистые функции без DOM. Внутреннее представление даты это `{ year, month, day }` (целые, месяц 1–12); ISO-строка преобразуется на границе (Adapter). Календарные расчёты на `Date.UTC` и `getUTC*` (никакого локального времени, поэтому переходы на летнее время ничего не ломают); год меньше 100 задаётся через `setUTCFullYear`. Допустимый диапазон лет 1–9999.

| Функция | Что делает |
|---|---|
| `parseIsoDate(text): DateParts \| null` | строгий разбор `YYYY-MM-DD` с проверкой существования даты (30 февраля даёт `null`) |
| `formatIsoDate(parts): string` | обратно, с нулями |
| `daysInMonth(year, month)` | длина месяца, високосные годы |
| `weekdayOf(parts)` | день недели 0–6 (0 воскресенье) |
| `addDays(parts, n)`, `addMonths(parts, n)`, `addYears(parts, n)` | сдвиг; `addMonths` и `addYears` ужимают день до длины месяца |
| `compareDates(a, b)` | порядок для `min`/`max` и сортировки |
| `clampDate(date, min?, max?)` | зажатие в диапазон |
| `monthGrid(year, month, firstDayOfWeek)` | всегда 42 даты (6 × 7) с признаком «из показанного месяца» |
| `yearBlock(year)` | 12 лет блока (десятилетие плюс соседи) и подпись «2020–2029» |
| `todayIso()` | локальная дата устройства (`getFullYear`, `getMonth`, `getDate`), единственное место, где используется локальное время |
| `firstDayOfLocale(locale)` | первый день недели: `Intl.Locale#getWeekInfo()` (или `weekInfo`), если есть; иначе таблица воскресенье-регионов (US, CA, JP, KR, IL, BR и др.), иначе понедельник. В минимальном Firefox 125 `getWeekInfo` может отсутствовать, поэтому запасной путь обязателен |
| `createDateFormats(locale)` | фабрика форматтеров `Intl` (месяц длинный и короткий, день недели короткий, подпись ячейки «воскресенье, 1 ноября 2026 г.», название периода) с кэшем по локали |

Тесты таблицами: границы месяцев и годов, високосные 2024 и 1900 (не високосный) и 2000 (високосный), февраль из 28 дней, начинающийся с понедельника (сетка из 6 строк, где первая целиком чужая), месяц из 31 дня, начинающийся с воскресенья (дата в последней строке), переходы на летнее время вокруг 2026-03-29 и 2026-10-25 (`addDays` не теряет и не дублирует сутки), `addMonths` 31 января, годы 1, 99, 100, 9999.

## 5. Клавиатура и доступность

- Режим дней: `role="grid"` у тела, `role="row"` по неделям, `role="gridcell"` с кнопкой внутри; строка дней недели с `role="columnheader"` и полным названием в `abbr`/`aria-label`. Один Tab-стоп: **roving tabindex** (`tabindex=0` у сфокусированной даты, `-1` у остальных); реальный DOM-фокус перемещается по ячейкам, виртуализация не нужна (42 ячейки).
- Стрелки ←/→ ±1 день, ↑/↓ ±7 дней, Home/End начало и конец недели, PageUp/PageDown ±1 месяц, Shift+PageUp/PageDown ±1 год, Enter и пробел выбирают дату. Переход за границы показанного месяца сдвигает показанный месяц. Отключённые даты пропускаются стрелками до ближайшей доступной в этом направлении; если доступных нет, фокус остаётся.
- Режимы месяцев и годов: `role="grid"` с ячейками-кнопками; стрелки ←/→ ±1, ↑/↓ ±3 (сетка в 3 колонки), Home/End первый и последний, PageUp/PageDown ±1 год или ±10 лет; Enter и пробел выбирают и возвращают на уровень ниже. Backspace в режимах месяцев и годов возвращает на уровень ниже по глубине (годы → месяцы → дни), как выбор ячейки, но без выбора (решение исполнителя).
- Фокус не теряется при смене режима и при пролистывании: после перерисовки фокус возвращается на ячейку `focusedDate` (микрозадача, как у чипов грида).
- `aria-label` ячейки дня: полная дата с днём недели; `aria-selected` у выбранной, `aria-current="date"` у сегодняшней, `aria-disabled` у отключённых. Названия кнопок шапки и подвала из `labels`; кнопка названия периода получает `aria-live="polite"` у текста, чтобы читалка озвучила смену месяца.
- Esc Calendar не обрабатывает: закрытие это забота слоя (DatePicker в Popover, раздел 8).
- Критерий 7 раздела 12 (фокус у кромки контейнеров с `overflow`) пройден для ячеек, кнопок шапки и подвала.

## 8. Критерии готовности

- а) высота и ширина календаря совпадают во всех трёх режимах и при любом месяце (проверка на месяцах из 4, 5 и 6 недель, на 28-дневном феврале с понедельника), размеры 28 / 32 / 40;
- б) режим дней всегда 42 ячейки; дни соседних месяцев приглушены и кликабельны; «Сегодня» переносит к текущей дате и возвращает режим дней;
- в) уход вглубь и обратно по кнопке названия и по ячейкам, значение при этом не меняется; месяцы и годы растянуты на всю рамку тела;
- г) клавиатурная модель раздела 5, один Tab-стоп, фокус не теряется при смене режима и месяца;
- д) `min`, `max`, `isDateDisabled`, `disabled` работают во всех режимах; кнопки шапки отключаются на границе диапазона;
- е) обе темы читаемы, кольца фокуса целы у кромок (критерий 7), литералов цветов нет;
- ж) хелперы дат покрыты тестами из раздела 4, включая летнее время и годы 1–9999; `pnpm check` зелёный, `verify-package-form.sh` зелёный.

## 9. Применённые паттерны и границы абстракций

- **Adapter:** ISO-строка ↔ `DateParts` на границе компонента; внутри только числа.
- **Strategy:** форматирование и названия через `createDateFormats(locale)`; Calendar не знает про конкретную локаль.
- **State:** режим `days → months → years` это явный конечный набор, переходы описаны в одном месте (`calendar-view.ts` и `calendar-navigation.ts`).
- Calendar не зависит от Popover и поля ввода; DatePicker зависит от Calendar, а не наоборот. `Button` и `IconButton` берутся из кита.
- Без `Temporal` и библиотек дат (раздел 2); локальное время только в `todayIso()`.

## 10. Открытые вопросы (рекомендации)

1. **«Сегодня»: только переносит или ещё и выбирает?** Владелец сказал «переносит к текущей дате», поэтому в Calendar только переносит. Для DatePicker обычно ожидают «выбрать сегодня и закрыть»: решить в спеке DatePicker (рекомендация: DatePicker сам выбирает дату по `onTodayClick`, который Calendar тогда получит; в этом спеке колбэк не добавляется, пока не понадобится).
2. **Клик по дню соседнего месяца.** Рекомендация: выбирает дату и переключает показанный месяц (как в Kendo и React Aria). Альтернатива: только переключает месяц.
3. **Номера недель.** Рекомендация: не рисовать (вне объёма); при необходимости это проп `showWeekNumbers` позже без смены разметки сетки.
4. **Диапазон дат.** Рекомендация: отдельный `DateRangePicker` после этапа 5, если понадобится; Calendar остаётся выбором одной даты.
5. **Сетка лет: 12 лет с соседями или ровно 12 подряд.** Рекомендация: десятилетие с соседними годами по краям (раздел 3), так подпись «2020–2029» честная.
6. **Названия месяцев: короткие или длинные.** Рекомендация: короткие («янв.» … «дек.») в сетке 3 × 4, длинное название идёт в шапку.
7. **Первый день недели.** Рекомендация: по локали (для `ru` понедельник), с запасным путём при отсутствии `getWeekInfo` (раздел 4) и явным пропом `firstDayOfWeek`.
8. **Тег.** Calendar отдельным тегом не выпускается (раздел 7); подтвердить, что устраивает.
