# Этап 4б, первая часть. Пейджер: Pager и нижняя полоса Grid

Статус: дизайн согласован владельцем в диалоге 2026-11-01 (подключение, поведение при смене размера, набор размеров страницы, четыре решения исполнителя); спек ждёт просмотра владельца. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md` (далее «зонтичный»), ссылки вида «раздел N» относятся к нему, если не сказано иное. Предыдущий этап: `2026-10-31-stage-4a-grid-core-design.md` (далее «спек 4а»), тег `v0.5.0`.

Этап 4б в зонтичном (раздел 13) включает меню колонок, пейджер, автосуммы и серверную группировку. Он режется на подэтапы, у каждого свои спек, план и приёмка. Этот спек описывает **только пейджер**; меню колонок, автосуммы и группировка получают свои спеки. Тег `v1.0.0` ставится после всего 4б.

## 1. Рамки

Один новый публичный компонент **Pager** (подпуть `@stark/solid-kit/pager`, подключается шаблоном `./*` из `package.json`, правки экспортов не нужны) и нижняя полоса **Grid**, которая рисует Pager внутри корпуса. Используются готовые `Button`, `IconButton`, `Select` и токены этапов 0–4а.

**Решения владельца, принятые в диалоге 2026-11-01:**

1. **Подключение:** пропы у `Grid` (плоско) плюс отдельный `Pager`. Когда пейджинговые пропы заданы, `Grid` сам рисует нижнюю полосу в корпусе; тот же `Pager` экспортируется отдельно и годится вне грида.
2. **Смена размера страницы:** сохраняется первая запись на экране (раздел 4).
3. **Размеры страницы по умолчанию:** `10, 20, 50, 200, 500, 1000, 2000`.
4. **Решения исполнителя, подтверждённые владельцем:** сводка «Записей 21–40 из 1 250»; если `total` сократился и страница вышла за границы, показывается зажатая страница без вызова колбэка; фокус не теряется (раздел 4.4).
5. **Иконки:** один объект «имя → path» и один компонент, как таблица `ARROW_PATH` у кнопки сортировки (раздел 5).

**Вне объёма:** серверная группировка и пагинация при ней (открытый вопрос 1 зонтичного, раздел 14), неизвестный `total` (курсорная пагинация), поле «перейти на страницу», автосуммы `tfoot`, меню колонок, клиентское разрезание `rows` (грид строки не режет, спек 4а).

## 2. Публичный API

### 2.1. Pager

```ts
interface PagerProps {
  total: number;                         // всего записей
  page?: number;  defaultPage?: number;  onPageChange?: (page: number) => void;   // с 1; default 1
  pageSize?: number;  defaultPageSize?: number;  onPageSizeChange?: (size: number) => void;  // default: первый из pageSizes
  pageSizes?: readonly number[];         // [10, 20, 50, 200, 500, 1000, 2000]
  onRefresh?: () => void;                // кнопка «Обновить» только если передан
  loading?: boolean;                     // всё недоступно, значок обновления вращается
  labels?: Partial<PagerLabels>;         // тексты на русском по умолчанию
  summaryText?: (range: PagerRange) => string;  // 'Записей 21–40 из 1 250'
  size?: 'sm' | 'md' | 'lg';             // как у остальных контролов (data-s-kit-size)
  class?: string;
  style?: JSX.CSSProperties;
}
```

- `PagerLabels`: `navigation` («Постраничная навигация»), `first` («В начало»), `previous` («Назад»), `next` («Вперёд»), `last` («В конец»), `page` (функция `(page: number) => string`, «Страница N»), `pageSize` («Размер страницы»), `refresh` («Обновить»). Отдельный файл-тип.
- `PagerRange`: `{ from: number; to: number; total: number }` (`from`, `to` с 1; при `total = 0` оба 0).
- Пары `page` / `defaultPage` и `pageSize` / `defaultPageSize` работают через `createControllableSignal` (контролируемый и неконтролируемый режим, предупреждение при смене режима, как у остальных контролов).
- **Размеры в списке:** в `Select` идёт отсортированное объединение `pageSizes` и текущего `pageSize`: если страница передала размер вне списка (например 25), он остаётся выбираемым значением и не пропадает из поля.

### 2.2. Grid

К `GridProps` добавляются: `total`, `page`, `defaultPage`, `onPageChange`, `pageSize`, `defaultPageSize`, `onPageSizeChange`, `pageSizes`, `onRefresh`, `pagerLabels`, `pagerSummaryText` (те же типы и значения по умолчанию, что у `Pager`).

- **Нижняя полоса показывается тогда и только тогда, когда передан `total`.** Без `total` грид выглядит как в 4а.
- `loading` грида передаётся пейджеру. Размер пейджера в гриде всегда `md`: у Grid нет `size`, а `size` есть только у отдельного `Pager`.
- Грид строки не режет и не запрашивает: страница передаёт строки текущей страницы и сама реагирует на `onPageChange`, `onPageSizeChange`, `onRefresh`.
- **Объявление результата:** при наличии `total` функция `foundText` (спек 4а, «Найдено N записей») получает `total`, а не длину `rows`: иначе скринридер услышит число записей страницы, а не выборки. Без `total` поведение прежнее.
- Выбор строк по ключам сохраняется между страницами (спек 4а, раздел 2), отдельной логики не нужно.

## 3. Чистые функции

Каждая в своём файле, с таблицей тестов.

- `pageCount(total, pageSize)`: `max(1, ceil(total / pageSize))`; нечисло, `total < 0` и `pageSize < 1` дают 1.
- `clampPage(page, count)`: целое в `[1, count]`; нечисло даёт 1.
- `pageRange(page, pageSize, total)`: `from = (page - 1) * pageSize + 1`, `to = min(page * pageSize, total)`; при `total = 0` оба 0.
- `pageForSizeChange(page, oldSize, newSize)`: `floor((page - 1) * oldSize / newSize) + 1` (первая запись страницы остаётся на экране). Примеры: страница 3 при 10 → 50: страница 1; страница 3 при 50 → 10: страница 11; страница 1 при любом: 1.
- `getPageItems(page, count)`: при `count ≤ 7` все страницы; иначе ровно 7 слотов, чтобы ширина полосы не прыгала. Каждый элемент: `{ kind: 'page', page }` или `{ kind: 'gap' }`.
  - вблизи начала (`page ≤ 4`): `1 2 3 4 5 … N`;
  - вблизи конца (`page ≥ N − 3`): `1 … N−4 N−3 N−2 N−1 N`;
  - в середине: `1 … p−1 p p+1 … N`.
- `defaultSummaryText(range)`: «Записей 21–40 из 1 250» (`Intl.NumberFormat('ru')`, неразрывный пробел; из последней страницы «1 241–1 250»; при `total = 0` просто «Записей 0»).

## 4. Поведение

1. **Кнопки.** «В начало» и «Назад» недоступны на первой странице, «Вперёд» и «В конец» на последней. Номера страниц это кнопки (`aria-label` «Страница N»), у текущей `aria-current="page"` и другой вид; многоточие не интерактивно (`aria-hidden`).
2. **Смена страницы** вызывает `onPageChange(page)`. Клик по текущей странице колбэк не зовёт.
3. **Смена размера** вызывает `onPageSizeChange(size)`, затем `onPageChange(newPage)`, если `pageForSizeChange` дал другую страницу (в неконтролируемом режиме внутреннее состояние обновляется в том же порядке).
4. **Фокус не теряется:**
   - нажатая кнопка стала недоступной из-за границы («Вперёд» на предпоследней странице): фокус переходит на кнопку текущей страницы;
   - начало загрузки (`loading`) делает недоступными все контролы пейджера: если фокус был внутри, он на время загрузки переносится на корень пейджера (`<nav tabindex="-1">`), а по окончании возвращается на ту же кнопку, если она снова доступна и фокус всё ещё на корне; иначе остаётся где есть;
   - если после смены размера кнопка выбранной страницы отсутствует (многоточие вместо неё), фокус остаётся на `Select` размера.
5. **`loading`:** все кнопки, размер страницы и «Обновить» недоступны (`disabled`); значок обновления вращается, при `prefers-reduced-motion` вместо вращения значок остаётся неподвижным с пониженной непрозрачностью. Недоступное «Обновить» не даёт запустить вторую загрузку.
6. **Выход страницы за границы** (например, `total` уменьшился): отображаются `clampPage(page, count)` и соответствующая сводка, но колбэк не вызывается; страница решает сама, что запрашивать. Следствие: после сокращения `total` кнопки и сводка согласованы между собой, но контролируемое `page` страницы может не совпадать с отображаемым до её реакции.
7. **`total = 0`:** одна страница, все кнопки навигации недоступны, сводка «Записей 0», размер страницы и «Обновить» доступны.
8. **Клавиатура:** обычный Tab по кнопкам (без roving-фокуса), Enter и Space по умолчанию у кнопок; `Select` по контракту этапа 3.
9. **Доступность:** корень `<nav aria-label>`; сводка не `aria-live` (иначе каждое листание озвучивается); итог загрузки объявляет живая область грида (раздел 2.2).

## 5. Иконки

Стрелки и значок обновления это встроенный SVG без внешних зависимостей, по образцу `ARROW_PATH` у кнопки сортировки:

- `pager-icon-paths.ts` экспортирует объект `PAGER_ICON_PATHS` (ключи `first`, `previous`, `next`, `last`, `refresh` → строка `path` для `viewBox="0 0 16 16"`, штрих `currentColor`, как у стрелки сортировки: толщина 1.6, скруглённые концы и углы);
- `pager-icon.tsx` один компонент `PagerIcon` с пропом `name: keyof typeof PAGER_ICON_PATHS`, `aria-hidden`, размер от шрифта кнопки;
- тип ключей выводится из объекта, отдельного enum нет.

## 6. Вид и раскладка

- **Полоса пейджера** (в `Pager`): `flex`, слева группа навигации (кнопки, номера) и сразу за ней размер страницы (`Select` с компактной шириной через `--s-kit-select-width`), справа сводка и «Обновить»; промежутки `--s-kit-pager-gap` (фолбэк 8 px).
- **Кнопки** это `IconButton` (стрелки, обновление) и `Button` (номера), вариант `plain`, текущая страница `tinted`; размер от `data-s-kit-size` обёртки.
- **В `Grid`** полоса стоит под скроллером в корпусе (`flex: none`), сверху тонкая граница `--s-kit-color-hairline`, фон `--s-kit-grid-footer-bg` (фолбэк `--s-kit-color-surface-2`, как у шапки), внутренние отступы по горизонтали как у ячеек. Скроллер сжимается (`flex: 1 1 auto`), грид по-прежнему ограничен `--s-kit-grid-max-height`.
- Фокусируемые элементы используют внутреннее кольцо: корень `Pager` всегда несёт `data-s-kit-focus-inset` (в гриде оно дублирует атрибут корня грида, вреда нет), поэтому кольцо не выходит за рамку и в отдельном `Pager`.
- **Узкая ширина:** полоса переносится (`flex-wrap`), сводка уходит на новую строку; номера страниц не сжимаются (7 слотов фиксированной ширины).
- Анимация вращения только на `transform`, отключается при `prefers-reduced-motion`. Литералов цвета нет; CSS с нативной вложенностью (правило кода владельца).
- Токены (публичный API кастомизации, читаются с фолбэком на глобальные): `--s-kit-pager-gap`, `--s-kit-pager-bg` (фон отдельного Pager), `--s-kit-grid-footer-bg`.

## 10. Расхождения с зонтичным и риски

**Расхождения:**

- Размеры страницы по умолчанию `10, 20, 50, 200, 500, 1000, 2000` (решение владельца), зонтичный размеров не называет.
- Сводка «Записей 21–40 из 1 250» (так в описании нижней полосы, раздел 10.1); в таблице переноса (раздел 13) стоит «Отображены записи … из …», расхождение внутри зонтичного снято в пользу первого.
- `foundText` получает `total` при пейджинге (раздел 2.2).

**Риски:**

- **Фокус при загрузке:** перенос на корень пейджера и возврат это самая хрупкая часть; проверяется настоящими Tab и Enter в Chrome (раздел 8, критерий 2), покрыта компонентным тестом.
- **`Select` размера страницы в тонкой полосе:** панель списка должна открываться вверх, если внизу нет места (Floating UI `flip` у Select уже есть); проверяется на странице с нижним краем окна.
- **Высота полосы и `skeletonCount`:** число заглушек считается по `clientHeight` скроллера, а с полосой скроллер ниже; проверяется в приёмке (заглушек не меньше 5).
- **Большие размеры страницы (1000, 2000):** грид виртуализирует, но «выбрать все» в шапке (спек 4а) отмечает строки, переданные гридом, то есть текущей страницы, а не всей выборки; это ожидаемо, выбор по всей выборке остаётся делом страницы.

## 11. Открытые вопросы

1. **Пагинация при серверной группировке** (вопрос 1 зонтичного): решается вместе с группировкой; пейджер из этого спека показывает число записей из `total`, а что считать записью при группировке, определит её спек.
2. **Нужен ли переход на страницу вводом номера** при 2000 страниц: в этом спеке нет; добавляется отдельным решением, если понадобится (кнопки «В начало» и «В конец» плюс размеры до 2000 закрывают основные сценарии).

- Список размеров на отдельном `Pager` у нижнего края окна открывается вверх и показывает все семь значений.
- Темы: тёмная и светлая. Размеры отдельного `Pager`: `sm`, `md`, `lg` рядом на странице.
- Узкая ширина (контейнер 380 px): полоса переносится, горизонтальной прокрутки страницы нет. Недостаток: кнопка «В конец» уходит на вторую строку одна; не исправлялось.
- `prefers-reduced-motion`: правило `animation: none` и `opacity: 0.5` есть в собранном CSS; эмуляцией настройки не проверялось.

**Критерий 4 (производительность).** 100 000 строк × 12 колонок, `selectable`, production-сборка, режим «Постраничная загрузка» с размером страницы 2000 (в DOM 17 строк), доля кадров длиннее 16,7 + 0,8 мс:

| Режим | 1500 px/с | 3000 px/с | 20 000 px/с |
|---|---|---|---|
| Без полосы (база) | 0,00 % (худший кадр 9,4 мс) | 0,00 % (9,4 мс) | 0,00 % (9,4 мс) |
| С полосой, страница 2000 | 0,00 % (9,5 мс) | 0,00 % (10,5 мс) | 0,00 % (9,4 мс) |

Условия: питание от сети, холостой rAF 120,5 fps перед базой и 121 fps перед вторым замером. Нагрузка `vm.loadavg` перед базой 1,95 (условие «ниже 2» выполнено); перед вторым замером 4,23 из-за только что прошедшего замера и операций со страницей, то есть условие «ниже 2» там не соблюдено. Загруженная машина искажает результат в худшую сторону, а он совпал с базой, поэтому вывод «не хуже базы» остаётся; повторять замер при покое можно, но на вывод это не повлияет.

**Дефект Grid 4а, найденный владельцем после приёмки.** В режиме «Загрузка» заглушки строк (`grid-skeleton.tsx`) рисовались без `sticky`: при горизонтальной прокрутке закреплённые колонки и чекбокс в теле уезжали, хотя в шапке оставались. Исправлено: ячейки заглушек получают те же `data-sticky`, `data-sticky-last` и `inset-inline-start`, что ячейки строк; тест «заглушки закреплены так же, как строки». В Chrome при `scrollLeft = 300` левые границы закреплённых ячеек тела и шапки совпадают (25, 69, 159 px), остальные ячейки уезжают. Пропустить дефект позволило то, что приёмка 4а смотрела заглушки без горизонтальной прокрутки.

**Расхождения и оговорки.**
- Перенос фокуса на корень `<nav>` при загрузке (решение исполнителя, раздел 4.4) принят в работу, в Chrome работает как задумано.
- Выбор «выбрать все» отмечает строки текущей страницы (раздел 10); отдельной проверки в браузере не делалось, поведение вытекает из спека 4а.
