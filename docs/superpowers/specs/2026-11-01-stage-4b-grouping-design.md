## 1. Рамки

Грид **не группирует и не считает**: он рисует иерархию `GridGroup<T>`, которую отдаёт сервер (через страницу), и управляет UI группировки: панель с чипами, перетаскивание заголовков, пункт меню колонки «Сгруппировать», кнопки свёрнутости. Состав группировки (`grouping`) и набор развёрнутых групп (`expandedGroupKeys`) это controlled-тройки; страница при `onGroupingChange` перезапрашивает данные.

**Решения владельца из зонтичного** (раздел 7, 10.1): группировка только серверная; три вида агрегатов не смешиваются (групповые `GridGroup.aggregates`, страничные `pageTotals`, глобальные `totals`); `GridGroup.key` стабилен между загрузками; верхняя полоса: слева панель группировки, справа четыре иконочные кнопки; итог группы это строка `gsum` после строк развёрнутой группы, у свёрнутой сумма в строке заголовка; заголовки групп не выбираются и не активируются; «Сгруппировать» живёт в меню колонки после «Закрепить».

**Вне объёма:** клиентская группировка, пагинация внутри одной группы, закреплённые («липкие») заголовки групп внутри скроллера, группировка по нескольким колонкам одним жестом, сортировка групп (её делает сервер), выбор группы целиком (чекбокс заголовка), перетаскивание чипа за пределы панели для удаления.

## 2. Ответ на открытый вопрос 1 (пагинация при группировке)

**Решение исполнителя: вариант (б) зонтичного.** Страницы считаются по группам верхнего уровня: `total` пейджера это число групп верхнего уровня, `pageSize` это групп на странице. Группа не разрезается между страницами; `aggregates` и `count` в заголовке всегда относятся к целой группе. Содержимое развёрнутой группы может подгружаться лениво: `children.kind === 'not-loaded'` и колбэк `onGroupExpand(key)`.

- Грид пагинацию не считает: `total`, `page`, `pageSize` остаются обычными пропсами (спек пейджера); смысл `total` («групп» или «записей») определяет страница. Подпись пейджера «Записей … из …» можно сменить `pagerLabels`/`pagerSummaryText`; объявление результата `foundText` (по умолчанию «Найдено N записей» от `total`) страница тоже переопределяет.
- `pageTotals` в сгруппированном режиме относятся к группам текущей страницы (зонтичный, раздел 7), `totals` ко всему результату.
- Цена варианта: пейджер показывает число групп; для очень больших групп нужна подгрузка частями; она вне объёма (ограничение, раздел 10).

## 3. Публичный API

### 3.1. Grid

```ts
rows?: readonly T[];                        // становится необязательным: в сгруппированном режиме игнорируется
groupable?: boolean;                        // верхняя полоса, пункт меню, перетаскивание; по умолчанию false
groups?: readonly GridGroup<T>[];           // есть — сгруппированный режим
grouping?: readonly string[];               // id колонок по порядку вложенности
defaultGrouping?: readonly string[];
onGroupingChange?: (fields: readonly string[]) => void;
expandedGroupKeys?: ReadonlySet<string>;    // ключи развёрнутых групп
defaultExpandedGroupKeys?: ReadonlySet<string>;
onExpandedGroupKeysChange?: (keys: ReadonlySet<string>) => void;
onGroupExpand?: (key: string) => void;      // раскрыта группа с children.kind === 'not-loaded'
groupingLabels?: Partial<GridGroupingLabels>;
```

- **`groupable` по умолчанию `false`** (решение исполнителя, зонтичный говорит «по умолчанию включено»): иначе существующие гриды без страничной обработки `onGroupingChange` получили бы бесполезную полосу и пункт меню. Включает панель, пункт меню колонки и перетаскивание. Колонка исключается полем `GridColumn.groupable: false`.
- **Режим** определяется наличием `groups`: передан (даже пустой) — сгруппированный, `rows` игнорируется; не передан — прежний плоский. Страница передаёт `groups` вместе с непустым `grouping`; пока идёт перезапрос после смены группировки, страница ставит `loading`.
- `grouping`, `expandedGroupKeys` — тройки через `createControllableSignal` (имя `Grid`); колбэки получают новые массив и `Set`, прежние не мутируются. Id группировки, которых нет среди колонок или у колонок `groupable: false`, в панели не показываются, но в `grouping` остаются (их убирает страница).
- **Свёрнутость (решение исполнителя):** набор хранит **развёрнутые** ключи (имя `expandedGroupKeys` из зонтичного, хотя текст раздела 7 говорит о «свёрнутых»); по умолчанию пусто, то есть все группы свёрнуты: сочетается с ленивой подгрузкой и пагинацией по группам. Ключи, которых нет в текущих данных, остаются в наборе (после перезагрузки или возврата на страницу свёрнутость сохраняется).
- `onGroupExpand(key)` вызывается при раскрытии группы, чьё `children.kind === 'not-loaded'`, и ещё раз при монтировании строки-заглушки, только если ключ в этот момент по-прежнему развёрнут и не загружен (страница сама решает, догружать ли). Грид показывает на месте строк одну строку-заглушку «Загрузка…».
- `GridGroupingLabels` (отдельный файл-тип, значения по умолчанию в `DEFAULT_GROUPING_LABELS`): `panel` («Группировка»: имя панели для читалок), `hint` («Перетащите заголовок колонки сюда, чтобы сгруппировать»), `remove: (title) => string` («Убрать группировку по «Город»»), `collapseLevel` («Свернуть уровень»), `collapseAll` («Свернуть все»), `expandLevel` («Развернуть уровень»), `expandAll` («Развернуть все»), `expand: (title) => string` («Развернуть группу «…»»), `collapse: (title) => string`, `groupTotal: (title) => string` («Итого: …»), `emptyValue` («(пусто)»), `loadingRows` («Загрузка…»), `group` («Сгруппировать»), `ungroup` («Убрать группировку»).

### 3.2. GridGroup и GridColumn

```ts
interface GridGroup<T> {
  key: string;                               // стабильный путь группы, например 'status=open/owner=7'
  field: string;                             // id колонки, по которой сгруппировано
  value: unknown;                            // значение группы для заголовка
  count: number;                             // строк в группе во всём результате
  aggregates?: Readonly<Record<string, unknown>>;   // по id колонки, от сервера
  children:
    | { kind: 'groups'; items: readonly GridGroup<T>[] }
    | { kind: 'rows'; items: readonly T[] }
    | { kind: 'not-loaded' };
}
```

- Форма совпадает с эскизом зонтичного. Уровень вложенности (`level`) вычисляется глубиной дерева, а не хранится.
- `GridColumn.groupable?: boolean` (по умолчанию `true` при `groupable` грида): `false` убирает колонку из перетаскивания и из пункта меню.
- `GridColumn.groupValue?: (value: unknown) => JSX.Element` (**решение исполнителя**): как показывать значение группы в заголовке (даты, булевы, справочники); без него `formatCellValue(value)`, для пустого `emptyValue`. Сам `aggregate` колонки (раздел автосумм) форматирует агрегаты группы так же, как итоги.

## 4. Представление: плоский список элементов

Тело таблицы строится из плоского списка **элементов**, а не строк:

```ts
type GridItem<T> =
  | { kind: 'row'; row: T; rowIndex: number; level: number }          // строка данных
  | { kind: 'group'; group: GridGroup<T>; level: number; expanded: boolean }   // заголовок
  | { kind: 'footer'; group: GridGroup<T>; level: number }            // gsum
  | { kind: 'loading'; key: string; level: number };                  // not-loaded
```

- **Плоский режим** не создаёт массив элементов: `itemCount = rows.length`, `itemAt(i)` строит `{kind:'row', rowIndex: i, level: 0}` по требованию (100 000 строк не дают 100 000 объектов).
- **Сгруппированный режим** разворачивает дерево чистой функцией `flattenGroups(groups, expanded)` → `{ items, rows }`: заголовок группы; для развёрнутой — её дочерние группы (рекурсивно) или строки (`level` на 1 больше), для `not-loaded` один элемент `loading`; затем `footer`, если у группы есть `aggregates`. Свёрнутая группа даёт только заголовок. `rows` это листовые строки загруженных развёрнутых групп в порядке показа; `rowIndex` ссылается на этот массив.
- **Всё, что работало по `rows`, работает по листовым строкам:** выбор (`getRowKey`, `selectedKeys`, главный чекбокс выбирает **загруженные видимые** строки развёрнутых групп), меню строки, двойной клик, индекс ключей. Заголовки, подвалы и заглушки не выбираются, не открывают меню строки и не принимают двойной клик; клик по заголовку (кроме интерактивных элементов) переключает группу.
- Окно виртуализации считает `itemCount` и измеряет все виды строк одинаково (`data-index` это индекс элемента). `aria-rowindex` строки это индекс элемента + 2, `aria-rowcount` = `itemCount + 1 + строки итогов`.
- Оценка высоты строки и измерение те же, что у строк данных; высоту заголовка и подвала определяет контрол-высота токена.
- Состояние «пусто»: `groups` пуст (и нет загрузки).

## 5. Строки групп

- **Заголовок группы** (`tr`, класс `group-row`): пустая закреплённая ячейка колонки чекбоксов (если есть); ячейка-подпись и, у свёрнутой группы, ячейки агрегатов. Подпись: кнопка-шеврон (`aria-expanded`, имя `expand`/`collapse`), затем «Заголовок колонки: значение» полужирно и счётчик `count` приглушённо («· 128»). Подпись занимает первую колонку и колонки без значения агрегатов (та же функция `totalsLabelSpan`, что у итогов, с теми же ограничениями по закреплению); у развёрнутой группы агрегатов в заголовке нет, подпись занимает все колонки.
- **Отступ:** подпись смещена на `level × 16 px`; ячейки данных первой колонки внутри групп получают такой же отступ (`--s-kit-grid-indent`), чтобы иерархия читалась.
- **Подвал группы** (`gsum`): после последней строки развёрнутой группы с `aggregates`; подпись `groupTotal(title)` (по первой колонке, как итоги), ячейки агрегатов в колонках; фон шапки, верхняя граница. У группы без `aggregates` подвала нет.
- **Агрегаты:** значения из `GridGroup.aggregates` по id колонки; форматируются `GridColumn.aggregate`, иначе `formatCellValue`; ключ без значения даёт пустую ячейку; ничего не пересчитывается по строкам.
- **Заглушка `not-loaded`:** строка высотой строки с текстом `loadingRows` приглушённо, с отступом уровня.
- Заголовок группы `aria-level` не получает: таблица остаётся `table`, иерархию озвучивает подпись и `aria-expanded` кнопки.

## 6. Верхняя полоса

Показывается, только если `groupable`. Первая строка корпуса над шапкой, `flex: none`, фон как у нижней полосы (`--s-kit-grid-footer-bg`), нижняя граница `--s-kit-color-hairline`.

- **Слева панель** (`role="group"`, имя `panel`): зона для перетаскивания и чипы. Пустая показывает `hint` приглушённо. Чип: `<span>` с кнопкой названия колонки (фокусируемая; Alt+←/→ переставляет чип, Delete и Backspace убирают) и кнопкой «×» (`remove`). Порядок чипов = порядок вложенности.
- **Справа четыре иконочные кнопки** (по порядку): свернуть один уровень, свернуть все, развернуть один уровень, развернуть все. Имена из `groupingLabels` (`aria-label`, `title`). Кнопки отключены, пока нет сгруппированных данных или идёт `loading`.
- Вид: кнопки и чипы используют внутреннее кольцо фокуса (`data-s-kit-focus-inset` корня); иконки `svg` 16 px, `currentColor`.

## 7. Чистые функции (каждая в своём файле, с таблицей тестов)

- `flatten-groups.ts`: `flattenGroups(groups, expanded)` (раздел 4).
- `group-keys.ts` (три функции в трёх файлах по правилу «одна на файл»: `all-group-keys.ts`, `expand-level-keys.ts`, `collapse-level-keys.ts`):
  - `allGroupKeys(groups)`: ключи всех групп дерева (кнопка «развернуть все»; «свернуть все» это пустой набор).
  - `expandLevelKeys(groups, expanded)`: добавляет все свёрнутые группы наименьшей глубины среди **видимых** свёрнутых (группа видима, если все её предки развёрнуты); если свёрнутых нет, возвращает тот же набор.
  - `collapseLevelKeys(groups, expanded)`: убирает все развёрнутые видимые группы наибольшей глубины; если развёрнутых нет, тот же набор.

## 8. Перетаскивание (Pointer Events)

Один контроллер `createGroupingDrag` в гриде, источник жеста: заголовок колонки или чип.

- Начало: `pointerdown` основной кнопкой на ячейке шапки (не на ручке ресайза и не на кнопке меню) либо на кнопке названия чипа, при `groupable` и колонке без `groupable: false`. Жест становится перетаскиванием после смещения на **4 px**; до этого клик (сортировка, фокус) работает как раньше, после перетаскивания следующий `click` гасится один раз.
- Во время жеста: «призрак» (`position: fixed`, ширина по содержимому, следует за указателем, `pointer-events: none`), зона панели подсвечивается (`data-drop-active`), перед чипом, на место которого встанет перетаскиваемый, и в конце панели рисуется метка вставки (`data-drop-before`, `data-drop-end`). Слушатели `pointermove`, `pointerup`, `pointercancel` и `keydown` (Esc отменяет) вешаются на `document` при старте и снимаются при завершении и в `onCleanup`.
- Завершение над панелью: заголовок колонки → `onGroupingChange(placeGrouping(...))` (колонка, уже стоящая в группировке, переставляется); чип → перестановка. Вне панели: отмена без изменений.
- **Клавиатура и тач:** перетаскивание не единственный путь: пункт меню колонки «Сгруппировать»/«Убрать группировку» и клавиши чипа дают всё то же. Касание без мыши (`pointerType: touch`) жест не начинает (прокрутка не должна сталкиваться с перетаскиванием); для тач-экрана остаётся меню.
- Текст выделения во время жеста отключён (`user-select: none` на корне, пока идёт жест).

## 9. Меню колонки

Пункт «Сгруппировать» (`group`; у колонки, уже стоящей в группировке, «Убрать группировку», `ungroup`) идёт после «Закрепить / Открепить» и перед разделителем (решение спека меню колонки). Показывается, только если `groupable` и колонка не `groupable: false`. Выбор закрывает меню и вызывает `onGroupingChange`. Состояние группировки при скрытии колонки не меняется (скрытая колонка остаётся в группировке; чип показывает её название).

## 11. Части, критерии приёмки, тестирование

Части: 1) типы и чистые функции; 2) плоский список элементов в Grid, строки групп, агрегаты, `expandedGroupKeys`, виртуализация; 3) панель, чипы, кнопки уровней, пункт меню; 4) перетаскивание; 5) playground: «сервер» группирует и режет по страницам групп, ленивая подгрузка, автопроверки, приёмка в Chrome.

Критерии приёмки:

- а) без `groups` грид работает как прежде (все прежние тесты зелёные, плоский режим не создаёт массив элементов);
- б) с `groups` рисуются заголовки, строки, подвалы, заглушки в правильном порядке; свёрнутая группа несёт агрегаты в заголовке, развёрнутая в подвале; уровни с отступом;
- в) `expandedGroupKeys`: клик по заголовку и шеврону переключает; четыре кнопки уровней дают результат функций раздела 7; свёрнутость переживает смену `groups` (то же `key`);
- г) выбор, меню строки, двойной клик работают на строках внутри групп и не срабатывают на заголовках, подвалах, заглушках; `aria-rowcount`/`aria-rowindex` последовательны, включая `tfoot`;
- д) чипы, удаление, Alt+стрелки, пункт меню; перетаскивание заголовка в панель и перестановка чипов мышью; Esc отменяет жест; сортировка кликом по заголовку не ломается;
- е) `not-loaded`: раскрытие вызывает `onGroupExpand`, показывается заглушка, после прихода строк заменяется ими;
- ж) виртуализация: 10 000 строк в нескольких группах не рендерят больше окна плюс overscan; прокрутка гладкая (замер по правилам спека 4а, раздел 12);
- з) светлая и тёмная темы читаемы; кольца фокуса у чипов и кнопок видны внутри рамки; критерии (г) и (е) из зонтичного для меню колонки повторяются на гриде с полосой.

Тесты: чистые функции таблицами; в `grid.test.tsx` описания «Grid: группировка» (режим, порядок элементов, агрегаты, развёртывание, выбор, aria, `not-loaded`), «Grid: панель группировки» (чипы, кнопки, меню, Alt+стрелки); перетаскивание в jsdom проверяется событиями `pointerdown/move/up` со стабами `getBoundingClientRect` (геометрию чипов подставляет тест), остальное в Chrome. Playground: страница «Грид» получает переключатель «Группировка» и «Сервер» группирует `ALL_ORDERS` по выбранным полям, считает `count` и `aggregates` (суммы `amount` и `score`), режет верхний уровень по страницам, делает группы не меньше 20 строк ленивыми.

## 12. Расхождения с зонтичным и риски

- `groupable` у грида по умолчанию `false` (раздел 3.1); набор хранит развёрнутые ключи, по умолчанию все свёрнуты (раздел 3.1); `rows` необязателен; клик по заголовку группы переключает её (зонтичный об этом молчит); липких заголовков групп в скроллере нет (вне объёма); добавлен `GridColumn.groupValue`.
- Риск размера: часть подэтапа 5 (playground-сервер) и приёмка самые трудоёмкие; если время не позволит, перетаскивание (часть 4) остаётся рабочим, но с пониженной полнотой приёмки (отмечается в итогах).
- Риск виртуализации: сдвиг индексов при раскрытии/сворачивании меняет вид элемента на индексе; строки ключуются по индексу окна, их содержимое переключается `Switch`.
- Ограничение: подгрузка частями внутри одной очень большой группы (тысячи строк) не поддерживается; страница может ограничить размер `rows` группы и показать «ещё» отдельным решением.
