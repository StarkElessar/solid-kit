## 1. Рамки

В этапе три публичных компонента: **Popover**, **Dialog**, **ContextMenu** (простое меню без ListBox, с подменю) и общая внутренняя основа плавающих панелей: хост панели (`PanelHost`), изоляция событий, сброс наследуемых свойств, фокус при открытии и закрытии, доработка стека слоёв (раздел 3).

Как в этапе 1, этап режется по частям: у каждой свой короткий план и свой коммит (или несколько), зелёная `pnpm check` обязательна перед каждым коммитом, план пишется перед выполнением своей части. Тег ставится один раз на конец этапа: `v0.3.0`, когда выполнены все критерии раздела 8.

**Вне объёма этапа:**

- ловушка фокуса за пределами того, что даёт нативный `<dialog>` (зонтичный, раздел 8, «Фокус»), модальный Popover, тултипы, hover-карточки, drawer, bottom sheet;
- поиск по набору букв (typeahead) в меню: это работа ListBox на этапе 3;

- RTL, `forced-colors`, `prefers-reduced-motion` для анимаций, которых нет.

## 2. Что уже есть с этапа 0 и что меняется

Есть и остаётся:

- `src/utils/create-panel-layer.ts`: показ панели в top layer (`popover="manual"`, `showPopover()`), регистрация в стеке слоёв, `hidePopover()` при очистке;
- `src/utils/layer-stack.ts`: модульный стек слоёв; Esc в фазе захвата закрывает верхний слой, `pointerdown` снаружи закрывает верхний слой;
- `src/utils/create-anchored-position.ts`: Floating UI, поддерживает виртуальный якорь (`VirtualElement`), `placement`, `gap`, `matchAnchorWidth`;
- `src/utils/create-controllable-signal.ts`.

Чего не хватает до контрактов разделов 6 и 8 зонтичного:

- панель сейчас рендерится на месте, а не в хосте (`Probe`): `Portal`, выбор хоста и `PanelHostContext` отсутствуют;
- у корня панели нет изоляции событий и общего CSS сброса наследуемых свойств (стили сброса лежат внутри `probe.module.css`);
- у слоя нет признака модальности, а клик снаружи закрывает только верхний слой: вложенные панели (подменю) требуют каскада (раздел 3.1);
- нет возврата фокуса на инициатор и фокуса внутрь панели при открытии;
- `Probe` и `probe-unused` это тестовые стенды этапа 0: на них держатся страница «Темы» (критерий 5) и матрица формы пакета; этап 2 заменяет их настоящими компонентами (раздел 7).

## 3. Основа панелей

### 3.1 Стек слоёв: изменения

```ts
export interface Layer {
  contains: (target: Node) => boolean;    // принадлежит ли цель слою (панель, диалог или инициатор)
  close: () => void;                      // запрос закрытия; регистрацию снимает владелец слоя
  modal?: boolean;                        // новый признак: слой модальный (Dialog)
}
```

- **Esc** без изменений: закрывает только верхний слой, `preventDefault()` и `stopPropagation()`, обработчик на `document` в фазе захвата.
- **Клик снаружи (`pointerdown` в фазе захвата) теперь каскадный.** Обработчик идёт сверху вниз по снимку стека: пока слой не содержит цель, он закрывается и обход продолжается; обход останавливается на первом слое, который содержит цель, и на модальном слое (модальный слой стек сам не закрывает). Причина отличия от формулировки «клик снаружи обрабатывает только верхний слой» (зонтичный, раздел 8): при меню с подменю один клик вне обоих должен закрыть оба, а не требовать два клика. Клик внутри нижней панели закрывает только панели над ней (подменю), как принято у меню.
- Модальный слой (Dialog) клик снаружи через стек не закрывается никогда: цель клика по подложке это сам элемент `<dialog>`, а даже если слой не содержит цель, обход на нём останавливается без закрытия. Закрытие по клику на подложку делает Dialog собственной логикой (раздел 5).
- Обход идёт по копии массива: `close()` слоя может синхронно снять регистрацию и изменить стек. Перед обработкой слоя проверяется, что он всё ещё зарегистрирован: закрытие верхней панели может снять нижние, и их `close()` уже не вызывается.
- Регистрация, снятие и `getLayerCount` без изменений. Тесты стека дополняются: каскад (три слоя), остановка на слое, содержащем цель, остановка после модального слоя, повторный вызов снятия.

### 3.2 Хост панели (`PanelHost`)

Реализует разделы 8.1 и 6.2 зонтичного. Файл `src/internal/panel/panel-host.ts`.

```ts
/** Хост по умолчанию для панели, открываемой из `anchor`. */
export function resolvePanelHost(anchor: Element): Element;

/** Переопределение хоста: ближайший провайдер выигрывает. Грид (этап 4а) и Dialog задают хост своим корнем. */
export const PanelHostContext: Context<Accessor<Element | undefined> | undefined>;
```

- `resolvePanelHost`: найти самого внешнего предка `anchor` (сам `anchor` не считается) из `table, label, button, a[href], summary`; хост это родитель такого предка; если предков нет, хост это `anchor.parentElement`; если родителя нет (корень документа), `document.body`.
- Порядок выбора хоста у панели: `PanelHostContext` (если провайдер есть и значение определено) → `resolvePanelHost(anchor)` → `document.body`. Для ContextMenu без `ContextMenu.Trigger` (точка передана снаружи) якорного элемента нет, тогда хост это контекст или `document.body`.
- **Dialog задаёт `PanelHostContext` своим корневым `<dialog>`.** Причина: `showModal()` делает всё вне диалога инертным; панель, открытая из диалога, обязана лежать в его DOM-поддереве, иначе при внешнем провайдере хоста (корень грида вокруг инициатора диалога) она оказалась бы инертной. Это правило стоит в разделе 5 и проверяется страницей «Панели».
- Панель монтируется `<Portal mount={host}>` с `ref`, который ставит контейнеру-обёртке `display: contents`: обёртка `<div>`, которую создаёт `Portal` (проверено по исходнику `solid-js` 1.9.17), не должна стать элементом раскладки у хоста (flex или grid с `gap`). Что `display: contents` у обёртки не влияет на раскладку хоста, проверяется в браузере на странице «Панели».

### 3.3 Корень панели: изоляция событий и сброс наследуемых свойств

Внутренний компонент `FloatingPanel` (`src/internal/floating-panel/floating-panel.tsx`) собирает то, что нужно каждой плавающей панели; Popover и ContextMenu пользуются им, позже Select, Combobox, MultiSelect. Папка `src/internal/` вне `exports`: подпуть `@stark/solid-kit/<имя>` отображается только на `src/components/<имя>/` (зонтичный, раздел 3.3), поэтому внутренний код туда не попадает случайно.

```ts
interface FloatingPanelProps {
  open: Accessor<boolean>;
  onDismiss: () => void;                       // клик снаружи, Esc
  anchor: Accessor<AnchorElement | undefined>; // Element или виртуальный (точка клика)
  anchorElement?: Accessor<Element | undefined>; // реальный элемент для выбора хоста и возврата фокуса
  dismissExempt?: Accessor<Element | undefined>; // pointerdown по нему не клик снаружи; по умолчанию anchorElement
  placement?: Placement;
  gap?: number;
  matchAnchorWidth?: boolean;
  // остальное: атрибуты корня панели, class, style, children
}
```

- **Изоляция** (раздел 8.3 зонтичного): корень вешает делегированные Solid-обработчики `click`, `dblclick`, `contextmenu`, `pointerdown`, `mousedown`, `keydown`, `keyup`, `input`, `focusin`, `focusout`, каждый вызывает `stopPropagation()`. Нативный `stopPropagation()` на корне запрещён. Все десять имён входят в `DelegatedEvents` Solid (проверено по исходнику).
- **Хост считается лениво.** `PanelPortal` не кэширует хост в `createMemo`: при `defaultOpen` панель создаётся, пока инициатор ещё не вставлен в DOM, и мемо зафиксировало бы `document.body`. Хост вычисляется обычной функцией, которую читает эффект `Portal` после вставки.
- **Что считается «снаружи».** `anchorElement` служит для выбора хоста и возврата фокуса; исключение из клика снаружи это отдельный `dismissExempt` (по умолчанию тот же элемент). Для кнопки Popover совпадение верно. Область вызова ContextMenu (большой `<div>`) в исключения не входит: `dismissExempt={() => undefined}`, клик в другом месте области закрывает меню.
- **Сброс наследуемых свойств** (раздел 8.2): общий `src/internal/floating-panel/panel-base.module.css`, подключается через `composes`; правило обёрнуто в `:where()` (специфичность 0, так же как основа контролов, см. итоги Tabs в спеке этапа 1, раздел 18). В основе: явный список свойств из раздела 8.2 (`font-*`, `color`, `line-height`, `letter-spacing`, `text-align: start`, `text-indent`, `text-transform`, `white-space`, `word-break`, `text-shadow`, `cursor: auto`, `visibility: visible`, `pointer-events: auto`), сброс UA-стилей `[popover]` (`inset`, `margin`, `border`, `padding`, `overflow`), материал панели (раздел 4.3: сплошной запасной фон, полупрозрачный `--s-kit-color-panel` и `backdrop-filter` под положительным `@supports` и без `prefers-reduced-transparency`), тень `--s-kit-shadow-popover`, скругление `calc(var(--s-kit-radius) * 1.5)`. `all: initial` и `all: revert` не используются (раздел 8.2). Фон каждого компонента переопределяется своим токеном (`--s-kit-popover-bg`, `--s-kit-menu-bg`), как `--s-kit-probe-panel-bg` у Probe.
- **Материал и фон.** Основа даёт только тень и `backdrop-filter` (под положительным `@supports` и без `prefers-reduced-transparency`). Фон задаёт сам компонент: сплошной `background: var(--s-kit-popover-bg, var(--s-kit-color-surface))` и тот же `background` с `--s-kit-color-panel` внутри `@supports … @media not (prefers-reduced-transparency: reduce)`. Общее частное свойство в основе отвергнуто: `no-unknown-custom-properties` требует объявленные токены. Скругление тоже у компонента (`calc(var(--s-kit-radius) * 1.5)` по умолчанию).
- **Неявная отправка формы.** Хост часто сам внутри `<form>`, поэтому Enter в `input` или `select` панели отправил бы чужую форму (критерий 6 (в) зонтичного спека). Изолированный `keydown` вызывает `preventDefault()`, если у такого поля есть `form`, и эта форма не лежит внутри панели (`blocksImplicitSubmit`, чистая функция). `form` намеренно не входит в блокирующих предков хоста: иначе сценарий вложенной формы со страницы «Темы» потерял бы токены формы. Кнопки и `textarea` не затрагиваются.
- `user-select`: `none` у меню, `text` у Popover (раздел 8.2).
- Корень несёт `data-s-kit` (раздел 11 зонтичного).

### 3.4 Фокус при открытии и закрытии

Два небольших хука в `src/internal/floating-panel/`, каждый в своём файле:

- `createFocusOnOpen(panel, open)`: после показа панели фокус переходит на первый табулируемый элемент внутри, а если такого нет, на сам корень панели (ему ставится `tabindex="-1"`). Меню переопределяет поведение (раздел 6: фокус на корень меню, а при открытии с клавиатуры на первый пункт).
- `createFocusRestore(anchor, open)`: при закрытии панели фокус возвращается на инициатор, если в момент очистки активный элемент это `document.body` (фокус потерян из-за удаления панели из DOM) или находится внутри панели. Если клик снаружи уже перевёл фокус на другой элемент, фокус не перехватывается. Порядок: по исходнику `solid-js` отрисовка удаляет узлы панели раньше пользовательских эффектов, поэтому в очистке эффекта панели уже нет в DOM и активным остаётся `body`; хук опирается именно на это и проверяется тестом.
- Клик по пустому месту страницы, закрывший панель, тоже оставляет активным `body`, поэтому и в этом случае фокус вернётся на инициатор. Это допустимо и документируется.

### 3.5 Применённые границы абстракций

- `layer-stack` ничего не знает о Solid, DOM-компонентах и позиционировании; `createPanelLayer` зависит от него; `FloatingPanel` собирает `createPanelLayer`, `createAnchoredPosition`, `createFocusOnOpen`, `createFocusRestore` и `PanelPortal`; компоненты зависят от `FloatingPanel`, но не от Floating UI (DIP: позиционирование за интерфейсом `createAnchoredPosition`).
- Хуки комбинируются, а не наследуются (Decorator из раздела 11.1): каждый хук делает одно дело и тестируется отдельно.

## 4. Popover

Свой Popover (зонтичный, раздел 8): панель с произвольным содержимым, открывается из кнопки. Compound-компонент (зонтичный, раздел 11.1).

```ts
interface PopoverRootProps {
  open?: boolean;                        // контролируемый режим
  defaultOpen?: boolean;                 // по умолчанию false
  onOpenChange?: (open: boolean) => void;
  placement?: Placement;                 // по умолчанию 'bottom-start'
  gap?: number;                          // по умолчанию 4
  children?: JSX.Element;
}

interface PopoverTriggerAttributes {     // то, что Trigger передаёт своему «рендеру»
  ref: (element: HTMLElement) => void;
  id: string;
  'aria-expanded': boolean;
  'aria-controls': string;
  'data-popover-open': '' | undefined;
  onClick: JSX.EventHandler<HTMLElement, MouseEvent>;
}
interface PopoverTriggerProps extends ButtonProps {
  render?: (attributes: PopoverTriggerAttributes) => JSX.Element;   // свой инициатор вместо Button
}

interface PopoverState { open: Accessor<boolean>; close: () => void }
// атрибуты корня, кроме изолируемых событий (onClick, onDblClick, onContextMenu, onPointerDown, onMouseDown, onKeyUp, onInput,
// onFocusIn, onFocusOut: ими владеет изоляция, обработчики вешаются на элементы внутри) и onKeyDown/ref, которые заданы ниже
interface PopoverContentProps extends FloatingPanelAttributes {
  onKeyDown?: (event) => void;             // вызывается раньше изоляции
  ref?: (element: HTMLDivElement) => void; // корневой элемент панели
  size?: 'sm' | 'md' | 'lg';
  matchAnchorWidth?: boolean;
  class?: string;
  style?: JSX.CSSProperties;
  children?: JSX.Element | ((state: PopoverState) => JSX.Element);
}

function usePopover(): PopoverState;     // из любого места внутри Popover.Root (в том числе в содержимом)
```

```tsx
<Popover.Root>
  <Popover.Trigger variant='tinted'>Фильтры</Popover.Trigger>
  <Popover.Content aria-label='Фильтры'>
    {(state) => <><Field label='Имя'>…</Field><Button onClick={state.close}>Готово</Button></>}
  </Popover.Content>
</Popover.Root>
```

Решения (рекомендации):

- **Состояние:** `createControllableSignal<boolean>` в `Popover.Root`; Root элементов не рендерит (контекст и фрагмент). Контекст без провайдера бросает `Popover.Content must be used inside Popover.Root` (так же устроены ошибки Tabs; уникальная строка `must be used inside Popover.Root` служит маркером «компонент в бандле» в матрице, раздел 7).
- **Инициатор.** По умолчанию `Popover.Trigger` это Button кита (все его пропсы), `type="button"`, `aria-expanded`, `aria-controls` (id содержимого), щелчок переключает состояние; пользовательский `onClick` вызывается первым и может отменить через `event.preventDefault()`. Нужен другой инициатор (IconButton): `render={(attributes) => <IconButton {...attributes} aria-label='Меню'>…</IconButton>}`. Рендер-проп получает атрибуты, включая `ref`; обязанность передать их на корневой элемент лежит на пользователе (как у `Field`). Альтернатива `as` отвергнута: типизация полиморфных пропсов в Solid тяжелее рендер-пропа и ломает вывод типов.
- **Якорь и клик по инициатору.** Якорь это элемент инициатора; `pointerdown` по нему не считается кликом снаружи (стек уже так работает), щелчок по инициатору закрывает открытый Popover.
- **Закрытие:** Esc и клик снаружи (стек слоёв), кнопка внутри через `state.close()`/`usePopover()`. Закрытие по уходу фокуса не делается (YAGNI: форма внутри Popover и переключение окон не должны его закрывать).
- **Фокус:** при открытии на первый табулируемый элемент или корень панели, при закрытии Esc или кнопкой возвращается на инициатор (раздел 3.4).
- **ARIA:** панель без роли по умолчанию; `role="dialog"` и `aria-label` задаются пользователем, как атрибуты (`aria-haspopup` у инициатора не ставится, пока роль неизвестна).
- **Размер:** `size` у `Popover.Content` ставит `data-s-kit-size` на панель; без него панель наследует размер обёртки хоста (раздел 5 зонтичного).
- **Компонентные токены:** `--s-kit-popover-bg` (фолбэк: материал панели), `--s-kit-popover-padding` (фолбэк 12 px), `--s-kit-popover-min-width` (фолбэк 0), `--s-kit-popover-max-width` (фолбэк `min(90vw, 480px)`), `--s-kit-popover-radius` (фолбэк скругление основы).
- **Тесты:** `resolvePanelHost` (предки `label`, `table`, `button`, `a[href]`, `summary`, самый внешний из вложенных, без предков, корень документа); `PanelHostContext` (переопределение, вложенный провайдер выигрывает); стек слоёв (каскад); `Popover`: контролируемый и неконтролируемый режим, открытие и закрытие щелчком, Esc, клик снаружи, клик по инициатору при открытом, `render` у инициатора, ссылка `ref`, `aria-expanded` и `aria-controls`, функция-ребёнок и `usePopover`, ошибка вне Root, фокус внутрь и возврат на инициатор, изоляция событий (обработчик `onClick` и `onDblClick` у ближайшего логического предка не вызывается кликом внутри панели; Enter внутри `<form>` без отправки), панель смонтирована в хосте, а не внутри `<label>`.

## 5. Dialog

Нативный `<dialog>` с `showModal()` (зонтичный, раздел 8). Compound-компонент.

```ts
interface DialogRootProps {
  open?: boolean;
  defaultOpen?: boolean;                  // по умолчанию false
  onOpenChange?: (open: boolean) => void;
  closeOnEscape?: boolean;                // по умолчанию true
  closeOnBackdropClick?: boolean;         // по умолчанию true (вопрос 1 раздела 10)
  children?: JSX.Element;
}
// Dialog.Trigger: как Popover.Trigger (Button по умолчанию, `render` для своего инициатора)
interface DialogContentProps extends Omit<JSX.DialogHTMLAttributes<HTMLDialogElement>, 'children' | 'class' | 'style' | 'open'> {
  size?: 'sm' | 'md' | 'lg';
  class?: string;
  style?: JSX.CSSProperties;
  children?: JSX.Element | ((state: DialogState) => JSX.Element);
}
interface DialogState { open: Accessor<boolean>; close: () => void }
// Dialog.Title (h2), Dialog.Description (p), Dialog.Body (прокручиваемое тело),
// Dialog.Footer (кнопки), Dialog.Close (Button, закрывает)
function useDialog(): DialogState;
```

```tsx
<Dialog.Root>
  <Dialog.Trigger>Удалить…</Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Title>Удалить запись?</Dialog.Title>
    <Dialog.Body>Действие нельзя отменить.</Dialog.Body>
    <Dialog.Footer>
      <Dialog.Close variant='plain'>Отмена</Dialog.Close>
      <Button variant='danger'>Удалить</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog.Root>
```

Решения (рекомендации):

- **Монтирование:** `Dialog.Content` рендерит `<dialog>` только пока `open()`; элемент монтируется в хост панели (раздел 3.2), как панели. После монтирования вызывается `showModal()`, при размонтировании (очистка эффекта) `close()`, если диалог ещё открыт. Контент между открытиями не сохраняется (как невыбранная панель Tabs без `keepMounted`).
- **Esc** (зонтичный, раздел 8; маршрутизация целиком реализована стеком слоёв и событиями диалога):
  - диалог регистрируется в стеке с `modal: true`; обработка Esc остаётся у стека: перехват `keydown` в фазе захвата, `preventDefault()` и `stopPropagation()` не дают браузеру вызвать нативную отмену. Если верхний слой не диалог (панель над ним), закрывается панель, диалог запроса не получает;
  - `close` слоя диалога вызывает `onOpenChange(false)` (контролируемый режим: DOM-диалог закрывается, когда `open` станет `false`; неконтролируемый: сразу после обновления состояния); при `closeOnEscape={false}` `close` ничего не делает, но нативное закрытие всё равно подавлено;
  - событие `cancel` всегда отменяется (`preventDefault()`): страховка на случай источников, минующих `keydown` (механизм close watcher); отмена может не удаться без предшествующей пользовательской активации, поэтому основной путь это `keydown`;
  - событие `close` из другого источника (`<form method="dialog">`) синхронизируется вызовом `onOpenChange(false)`; в контролируемом режиме, если родитель оставил `open`, диалог открывается снова (`showModal()`), чтобы DOM и `open` не расходились.
  - `onOpenChange(false)` вызывается ровно один раз на закрытие (тест).
- **Клик по подложке:** при `closeOnBackdropClick` пара `pointerdown` и `click`, у которых цель сам `<dialog>`, а координаты вне его `getBoundingClientRect()`, закрывает диалог. Выделение текста, начатое внутри и закончившееся над подложкой, не закрывает (нужны оба события вне прямоугольника). Рекомендация: по умолчанию `true`, для диалогов с несохранёнными данными `false`.
- **Фокус:** при открытии нативный `showModal()` ставит фокус на первый фокусируемый элемент или на элемент с `autofocus`; при закрытии браузер возвращает фокус на элемент, который был активен до открытия; хук `createFocusRestore` (раздел 3.4) страхует случай, когда инициатор был вне диалога и потерял фокус. Ловушка фокуса поверх нативной инертности фона не делается.
- **Хост панелей внутри:** `Dialog.Content` задаёт `PanelHostContext` своим `<dialog>` (раздел 3.2); Popover и ContextMenu внутри диалога рендерятся внутри него и оказываются над ним, потому что показаны позже (проверено на этапе 0).
- **Структура и вид:** `<dialog>` с `display: flex; flex-direction: column` и ограничением `max-block-size`; `Dialog.Title` и `Dialog.Footer` фиксированы, `Dialog.Body` прокручивается (`overflow: auto`, `overscroll-behavior: contain`) и резервирует внутренний отступ не меньше `--s-kit-focus-space` вокруг содержимого (зонтичный, раздел 5.1: тело Dialog со свободными контролами использует внешнее кольцо; отступ нужен, чтобы `overflow` его не обрезал). Фон диалога сплошной `--s-kit-color-surface` (плотный слой данных, материал панелей из раздела 4.3 ему не подходит), подложка `::backdrop`: `color-mix(in oklch, var(--s-kit-color-text) 40%, transparent)`.
- **ARIA:** `<dialog>` получает `aria-labelledby` (id заголовка), если `Dialog.Title` смонтирован, и `aria-describedby` (id описания), если смонтирован `Dialog.Description` (регистрация в контексте); без заголовка автор задаёт `aria-label` сам.
- **Размер:** `size` ставит `data-s-kit-size` на диалог; содержимое наследует размер контролов.
- **Компонентные токены:** `--s-kit-dialog-bg` (фолбэк `--s-kit-color-surface`), `--s-kit-dialog-width` (фолбэк 480 px, максимум `calc(100vw - 2 * 16px)`), `--s-kit-dialog-padding` (фолбэк 20 px), `--s-kit-dialog-radius` (фолбэк `calc(var(--s-kit-radius) * 2)`), `--s-kit-dialog-backdrop` (цвет подложки).
- **Тесты:** в jsdom нет `showModal`, `close` и событий `cancel`/`close`; тесты подключают тестовый адаптер диалога (подмена прототипа `HTMLDialogElement`, как `showPopover` в тестах `createPanelLayer`): `showModal` выставляет атрибут `open`, `close` убирает его и шлёт событие `close`. Проверяется: открытие и закрытие (контролируемый и неконтролируемый режим), Esc через стек, `onOpenChange(false)` ровно один раз, `closeOnEscape={false}`, отмена `cancel`, синхронизация по `close` и повторное открытие в контролируемом режиме, клик по подложке с выделением и без, `Dialog.Close`, `aria-labelledby`/`aria-describedby`, `PanelHostContext` у содержимого, возврат фокуса, функция-ребёнок и `useDialog`, ошибка вне Root.
- **Блокировка прокрутки страницы (решение владельца 2026-10-30, делается в части 2).** Пока открыт модальный `<dialog>`, страница под подложкой не прокручивается: правило в CSS Dialog через `:global(html):has(.dialog:modal)` с `overflow: hidden` и `scrollbar-gutter: stable` (без сдвига вёрстки при исчезновении полосы). Известное ограничение: на странице короче экрана при классических (занимающих место) полосах прокрутки `stable` резервирует место под полосу, которой не было, и содержимое сужается на её ширину; при наложенных полосах сдвига нет (замечание ревью Astra, принято как ограничение). Проверяется в Chrome на странице «Панели»: колесо над подложкой не двигает страницу, ширина содержимого не прыгает, после закрытия прокрутка возвращается, при двух вложенных диалогах не снимается раньше времени.
- **Вне объёма:** анимация, несколько диалогов друг в друге (стек это допускает, отдельной проверки нет), `Dialog` как `<form method="dialog">` из коробки.

## 6. ContextMenu

Простое меню (без ListBox и без поиска по буквам) с подменю. Compound-компонент (зонтичный, раздел 11.1). Семантика меню, не списка выбора (раздел 11): `role="menu"`, `role="menuitem"`, `role="separator"`; активация пункта вызывает команду и закрывает меню, выбора значения нет. Этап 3 переводит внутренности на ListBox; публичный API при этом сохраняется, поэтому ниже только то, что останется.

```ts
interface ContextMenuPoint { x: number; y: number }     // координаты вьюпорта (clientX, clientY)

interface ContextMenuRootProps {
  open?: boolean;
  defaultOpen?: boolean;                                 // по умолчанию false
  onOpenChange?: (open: boolean) => void;
  anchorPoint?: ContextMenuPoint | null;                 // точка, заданная снаружи (контекстное меню строки грида)
  children?: JSX.Element;
}
interface ContextMenuTriggerProps extends Omit<JSX.HTMLAttributes<HTMLDivElement>, 'class' | 'style'> {
  disabled?: boolean;
  class?: string;
  style?: JSX.CSSProperties;
}
interface ContextMenuContentProps extends Omit<JSX.HTMLAttributes<HTMLDivElement>, 'class' | 'style' | 'role'> {
  size?: 'sm' | 'md' | 'lg';
  class?: string;
  style?: JSX.CSSProperties;
}
interface ContextMenuItemProps extends Omit<JSX.HTMLAttributes<HTMLDivElement>, 'class' | 'style' | 'role' | 'onSelect'> {
  variant?: 'default' | 'danger';
  disabled?: boolean;
  closeOnSelect?: boolean;                               // по умолчанию true
  onSelect?: () => void;
  class?: string;
  style?: JSX.CSSProperties;
}
// ContextMenu.Separator
// ContextMenu.Sub (состояние подменю), ContextMenu.SubTrigger (пункт со стрелкой), ContextMenu.SubContent
```

```tsx
<ContextMenu.Root>
  <ContextMenu.Trigger>Область с контекстным меню</ContextMenu.Trigger>
  <ContextMenu.Content>
    <ContextMenu.Item onSelect={rename}>Переименовать</ContextMenu.Item>
    <ContextMenu.Sub>
      <ContextMenu.SubTrigger>Переместить в</ContextMenu.SubTrigger>
      <ContextMenu.SubContent>
        <ContextMenu.Item onSelect={() => move('a')}>Папка A</ContextMenu.Item>
      </ContextMenu.SubContent>
    </ContextMenu.Sub>
    <ContextMenu.Separator />
    <ContextMenu.Item variant='danger' onSelect={remove}>Удалить</ContextMenu.Item>
  </ContextMenu.Content>
</ContextMenu.Root>
```

Решения (рекомендации):

- **Вызов.** `ContextMenu.Trigger` это `<div>`-область: по событию `contextmenu` отменяет действие по умолчанию и открывает меню в точке клика (виртуальный якорь `{ getBoundingClientRect }` с нулевым размером, Floating UI сам разворачивает меню через `flip` и `shift` вместо ручного зажатия из референса, раздел 8 зонтичного). С клавиатуры: клавиша ContextMenu и Shift+F10 на элементе внутри области открывают меню у нижнего левого угла сфокусированного элемента. Снаружи меню можно открыть, передав `anchorPoint` и `open`; тогда `Trigger` не нужен (так будет работать меню строки грида). Область вызова служит `anchorElement` (хост и возврат фокуса), но не исключением из клика снаружи: меню передаёт `dismissExempt={() => undefined}` (раздел 3.3).
- **Хост:** по правилам раздела 3.2 (`PanelHostContext` → область `Trigger` → `document.body`).
- **Фокус и навигация (DOM-фокус на пунктах).** Корень меню `tabindex="-1"` и получает фокус при открытии мышью; при открытии с клавиатуры фокус на первом доступном пункте. Пункты `tabindex="-1"`, фокус переводят `ArrowDown`/`ArrowUp` (по кругу, недоступные пропускаются), `Home`/`End`; `Enter` и `Space` активируют (`preventDefault()`, чтобы форма не отправилась). Подсветка пункта это `:focus` (мышь при наведении переводит на пункт фокус), кольцо только `:focus-visible` и внутреннее: корень меню несёт `data-s-kit-focus-inset` (зонтичный, раздел 5.1). `Tab` закрывает все меню и не уводит фокус дальше инициатора. Esc закрывает верхний слой стека (подменю или меню), фокус возвращается на пункт-инициатор подменю или на инициатор меню (раздел 3.4).
- **Подменю.** `ContextMenu.Sub` держит состояние подменю, `SubTrigger` это пункт с `aria-haspopup="menu"`, `aria-expanded` и стрелкой. `ArrowRight` или `Enter`/`Space` на нём открывают подменю и ставят фокус на его первый пункт; `ArrowLeft` закрывает подменю и возвращает фокус на `SubTrigger`. Наведение мыши открывает подменю через 120 мс и закрывает, когда фокус уходит на другой пункт родителя. «Безопасный треугольник» движения к подменю не делается (YAGNI). Подменю это вложенный слой стека (клик снаружи каскадно закрывает оба, раздел 3.1), позиционируется `right-start` с `flip`, якорь это `SubTrigger`. Композиция (Composite): меню и подменю используют одни и те же `ContextMenu.Content`-механики через общий компонент пунктов; глубина вложенности не ограничена.
- **Закрытие:** Esc, клик снаружи (каскад), активация пункта (если не `closeOnSelect={false}`; закрывает всю цепочку меню, а не только подменю), `Tab`, прокрутка любого предка или окна и изменение размера окна (меню в точке клика не должно остаться висеть над сдвинувшимся содержимым; правило раздела 8.4 зонтичного для грида включает это поведение). События прокрутки внутри самого меню меню не закрывают.
- **Ширина:** `--s-kit-menu-min-width` (фолбэк 180 px) … `--s-kit-menu-max-width` (фолбэк 320 px), по содержимому; длинные пункты обрезаются многоточием и получают `title` (раздел 6.2 зонтичного: для меню в этапе 3 ширина измеряется по первому окну рендера, пока ListBox не появился, ширина естественная в этих пределах).
- **Пункт:** высота по правилу раздела 5 зонтичного (`var(--s-kit-control-height, var(--s-kit-control-height-md))`), `danger` красит текст `--s-kit-color-danger`, отключённый: `aria-disabled="true"`, `cursor: not-allowed`, `--s-kit-disabled-opacity`, не получает фокус при навигации, не активируется.
- **Компонентные токены:** `--s-kit-menu-bg`, `--s-kit-menu-min-width`, `--s-kit-menu-max-width`, `--s-kit-menu-item-radius`, `--s-kit-menu-padding` (фолбэк 4 px).
- **Тесты:** чистые функции навигации по пунктам (следующий и предыдущий доступный по кругу, Home и End с пропуском недоступных, пустое меню) отдельным файлом; компонент: открытие по `contextmenu` в точке, `anchorPoint` снаружи, клавиши ContextMenu и Shift+F10, роли и `aria-*`, навигация стрелками, Home и End, Enter и Space, `onSelect` и закрытие, `closeOnSelect={false}`, отключённый пункт, `danger`, подменю (открытие стрелкой вправо и наведением, возврат стрелкой влево и Esc, клик снаружи закрывает оба), закрытие по Tab, прокруткой и изменением размера окна, возврат фокуса, изоляция событий, ошибка вне Root.
- **Вне объёма:** поиск по набору букв, группы с заголовками, пункты-флажки и пункты-радио, горячие клавиши в подписях, значки, «безопасный треугольник».

## 7. Замена `Probe` и `probe-unused`, матрица формы пакета

- Демонстрационные панели страницы «Темы», которые должны оставаться открытыми для проверок (секции 1 и 3), делаются управляемыми (`<Popover.Root open>` без `onOpenChange`): при `defaultOpen` первый `pointerdown` по переключателю темы закрыл бы их каскадом. Нативный `<dialog>` страницы в стек слоёв не регистрируется (это появится у Dialog в части 2), поэтому Esc на нём закрывает только панель, открытую поверх.
- `Probe` и его контекст `ProbeScope` удаляются в части 1. Страница «Темы» (критерий 5) и проверки `theme-checks.ts` переводятся на `Popover` (вложенные области, компонентный токен формы вместо `--s-kit-probe-panel-bg`: `--s-kit-popover-bg`, материал панели, панель внутри `<dialog>`, настоящий Esc). Атрибут `data-probe-panel` заменяется на `data-s-kit-popover-content` (ставится самим компонентом, нужен для проверок).
- `ProbeScope` (контекст, который читается внутри содержимого матрицы) заменяется на `usePopover()`: в матрице `#scope` показывает `popover-open`, `#app` по-прежнему читает контекст приложения; это сохраняет проверку «контекст, созданный приложением, читается внутри компонента кита» (критерий 1 зонтичного).
- `probe-unused` остаётся до части 2 и заменяется на Dialog как «неимпортированный компонент»: потребитель Dialog не импортирует, а сборка проверяет, что строки из его кода в бандл не попали. Маркеры в сборке: вместо `marker-used` проверяется строка `must be used inside Popover.Root` (часть 1), вместо `marker-unused` строка `must be used inside Dialog.Root` (часть 2).
- В `scripts/consumer/src/main.tsx` Popover заменяет Probe (используется), Dialog не импортируется (часть 2); в `scripts/verify-package-form.sh` проверка CSS Probe заменяется токеном `--s-kit-popover-padding`, проверка порядка правил не нужна (основы нулевой специфичности).
- Тесты `probe.test.tsx` удаляются вместе с компонентом (часть 1); их проверки (контролируемый и неконтролируемый режим, слой в стеке, панель в top layer) переходят в тесты Popover.

## 8. Критерии готовности этапа

Из дорожной карты (раздел 13 зонтичного) для этапа 2:

1. **Приёмка Esc.** Popover с формой внутри Dialog: первый Esc закрывает только Popover, второй закрывает Dialog, `onOpenChange(false)` диалога вызван ровно один раз. ContextMenu с подменю внутри Dialog: три нажатия закрывают по очереди подменю, меню и диалог. Проверяется настоящим нажатием Esc в Chrome. Вариант с Select переносится на этап 3.
2. **Критерий 6 раздела 12, сценарии (б), (в), (д)** на странице «Панели»:
   - (б) панель, инициатор которой лежит под предком с `pointer-events: none`, остаётся кликабельной;
   - (в) Popover внутри `<label>` и внутри кликабельной карточки с `onClick`/`onDblClick`: клик и двойной клик по содержимому не активируют `<label>` и не вызывают обработчики карточки; Enter внутри панели в `<form>` не отправляет форму;
   - (д) предки инициатора с `transform`, `filter`, `contain: paint` и `overflow: hidden`: панель не обрезана и стоит у якоря.
3. **Панель внутри Dialog** видна поверх него (проверено на этапе 0 на Probe, повторяется на Popover и ContextMenu); панель, открытая из диалога, лежит в DOM-поддереве диалога даже при внешнем провайдере хоста.

## 9. Применённые паттерны и границы абстракций (требование раздела 11)

- **Compound components:** Popover (`Root`, `Trigger`, `Content`), Dialog (`Root`, `Trigger`, `Content`, `Title`, `Description`, `Body`, `Footer`, `Close`), ContextMenu (`Root`, `Trigger`, `Content`, `Item`, `Separator`, `Sub`, `SubTrigger`, `SubContent`). Состояние держит `Root` через контекст; контекст без провайдера бросает понятную ошибку. Быстрых форм (фасадов) этапа нет: у Popover и Dialog нечего фасадировать, а меню собирается из пунктов.
- **Render props:** `Popover.Trigger`/`Dialog.Trigger` (`render`), функция-ребёнок у `Popover.Content` и `Dialog.Content` с состоянием `{ open, close }` (контракт раздела 11.1: вызов через `untrack`, реактивные чтения внутри JSX).
- **Template Method / композиция хуков (Decorator):** жизненный цикл слоя (открыть → позиционировать → слушать dismiss → закрыть → вернуть фокус) собирается из хуков `createPanelLayer`, `createAnchoredPosition`, `createFocusOnOpen`, `createFocusRestore` внутри `FloatingPanel`; Popover и ContextMenu подключаются колбэками (`onOpenChange`, `onDismiss`), а не наследованием; Dialog использует тот же стек слоёв, но не `FloatingPanel` (у него нативная модальность).
- **Composite:** дерево меню (меню → подменю → …); каждый уровень это один и тот же компонент пунктов.
- **Strategy:** `placement` и якорь (элемент или точка) подставляются в позиционирование.
- **DIP:** компоненты зависят от интерфейса позиционирования (`createAnchoredPosition`) и стека слоёв, а не от Floating UI и DOM-слушателей напрямую.
- **SRP:** чистые функции (`resolvePanelHost`, навигация по пунктам меню, `isOutsideRect` для подложки диалога) отдельно от хуков и разметки.
- **LSP:** Popover, Dialog и ContextMenu соблюдают единый контракт открытия: `open`/`defaultOpen`/`onOpenChange` (раздел 7 зонтичного).
- Зависимости только вниз: компоненты → `internal/` и `utils/` → ничего; Popover и Dialog зависят от Button (инициатор и `Dialog.Close`), ContextMenu от общих внутренних модулей.

## 10. Решения владельца (2026-10-30)

Все вопросы раздела ниже закрыты.

1. **`closeOnBackdropClick` у Dialog по умолчанию (принято: `true`).** Рекомендация: `true` (привычное поведение; диалоги с несохранёнными данными ставят `false`). Альтернатива: `false` по умолчанию, закрытие только явными кнопками и Esc.
2. **Прокрутка страницы под открытым Dialog (принято: блокировать, делается в части 2, см. раздел 5).** Нативный модальный диалог делает фон инертным, но колесо над подложкой по-прежнему прокручивает страницу. Решение: блокировать прокрутку `html` через `:has(dialog[open])` с `scrollbar-gutter: stable`.
3. **Каскадный клик снаружи (принято, общий спек исправлен)** (раздел 3.1) отличается от формулировки зонтичного «клик снаружи обрабатывает только верхний слой». Формулировка общего спека: «Esc закрывает только верхний слой, клик снаружи каскадно закрывает все слои выше слоя с целью».
4. **Инициатор через `render`, а не `as` (принято)** (раздел 4).
5. **Где живёт внутренний код (принято: `src/internal/`):** `src/internal/` вне `exports` (рекомендация) или `src/utils/`. Папка `src/utils/` по зонтичному это хелперы без DOM-компонентов; `FloatingPanel` это компонент, поэтому `internal/`.
6. **Подменю: задержка наведения 120 мс без безопасного треугольника (принято 2026-10-30; треугольник записан тех. долгом SK-1 на Ticket Board).** Достаточно для этапа или нужен треугольник сразу.
7. **Закрытие Popover при уходе фокуса не делается (принято).** (форма внутри Popover и переключение окон не должны его закрывать).

## 11. Что не проверено (на момент написания спека)

- Всё поведение в браузере: `display: contents` у контейнера `Portal` не влияет на раскладку хоста; `showModal()` и панель в top layer над диалогом при хосте внутри `<dialog>`; `::backdrop` наследует токены диалога; `contain: paint` у предка не обрезает панель в top layer; настоящий Esc при каскаде из трёх слоёв; поведение close watcher.
- Что порядок удаления DOM и пользовательских эффектов в Solid 1.9.17 именно такой, как описано в разделе 3.4 (читалось по исходнику, тест в плане 1 проверяет это прогоном).
- `HTMLDialogElement` в jsdom: методов `showModal` и `close` нет, поэтому поведение диалога в юнит-тестах это тестовый адаптер, а не браузер.
