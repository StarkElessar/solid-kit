## 1. Рамки

В этапе три публичных компонента **Select**, **Combobox**, **MultiSelect** и общий внутренний **ListBox**, на котором они стоят. Отдельно создаётся «окно рендера» (интерфейс и две реализации) в `src/utils/`, потому что оно нужно и гриду (этап 4а).

**Решения владельца, принятые до спека (2026-10-31):**

1. Select, Combobox и MultiSelect переиспользуют один ListBox. Это одна общая реализация списка, а не три копии.
2. **ContextMenu на ListBox не переводится.** Он остаётся на DOM-фокусе, как в этапе 2. Что у меню и у списков общего, решается отдельным анализом, когда готовы все компоненты (раздел 14).
3. Меню колонок грида (этап 4б) строится на ContextMenu, а не на ListBox. Что ему нужно добавить в ContextMenu, решается в спеке этапа 4б.
4. Композиция, а не наследование: общее поведение выносится в функции и хуки, а Select, Combobox и MultiSelect собирают их по-своему. Цепочка «Select → Combobox → MultiSelect» не строится, потому что отношения «является» между ними нет (у Combobox другая модель фокуса и ввод текста).

Как в этапах 1 и 2, этап режется по частям: у каждой свой короткий план и свой коммит (или несколько), зелёная `pnpm check` обязательна перед каждым коммитом, план пишется перед выполнением своей части. Тег ставится один раз на конец этапа: `v0.4.0`, когда выполнены все критерии раздела 10.

## 3. Окно рендера (`src/utils/`)

Реализует разделы 6 и 11.1 (DIP) зонтичного: ListBox и грид зависят от интерфейса, а не от TanStack.

```ts
export interface RenderWindowItem {
  readonly index: number;   // индекс строки в плоском списке
  readonly start: number;   // смещение сверху, px (для отступов-spacer)
  readonly size: number;
}

export interface RenderWindow {
  items: Accessor<readonly RenderWindowItem[]>;
  totalSize: Accessor<number>;
  measure: (element: HTMLElement) => void;               // ref строки; строке нужен атрибут data-index
  scrollToIndex: (index: number, options?: { align?: 'auto' | 'start' | 'center' | 'end' }) => void;
}

export interface RenderWindowOptions {
  count: Accessor<number>;
  scroller: Accessor<HTMLElement | undefined>;
  estimateSize: (index: number) => number;               // стартовая оценка, раздел 6 зонтичного
  overscan: number;                                      // по умолчанию 6 у списков
  scrollPaddingStart?: Accessor<number>;                 // высота липкого заголовка группы
  initialHeight?: Accessor<number>;                      // высота окна до первого измерения скроллера (см. «Начальное окно»)
}

type ScrollAlign = 'auto' | 'start' | 'center' | 'end';   // выравнивание у scrollToIndex
```

- `createVirtualWindow(options)` в `create-virtual-window.ts`: обёртка над `createVirtualizer`; пункты рендерятся в обычном потоке между двумя spacer-элементами (раздел 6 зонтичного), а не абсолютным позиционированием. `measure` передаётся в `measureElement`, поэтому пункты с `renderOption` любой высоты поддерживаются.
- `createFullWindow(options)` в `create-full-window.ts`: при `virtualized={false}`; `items()` возвращает все строки без измерения, `scrollToIndex` прокручивает через `scrollIntoView({ block: 'nearest' })` с `scroll-padding` на скроллере.
- **Оценка высоты** берётся по правилу раздела 5: вычисленное `--s-kit-control-height` на скроллере, иначе `--s-kit-control-height-md`, иначе 32. Читается один раз при открытии, не на каждую строку.
- **Начальное окно.** Чтобы первый кадр не рендерил пустой список, виртуализатору передаётся `initialRect` с высотой `min(--s-kit-listbox-max-height, count × estimate)`. Из-за этого Select не нуждается в фазе «открыта невидимой»: ширину даёт якорь (раздел 6.2 зонтичного), а высота известна заранее. Не мигает ли панель в левом верхнем углу до расчёта позиции, проверяется в части 2 (поведение `FloatingPanel` из этапа 2 не менялось).
- **Тестовый адаптер геометрии** (`src/utils/render-window.test-helper.ts`, только для тестов): реализация `RenderWindow` с известными размерами, ручным смещением и фиксированной высотой окна. Нужен потому, что в jsdom нет раскладки (раздел 12 зонтичного). Реальную геометрию (переменные высоты, sticky) проверяет только браузер.

## 4. Чистые функции списка (`src/internal/list-box/`)

Все без DOM и без Solid, каждая в своём файле со своим тестом.

```ts
type ListKey = string | number;

type ListRow<T> =
  | { kind: 'option'; key: ListKey; item: T; label: string; disabled: boolean; optionIndex: number; groupIndex: number }
  | { kind: 'group'; key: string; label: string; groupIndex: number }
  | { kind: 'all'; key: ListKey };        // строка «Все» MultiSelect (раздел 8); подпись рисует разметка (allLabel), активируется как опция, в optionIndex не входит

interface FlattenOptions<T> {
  getKey: (item: T) => ListKey;
  getLabel: (item: T) => string;
  groupBy?: (item: T) => string;
  isItemDisabled?: (item: T) => boolean;
  allKey?: ListKey;             // ключ строки «Все», например -1; без него строки нет
}
```

- **`isRowAvailable(row)`**: опция без `disabled` или строка «Все»; на неё можно поставить подсветку. Ею пользуются остальные функции.
- **`flattenRows(items, options)`** возвращает `readonly ListRow<T>[]`: плоский список из заголовков групп и опций (индексы раздела 6.1 зонтичного). Группы собираются в порядке первого появления значения `groupBy`; внутри группы порядок элементов исходный. Заголовок пустой группы не создаётся. При `allKey` и хотя бы одной опции первой идёт строка `{ kind: 'all', key: allKey }` (перед первым заголовком); без опций её нет. `getLabel` вызывается один раз на элемент (на 100 000 это допустимо, затем результат живёт в строке), `optionIndex` нужен для `aria-posinset`.
- **`nextActiveIndex(rows, current, command, pageSize)`** с командами `next | previous | first | last | next-page | previous-page` возвращает индекс строки или `-1`. Идёт по плоскому списку, пропуская заголовки и отключённые опции. **Без зацикливания:** на краю остаётся на месте (на 100 000 элементов перескок с конца в начало сбивает; в меню оно зацикливается, это другой компонент). Если `current` отсутствует (`-1`), `next` и `first` дают первую доступную, `previous` и `last` последнюю.
- **`matchTypeahead(rows, current, buffer)`**: первая доступная опция, чья подпись начинается с накопленной строки (регистр не учитывается, `toLocaleLowerCase`); поиск идёт от `current` включительно и по кругу; повтор одной буквы подряд переходит к следующей опции на эту букву. Накопление и сброс буфера (500 мс без нажатий) делает хук, не функция.
- **`initialActiveIndex(rows, selectedKeys)`**: индекс первой выбранной опции, иначе первой доступной, иначе `-1` (раздел 6.1: при открытии список прокручивается к выбранному).
- **`filterItems(items, query, filter, getLabel)`**: Strategy фильтра. По умолчанию `getLabel(item).toLocaleLowerCase().includes(query.toLocaleLowerCase())`, пустой запрос возвращает `items` как есть, `filter === false` отключает клиентский фильтр (внешний поиск). Используется Combobox и MultiSelect.
- **`resolveActiveKey(rows, activeKey)`**: после смены данных или запроса сохраняет подсветку, если ключ остался среди доступных опций, иначе возвращает ключ первой доступной (раздел 6.1: подсветка сбрасывается на первую допустимую опцию).

## 5. ListBox

Внутренний компонент в `src/internal/list-box/`, вне `exports` пакета (решение раздела 12, вопрос 1). Разделён на контроллер (состояние и клавиши, без разметки) и разметку.

### 5.1 Модель фокуса: подсветка через `aria-activedescendant`

Для всех трёх потребителей один способ: **DOM-фокус остаётся у владельца списка** (кнопка Select, поле ввода Combobox, поле поиска MultiSelect), а список показывает *активную* опцию. Владелец получает `aria-activedescendant` с `id` активной опции. Причины:

- Combobox не может отдать фокус опции: он в поле ввода;
- в виртуализированном списке DOM-элемент активной опции может быть не смонтирован, а фокус на удалённом узле теряется, `aria-activedescendant` указывает на `id`, а активная опция по контракту 6.1 всегда в окне;
- одна модель для трёх потребителей проще проверяется, чем две.

Следствия: подсветка это `[data-active]`, а не `:focus`; кольцо фокуса рисуется на активной опции только при клавиатурной модальности (поле-владелец в состоянии `:focus-visible`), при наведении мыши опция получает только фон (`--s-kit-color-tint`); кольцо внутреннее (`data-s-kit-focus-inset` на скроллере, раздел 5.1 зонтичного). Различие источника: контроллер хранит `activeSource: 'keyboard' | 'pointer'` и ставит его атрибутом `data-active-source` на скроллер.

### 5.2 Контроллер

```ts
interface ListBoxControllerOptions<T> {
  rows: Accessor<readonly ListRow<T>[]>;
  selectedKeys: Accessor<ReadonlySet<ListKey>>;
  onActivate: (item: T) => void;                  // клик или Enter/Space на активной опции
  window: RenderWindow;
  keys?: { typeahead?: boolean; space?: boolean; homeEnd?: boolean };  // по умолчанию все true
}

interface ListBoxController<T> {
  activeKey: Accessor<ListKey | undefined>;
  activeId: Accessor<string | undefined>;          // для aria-activedescendant владельца
  setActiveKey: (key: ListKey | undefined, source: 'keyboard' | 'pointer') => void;
  resetActive: () => void;                         // при открытии: initialActiveIndex + прокрутка
  /** Возвращает true, если клавиша обработана; владелец вызывает preventDefault(). */
  handleKeyDown: (event: KeyboardEvent) => boolean;
}
```

- `handleKeyDown` обрабатывает `ArrowDown`, `ArrowUp`, `Home`, `End` (если `homeEnd`), `PageUp`, `PageDown` (шаг `pageSize` = число полностью помещающихся строк окна), `Enter` и `Space` (если `space`; в поле ввода пробел это текст), печатные символы без модификаторов (если `typeahead`). Combobox и поле поиска MultiSelect передают `keys: { typeahead: false, space: false, homeEnd: false }`.
- Активная опция прокручивается `window.scrollToIndex`; для переменных высот прокрутка считается завершённой после измерения (раздел 6.1 зонтичного), поэтому контроллер после `scrollToIndex` повторяет вызов один раз в следующем кадре, если строка ещё не смонтирована. Подробности повтора уточняются в плане части 2 и проверяются тестом на адаптере.
- Подсветка хранится по ключу, а не по индексу или элементу DOM.
- `id` опций строятся из `createUniqueId()` списка и ключа: `${listId}-opt-${String(key)}` с экранированием.

### 5.3 Разметка и поведение

```ts
interface ListBoxProps<T> {
  controller: ListBoxController<T>;
  rows: Accessor<readonly ListRow<T>[]>;
  window: RenderWindow;
  scrollerRef: (element: HTMLElement) => void;
  multiple?: boolean;                              // aria-multiselectable, индикатор выбора у опций
  loading?: boolean;
  loadingText?: JSX.Element;                       // «Загрузка…»
  emptyText?: JSX.Element;                         // «Нет элементов для отображения»
  renderOption?: (item: T, state: OptionState) => JSX.Element;
  renderGroupHeader?: (label: string) => JSX.Element;
  size?: 'sm' | 'md' | 'lg';
}
interface OptionState { selected: Accessor<boolean>; active: Accessor<boolean>; disabled: boolean }
```

- Скроллер `role="listbox"`, `data-s-kit-focus-inset`, `aria-multiselectable` при `multiple`; `tabindex` нет (фокус у владельца).
- Опция `role="option"`, `aria-selected`, `aria-disabled`, `id`, **`aria-setsize` и `aria-posinset`** (число опций и порядковый номер среди опций): в виртуализированном списке без них вспомогательные технологии видят только смонтированные строки. `data-index` для измерения.
- Заголовок группы `role="presentation"`, не активируется и не выбирается. **Липкий заголовок** текущей группы рендерится отдельным `position: sticky` элементом в начале скроллера и показывает группу первой видимой строки; пока его строка в окне, она не дублируется. Для `scrollToIndex` задаётся `scrollPaddingStart` на его высоту, чтобы активная опция не уходила под него (Focus Not Obscured, раздел 5.1 зонтичного).
- Пока `loading`, вместо строк текст загрузки (`role="status"`); при пустом результате текст `emptyText`. Скроллер при этом без окна рендера.
- **Указатель:** `mousemove` на опции ставит её активной с источником `pointer` (движение, а не `mouseover`, чтобы прокрутка колёсиком под неподвижным курсором не перебивала подсветку клавиатуры); `click` активирует опцию; `mousedown` на списке вызывает `preventDefault()`, поэтому фокус не уходит с владельца; отключённая опция не активируется.
- Высота опции: минимум `var(--s-kit-control-height, var(--s-kit-control-height-md))` (раздел 5 зонтичного), длинная подпись обрезается многоточием и получает `title`.
- Скроллер: `overflow: auto`, `overscroll-behavior: contain`, `max-block-size` из `--s-kit-listbox-max-height` (фолбэк 320 px) и из доступного места (`size()` Floating UI уже кладёт `max-height` на панель).

## 6. Select

Compound-компонент (раздел 11.1 зонтичного) и быстрая форма поверх его частей.

**Поправка к зонтичному (раздел 12, вопрос 2).** В примере 11.1 внутри `Select.Content` лежат `Select.Group` и `Select.Option`. Такая разметка не сочетается с виртуализацией по умолчанию: опции, заданные детьми, нельзя размонтировать и нельзя пронумеровать в плоском списке. Поэтому данные приходят **пропсами корня** (`items`, `getKey`, `getLabel`, `groupBy`), а части это `Root`, `Trigger`, `Content`. Опций и групп как компонентов нет, их внешний вид меняют `renderOption` и `renderGroupHeader`.

```ts
interface SelectRootProps<T> {
  items: readonly T[];
  getKey: (item: T) => ListKey;
  getLabel: (item: T) => string;
  groupBy?: (item: T) => string;
  isItemDisabled?: (item: T) => boolean;
  value?: T | null;
  defaultValue?: T | null;                      // по умолчанию null
  onValueChange?: (value: T | null) => void;
  open?: boolean;
  defaultOpen?: boolean;
  onOpenChange?: (open: boolean) => void;
  loading?: boolean;
  virtualized?: boolean;                        // по умолчанию true
  overscan?: number;                            // по умолчанию 6
  disabled?: boolean;
  size?: 'sm' | 'md' | 'lg';                     // размер у корня: от него зависят и кнопка, и строки списка
  children?: JSX.Element;
}
interface SelectTriggerProps extends Omit<JSX.ButtonHTMLAttributes<HTMLButtonElement>, 'class' | 'style' | 'disabled'> {
  placeholder?: JSX.Element;
  renderValue?: (item: T) => JSX.Element;       // по умолчанию подпись
  class?: string;
  style?: JSX.CSSProperties;
}
interface SelectContentProps<T> {
  renderOption?: ListBoxProps<T>['renderOption'];
  renderGroupHeader?: ListBoxProps<T>['renderGroupHeader'];
  loadingText?: JSX.Element;                    // по умолчанию «Загрузка…»
  emptyText?: JSX.Element;                      // по умолчанию «Нет элементов для отображения»
  class?: string;
  style?: JSX.CSSProperties;
}
```

- **Быстрая форма:** `<Select items={users} getKey={...} getLabel={...} value={v()} onValueChange={setV} placeholder='Сотрудник' />` собирает `Root`, `Trigger`, `Content` из одного набора пропсов (Facade). Основной способ использования; части нужны для своего инициатора через `render` или нестандартной раскладки.
- Тип `T` у `Content` не выводится из контекста (контекст стирает тип). Render-пропсы в частях типизируются явно: `<Select.Content<User> renderOption={...}>`; в быстрой форме `T` общий, поэтому проблемы нет.
- **Trigger:** нативная `<button type="button" role="combobox">`, `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` (id скроллера), `aria-activedescendant` пока открыт, внутри подпись выбранного (или `placeholder` приглушённым цветом) и шеврон (inline SVG, как отметки Checkbox). Высота по правилу раздела 5, граница `--s-kit-color-control-edge`. Атрибуты Field (`id`, `aria-describedby`, `aria-invalid`) принимаются как у Input; метка `<label for>` работает, потому что кнопка labelable.
- **Открытие:** клик по кнопке переключает; `ArrowDown`, `ArrowUp`, `Enter`, `Space` на закрытой кнопке открывают. При открытии активной становится выбранная опция (иначе первая доступная), список прокручивается к ней.
- **Открыт (фокус на кнопке):** клавиши контроллера (раздел 5.2); `Enter` и `Space` выбирают активную опцию и закрывают список; печать букв ищет по началу подписи (typeahead). `Esc` закрывает через стек слоёв, фокус остаётся на кнопке. `Tab` закрывает без выбора, фокус уходит естественным порядком. Клик снаружи закрывает каскадом.
- **Выбор:** `onValueChange(item)`, список закрывается, повторный выбор уже выбранного значения не снимает его (значение `null` Select получает только извне). Выбранная опция помечена фоном `--s-kit-color-row-selected` и отметкой.
- **Данные меняются при открытом списке:** подсветка по `resolveActiveKey`; выбранное значение показывается из `value`, даже если его уже нет в `items` (внешний поиск).
- **Панель:** `FloatingPanel` с `matchAnchorWidth`, `initialFocus="none"`, `placement` `bottom-start` (по умолчанию из этапа 2), минимальная ширина `--s-kit-listbox-min-width` (раздел 6.2 зонтичного), хост по правилам этапа 2.
- **Тесты:** `getKey` и выбор по ключу, controlled/uncontrolled для `value` и `open`, роли и `aria-*` (в том числе `aria-setsize` и `aria-posinset`), открытие всеми клавишами, навигация (на адаптере окна, 1000 строк, прокрутка до недоступной опции), выбор Enter/Space/кликом, закрытие Esc, Tab, клик снаружи, typeahead, отключённая опция, группы и липкий заголовок, пустое состояние и `loading`, `virtualized={false}` рендерит все строки, значение вне `items`, изоляция событий, возврат фокуса, ошибка вне `Select.Root`.

## 7. Combobox

Поле ввода с фильтруемым списком. Compound: `Combobox.Root`, `Combobox.Input`, `Combobox.Content`, быстрая форма.

```ts
interface ComboboxRootProps<T> extends /* items, getKey, getLabel, groupBy, isItemDisabled, value, defaultValue,
                                          onValueChange, open, defaultOpen, onOpenChange, loading, virtualized, overscan, disabled как у Select */ {
  query?: string;                                // текст в поле; controlled-тройка query / defaultQuery / onQueryChange
  defaultQuery?: string;
  onQueryChange?: (query: string, reason: 'input' | 'reset') => void;   // 'reset': текст вернулся к подписи значения
  filter?: ((item: T, query: string) => boolean) | false;   // Strategy; false: фильтрует сервер
}
```

- **Модель.** Фокус всегда в `<input role="combobox">` (`aria-autocomplete="list"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`); в поле справа кнопка-шеврон (`tabindex="-1"`, `aria-label` задаётся пропом, по умолчанию «Показать список»), клик по ней открывает и закрывает список. Поле это `Input` из этапа 1 (граница, ошибка, размер), шеврон добавляется поверх.
- **Фильтр только после печати.** Пока текст в поле это подпись значения (список открыли, не печатая), список показывается целиком; запрос для фильтра равен тексту только после события `input`, до выбора или ухода из поля. `onQueryChange(query, reason)`: `'input'` при печати, `'reset'` при возврате текста к подписи; страница с внешним поиском не ищет по `'reset'`.
- **Что показывает поле.** Закрытый список: подпись выбранного значения (или пустое поле с `placeholder`). Пользователь печатает: показывается введённый текст (`query`), список открывается, `onQueryChange(text)` вызывается на каждое изменение, клиентский фильтр применяется к `items` (раздел 4, `filterItems`), подсветка сбрасывается на первую доступную опцию. При `filter={false}` `items` показывается как пришёл: страница ищет по `onQueryChange` и передаёт результат, `loading` показывает текст загрузки.
- **Клавиши.** `ArrowDown` открывает список (если закрыт) и двигает подсветку, `ArrowUp` так же; `PageUp`/`PageDown` по странице; `Home` и `End` остаются клавишами поля (перенос курсора), как и `Space`; typeahead выключен (`keys: { typeahead: false, space: false, homeEnd: false }`). `Enter` при открытом списке и активной опции выбирает её, закрывает список и вызывает `preventDefault()` (форма страницы не отправляется); при закрытом списке или без активной опции `Enter` ничего не перехватывает. `Esc` закрывает список через стек слоёв; фокус остаётся в поле. `Tab` закрывает список.
- **Закрытие и значение.** После выбора и при потере фокуса текст поля возвращается к подписи выбранного значения: свободного ввода нет. Если пользователь стёр весь текст и ушёл из поля, значение сбрасывается в `null` (иначе очистить поле нельзя, рекомендация раздела 12, вопрос 4).
- **Панель** как у Select: `matchAnchorWidth` по ширине поля (якорь это оболочка поля), `initialFocus="none"`.
- **IME.** Фильтрация во время композиции ввода (`compositionstart` … `compositionend`) не откладывается: пока что не проверено в браузере (раздел 13).
- **Тесты:** controlled/uncontrolled для `value`, `query`, `open`; фильтр по умолчанию и свой, `filter={false}`; открытие печатью и стрелкой; Enter с активной опцией и без; Home/End/Space не перехватываются; сброс текста при закрытии; очистка значения при пустом тексте; `aria-*`; ошибка вне `Combobox.Root`.

## 8. MultiSelect

Множественный выбор. Compound: `MultiSelect.Root`, `MultiSelect.Trigger`, `MultiSelect.Content`, быстрая форма. Отдельный компонент, а не режим `multiple` у Select: тип значения (`readonly T[]` против `T | null`) и разметка триггера (чипы) различаются настолько, что общий компонент с режимом дал бы взаимоисключающие пропсы (раздел 12, вопрос 3).

```ts
interface MultiSelectRootProps<T> extends /* items, getKey, getLabel, groupBy, isItemDisabled, open, defaultOpen, onOpenChange,
                                             loading, virtualized, overscan, disabled, filter, query, defaultQuery, onQueryChange как выше */ {
  value?: readonly T[];                          // порядок выбора сохраняется
  defaultValue?: readonly T[];
  onValueChange?: (value: readonly T[]) => void;
  total?: number;                                // «из M»; без него число элементов items
  searchable?: boolean;                          // поле поиска в панели, по умолчанию true
  allLabel?: JSX.Element;                        // строка «Все» первой в списке; без пропа строки нет
  chipsOverflow?: 'collapse' | 'wrap' | 'summary';   // по умолчанию 'collapse' (раздел 5 зонтичного)
}
```

- **Триггер** собран из оболочки `div` и трёх частей: чипы выбранных значений (каждый с кнопкой `×`, обычная нативная кнопка в порядке табуляции, кольцо внутреннее), основная `<button role="combobox">` на оставшуюся ширину (плейсхолдер, счётчик «+N» или «N из M», шеврон) и фон оболочки с границей `--s-kit-color-control-edge`. Метка `<label for>` указывает на кнопку `combobox`. Клик по пустому месту оболочки открывает список. Вложенные кнопки не лежат внутри кнопки: поэтому не одна `<button>`.
- **Режимы переполнения** (рекомендация зонтичного, раздел 5, решение владельца): `collapse` показывает чипы в одну строку, не поместившееся сворачивается в «+N»; `summary` один чип «N из M» со стрелкой; `wrap` чипы переносятся и контрол растёт, он выпадает из проверки единой высоты и показывается на странице «Контролы в ряд» отдельной строкой с пометкой. `N` это число выбранных, в том числе вне текущего результата поиска; `M` это `total`, а без него число `items`; при `N > M` показывается «N выбрано», при `N = 0` плейсхолдер, при всех выбранных «43 из 43».
- **Расчёт `collapse`.** Чистая функция `fitChips(widths, available, counterWidth, gap)` возвращает число помещающихся чипов (юнит-тест). Ширины чипов измеряются после первого показа и кэшируются по ключу; пересчёт по `ResizeObserver` контейнера. Чтобы не рендерить десятки тысяч чипов, измеряются и рендерятся не более 24 первых; остальные идут в счётчик.
- **Панель.** Список с индикатором выбора у каждой опции (отметка у выбранных, `aria-selected`, `aria-multiselectable`), панель **не закрывается** по выбору, повторный клик снимает. При `searchable` вверху панели поле ввода (`Input`), оно владелец списка (`aria-activedescendant`, `keys: { typeahead: false, space: false, homeEnd: false }`), `initialFocus` переводит фокус в него; `onQueryChange` сообщает запрос странице (внешний поиск), `filter` как у Combobox. Без `searchable` владельцем остаётся кнопка `combobox`, фокус при открытии остаётся на ней, работает typeahead.
- **Строка «Все»** (владелец, 2026-10-31: у «Все» принят ключ вроде `-1`, как `allItem` или `allKey`; код референса в репозитории нет, поэтому остальная логика ниже рекомендация, а не перенос). Пропы `allKey` (например `-1`) и `allLabel`; при `allLabel` первой строкой списка идёт «Все» (не опция из `items`, отдельный вид строки в `ListRow`): клик переключает все элементы, прошедшие текущий фильтр (при пустом запросе все `items`); отметка у «Все» стоит, когда выбраны все такие элементы. Решение владельца (2026-10-31): при выбранном «Все» значение это `allKey` (например `-1`), а не массив элементов; нужен полный набор, потребитель запрашивает его сам. Так значение не раздувается до 100 000 записей. Точная типизация (`value`: массив ключей или `allKey`) и поведение «Все» вместе с отдельными отметками (снятие одной опции выводит из состояния «Все») фиксируются в плане части 4.
- **Клавиши.** На закрытой кнопке `ArrowDown`, `ArrowUp`, `Enter`, `Space` открывают; в открытом списке `Enter` и `Space` (если не поле поиска) переключают активную опцию; `Esc` закрывает, фокус возвращается на кнопку `combobox`; `Tab` закрывает и возвращает фокус на кнопку, чтобы следующий `Tab` продолжил с неё.
- **Тесты:** controlled/uncontrolled; переключение опций с сохранением порядка; панель остаётся открытой; `searchable` и без него; внешний поиск; режимы `collapse`, `summary`, `wrap` на адаптере (`fitChips` отдельно); «N из M» и все граничные случаи формулы (`N = 0`, `N > M`, все выбраны); удаление чипа кнопкой; выбранное вне результата поиска; `aria-*`.

## 9. Стили и токены

- Компонентные токены (публичный API кастомизации, читаются с фолбэком на глобальные): `--s-kit-select-bg`, `--s-kit-combobox-bg`, `--s-kit-multiselect-bg` (фон панели каждого компонента), `--s-kit-select-border`, `--s-kit-select-radius`, `--s-kit-select-width` (триггер Select, Combobox, MultiSelect), общие для списков `--s-kit-listbox-min-width` (фолбэк 160 px), `--s-kit-listbox-max-height` (фолбэк 320 px), `--s-kit-listbox-padding` (фолбэк 4 px), `--s-kit-listbox-item-radius`. Каждый объявляется как токен, чтобы пройти `no-unknown-custom-properties`.
- Подсветка активной опции `--s-kit-color-tint`; выбранная опция `--s-kit-color-row-selected` и отметка; отключённая `--s-kit-disabled-opacity` и `cursor: not-allowed`. Литералов цветов нет (раздел 11 зонтичного).
- Панель подключает основу из `panel-base.module.css` (`composes`), материал и тень как у ContextMenu.
- Размер: Select, Combobox, MultiSelect принимают `size`, строка ListBox наследует высоту через `data-s-kit-size` на панели (панель в top layer не наследует размер обёртки, поэтому `FloatingPanel` получает `size`, как у меню).

## 10. Критерии готовности этапа

Из дорожной карты (раздел 13 зонтичного) для этапа 3:

1. **Ряд контролов.** Select, Combobox и MultiSelect (`collapse` и `summary` в пяти рядах, `wrap` отдельной строкой с пометкой) стоят на одной линии с кнопкой, инпутом и остальными контролами этапов 0–2 без разнобоя; внешнее кольцо фокуса видно целиком, соседей не двигает.
2. **Производительность Select** (раздел 6.3 зонтичного): страница «Большие списки», 100 000 опций; открытие до 100 мс, не более 5 % кадров длиннее 16,7 мс при равномерной прокрутке на 10 секунд, в DOM не больше окна плюс `overscan`. Измеряется в production-сборке playground в Chrome.
3. **Навигация по контракту 6.1** покрыта юнит-тестами (раздел 4) и компонентными тестами на адаптере окна: прокрутка до опции вне окна, пропуск заголовков групп и отключённых опций, сброс подсветки после смены запроса, прокрутка к выбранному при открытии.
4. **Критерий 6 (е)** для ListBox и Select (и Combobox, MultiSelect): активная опция показывает внутреннее кольцо целиком у верхнего и нижнего края скроллера; кольцо не закрыто липким заголовком группы; после закрытия панели фокус и кольцо на инициаторе. **Критерий 7:** чипы MultiSelect внутри области с `overflow: hidden` показывают внутреннее кольцо; Focus Not Obscured для пункта под липким заголовком.
5. **Критерий 6 (б), (в), (д) для Select:** панель из-под предка с `pointer-events: none` кликабельна; Select внутри `<label>` и кликабельной карточки: клик и двойной клик по опции не задевают `<label>` и обработчики карточки; Enter в панели внутри `<form>` не отправляет форму; предки с `transform`, `filter`, `contain: paint`, `overflow: hidden` панель не обрезают. Страница «Панели» дополняется сценариями для Select.
6. **Esc-приёмка из этапа 2** (перенесена сюда): Select внутри Dialog: первый Esc закрывает панель Select, второй закрывает Dialog, `onOpenChange(false)` диалога вызван один раз. Проверяется настоящим нажатием Esc в Chrome.
7. **`virtualized={false}`** рендерит все элементы (тест и страница).
8. Контраст текста в панелях, подписях опций и плейсхолдерах не ниже 4,5:1 в обеих темах; страница «Темы» включает Select (фон `--s-kit-select-bg` из формы, как описано в критерии 5 зонтичного) и остаётся зелёной.
9. controlled/uncontrolled покрыты тестами; чистые функции раздела 4 покрыты юнит-тестами; `pnpm check` зелёная; матрица формы пакета (`scripts/verify-package-form.sh`) зелёная на TypeScript 5.9.3 и 7.0.2.

Проверка идёт в Chrome. Firefox 125 и Safari 17.5 не проверяются (нет доступа), как на этапах 0–2.

## 11. Применённые паттерны и границы абстракций

- **Compound components + Facade:** `Select`, `Combobox`, `MultiSelect` собираются из `Root`, `Trigger`/`Input`, `Content` с общим состоянием в контексте; быстрая форма поверх частей.
- **Strategy:** фильтр Combobox и MultiSelect (`filter`), реализация окна рендера, позиционирование.
- **DIP:** ListBox зависит от интерфейса `RenderWindow`, а не от TanStack; панели зависят от `FloatingPanel`, а не от Floating UI.
- **SRP:** чистые функции (`flattenRows`, `nextActiveIndex`, `matchTypeahead`, `filterItems`, `fitChips`) отдельно от контроллера, контроллер отдельно от разметки.
- **Композиция хуков (Decorator), а не наследование:** общее поведение это функции и контроллер; компоненты подключают нужное. Select, Combobox и MultiSelect не наследуют друг от друга.
- **Render props:** `renderOption`, `renderGroupHeader`, `renderValue`; состояние передаётся аксессорами (контракт слотов раздела 11.1).
- **Зависимости вниз:** `Select`/`Combobox`/`MultiSelect` → `internal/list-box`, `internal/floating-panel`, `Input` → `utils/` (окно рендера, позиционирование, `createControllableSignal`). `internal/list-box` не знает о Select, Combobox, MultiSelect; ContextMenu от него не зависит.
- Один компонент в файле, имена kebab-case, один класс на файл (классов нет): раздел 11 зонтичного.

## 12. Решения и вопросы владельцу (рекомендации)

1. **ListBox внутренний, не публичный.** Рекомендация: внутренний (`src/internal/list-box/`, вне `exports`), как в зонтичном. Публичным его можно сделать позже добавлением `src/components/list-box/index.ts`, ломающих изменений не будет. Альтернатива: публичный сразу (нужен, если появится самостоятельный список без выпадающей панели).
2. **Select без `Select.Option` и `Select.Group`** (раздел 6). Рекомендация: данные пропсами, детей-опций нет, иначе виртуализация по умолчанию невозможна. Зонтичный (раздел 11.1) правится.
3. **MultiSelect отдельным компонентом, не режимом `multiple` у Select** (раздел 8). Рекомендация: отдельный. Альтернатива: `Select multiple` с условными типами пропсов; решение можно пересмотреть в финальном анализе общего (раздел 14).
4. **Combobox: пустой текст и уход из поля сбрасывают значение в `null`.** Рекомендация: сбрасывают (иначе очистить нечем). Альтернатива: значение не меняется, добавить кнопку очистки (`clearable`).
5. **Без зацикливания в списках.** Рекомендация: на краю остаётся на месте (на 100 000 элементов перескок сбивает); в ContextMenu зацикливание сохраняется.
6. **Чипы MultiSelect с `×` в порядке табуляции.** Решение владельца (2026-10-31): да, `×` каждого чипа остаётся в порядке табуляции (клавиатурный пользователь может убрать чип; цена: больше остановок `Tab`).
7. **Строка «Все» в MultiSelect** (раздел 8). Ответ владельца: у «Все» принят ключ вроде `-1` (`allKey`). Решение владельца (2026-10-31): при «Все» значение равно `allKey` (`-1`), полный набор потребитель запрашивает сам.

**Ответы владельца (2026-10-31):** 1 — группировка опций по условию с заголовком группы и самими элементами нужна, виртуализация тоже: это `groupBy` и `renderGroupHeader`, а не компоненты `Select.Group`/`Select.Option` (раздел 6); 2 — MultiSelect отдельным компонентом; 3 — пустой текст в Combobox сбрасывает значение; 4 — без зацикливания принято; 7 — см. выше.

## 13. Что не проверено (на момент написания спека)
