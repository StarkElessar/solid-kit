# Этап 5, часть 2. DatePicker и общая оболочка полей даты и времени

Статус: принята владельцем 2026-11-03 (все рекомендации раздела 12, `selectOnToday` по умолчанию `true`), реализация по плану `docs/superpowers/plans/2026-11-03-stage-5-date-picker.md`. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md` (далее «зонтичный»), спека Calendar: `2026-11-02-stage-5-calendar-design.md` (далее «спека Calendar»). Здесь только то, чего в них нет: поле с текстом даты, открытие календаря, общая оболочка для DatePicker, TimePicker и DateTimePicker. TimePicker и DateTimePicker получат свои спеки после DatePicker.

## 1. Рамки

**DatePicker** это поле даты: текстовый ввод, значок календаря и панель с `Calendar` в плавающей панели (раздел 8 зонтичного, как у Select и Combobox). Значение это ISO-строка `'2026-11-03'` или `null` (раздел 2 зонтичного).

**Решения владельца (2026-11-03):**

1. **«Сегодня» выбирает дату.** В DatePicker кнопка подвала Calendar выбирает сегодняшнюю дату, закрывает панель и возвращает фокус в поле.
2. **Клик по полю ввода открывает календарь.** Клик по значку календаря в поле тоже открывает календарь. Это общее правило для DatePicker, TimePicker и DateTimePicker: поведение живёт в общей оболочке `PickerField`, а не в каждом компоненте отдельно.

**Вне объёма:** выбор диапазона (`DateRangePicker`), маска ввода с автоподстановкой разделителей, пользовательские форматы даты (`format`, `parse`), несколько дат, не григорианские календари. Время и дата со временем это отдельные спеки на той же оболочке.

## 2. Что меняется в существующем

- **Calendar:** новый проп `selectOnToday?: boolean` (по умолчанию `true`, решение владельца 2026-11-03: «Сегодня» выбирает дату везде, а не только в DatePicker). Кнопка «Сегодня» вызывает `onValueChange` с сегодняшней датой; `false` возвращает «только перенести показ».
- **`src/utils/date/`:** три хелпера текста даты по локали (раздел 4).
- **Новое:** `src/internal/picker-field/` (оболочка, раздел 3) и `src/components/date-picker/`.
- Popover, Input, Field, `FloatingPanel` не меняются: оболочка собирается из них.

## 3. Общая оболочка `PickerField` (`src/internal/picker-field/`)

Внутренний компонент (не часть публичного API), на нём строятся три пикера. Он знает про поле, значок, открытие и фокус; не знает про даты и время.

**Раскладка.** Оболочка-`span` (она же якорь панели) с `data-s-kit`, внутри `Input` и кнопка-значок справа (по образцу `Combobox.Input`: кнопка внутри рамки поля). Необязательная кнопка «Очистить» между текстом и значком. Рядом скрытый `<input type="hidden" name value>`, если задан `name`. Панель: `FloatingPanel` под якорем (`placement: bottom-start`), `role="dialog"` с `aria-label`, содержимое отдаёт пикер.

**Правила открытия (требование владельца):**

| Действие | Результат |
|---|---|
| Клик (касание) по полю ввода, панель закрыта | **открывает** панель; фокус и курсор остаются в поле |
| Клик по полю ввода, панель открыта | панель остаётся открытой, курсор ставится в текст |
| Клик по значку, панель закрыта | **открывает** панель; фокус возвращается в поле |
| Клик по значку, панель открыта | закрывает панель (переключатель, как шеврон Combobox); вопрос 1 |
| ArrowDown или Alt+ArrowDown в поле | открывает панель (если закрыта) и переносит фокус внутрь неё |
| Клик снаружи, Tab, Esc | закрывают; Esc возвращает фокус в поле |
| `disabled` | клики и клавиши ничего не открывают |
| `readOnly` | текст не меняется, клики по полю и значку панель **не** открывают (значение нельзя выбрать) |

- Значок это `<button type="button" tabindex="-1">` с `onMouseDown: preventDefault`: клик по нему не уводит фокус из поля и не считается уходом из поля (как у Combobox). Клавиатурные пользователи открывают панель стрелкой вниз. У значка есть доступное имя из `labels.openCalendar`.
- Поле: `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` (id панели, пока она открыта), `autocomplete="off"`.
- Открытие по указателю не переносит фокус в панель, чтобы можно было сразу печатать дату. Открытие стрелкой переносит (`autoFocus` у Calendar).
- Панель монтируется заново при каждом открытии: Calendar всегда стартует в режиме дней на месяце текущего значения.

**Контракт с пикером** (пропсы оболочки): `text` и `onTextChange` (набираемый текст), `onCommit(text)` (Enter и уход из поля), `onRevert()` (Esc при закрытой панели и откат при ошибке), `open`/`defaultOpen`/`onOpenChange` (тройка через `createControllableSignal`, имя `PickerField`), `icon`, `placeholder`, `disabled`, `readOnly`, `size`, `clearable` и `onClear`, `name` и `hiddenValue`, `labels`, `children: (panel) => JSX` с `panel.close()`, `panel.autoFocus` и `panel.restoreFocus()`; а также `Field`-атрибуты (`id`, `aria-describedby`, `aria-invalid`, `aria-label`) пробрасываются на `<input>`.

## 4. Хелперы текста даты (`src/utils/date/`)

Чистые функции, по одной на файл, у каждой тест таблицами для `ru`, `en-US`, `de`, `ja`.

| Функция | Что делает |
|---|---|
| `datePattern(locale): DatePattern` | порядок частей (`day`, `month`, `year`) и разделитель из `Intl.DateTimeFormat(locale, { day: '2-digit', month: '2-digit', year: 'numeric', timeZone: 'UTC' }).formatToParts`; запасной порядок день-месяц-год с точкой |
| `formatDateText(parts, locale): string` | текст по образцу локали с ведущими нулями (`'03.11.2026'`, `'11/03/2026'`) |
| `parseDateText(text, locale): DateParts \| null` | разбор набранного: части разделены любой нецифровой последовательностью или идут подряд цифрами (`03112026`); порядок по `datePattern`; год ровно из 4 цифр (вопрос 2); несуществующая дата даёт `null`; пустая строка даёт `null` |

Подсказка в поле (`placeholder` по умолчанию) строится из образца: для `ru` «дд.мм.гггг», для `en-US` «мм/дд/гггг» (названия частей берутся из `labels`).

## 5. Публичный API DatePicker

```ts
value?: string | null;                 // 'YYYY-MM-DD'
defaultValue?: string | null;
onValueChange?: (value: string | null) => void;

open?: boolean;
defaultOpen?: boolean;
onOpenChange?: (open: boolean) => void;

min?: string;                          // как у Calendar
max?: string;
isDateDisabled?: (date: string) => boolean;

locale?: string;                       // по умолчанию 'ru'; влияет на формат текста и на Calendar
firstDayOfWeek?: 0 | 1 | 2 | 3 | 4 | 5 | 6;
placeholder?: string;
disabled?: boolean;
readOnly?: boolean;
clearable?: boolean;                   // кнопка «Очистить»; по умолчанию false
name?: string;                         // скрытое поле с ISO-значением для форм
size?: 'sm' | 'md' | 'lg';
labels?: Partial<DatePickerLabels>;
// остальные атрибуты input (id, aria-*, required, autofocus, onBlur, onFocus…) попадают на <input>
```

- Тройки `value` и `open` через `createControllableSignal` (имя `DatePicker`).
- **Выбор в календаре** (день, «Сегодня») вызывает `onValueChange(date)`, обновляет текст, закрывает панель и возвращает фокус в поле.
- **Ввод текста.** Текст хранится отдельно от значения и пока не принят. Валидный полный текст (разбирается и проходит `min`, `max`, `isDateDisabled`) показывается в Calendar сразу: открытый календарь переходит на этот месяц и фокусирует эту дату, значение при этом не меняется. **Принимается** (вызывается `onValueChange`) по Enter и при уходе из поля. Пустой текст принимается как `null`. Невалидный или запрещённый текст при Enter и уходе откатывается к тексту текущего значения (без сообщений: сообщение об ошибке это дело `Field`).
- Внешнее изменение `value` сразу обновляет текст, если пользователь в этот момент не печатает.
- `Escape` при открытой панели закрывает её (стек слоёв); при закрытой откатывает набранный текст.
- Недопустимая ISO-строка в `value`, `min`, `max`: dev-предупреждение и поведение как у «пусто» (разбор через `readDateProp`, как в Calendar).
- `DatePickerLabels` (по умолчанию на русском, `DEFAULT_DATE_PICKER_LABELS`): `openCalendar` («Открыть календарь»), `clear` («Очистить»), `calendar` (имя диалога, «Выбор даты»), `day`, `month`, `year` (части для подсказки: «дд», «мм», «гггг»). Подписи Calendar приходят через `calendarLabels?: Partial<CalendarLabels>`.

## 6. Вид

Оболочка: высота `--s-kit-control-height`, граница и скругление как у `Input`, кольцо фокуса на оболочке при фокусе в поле (`:focus-within`, как у Combobox), ширина по умолчанию `--s-kit-date-picker-width` (10rem; влезает `дд.мм.гггг`), значок 16 px цвета `--s-kit-color-muted`, при наведении `--s-kit-color-text`. Панель: общий материал панелей, внутри Calendar с `showToday` и `selectOnToday`, отступы Calendar. Токены: только существующие плюс `--s-kit-date-picker-width`. CSS с нативной вложенностью, без литералов цветов.

## 7. Доступность

- Поле: `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`; `aria-invalid` и `aria-describedby` от `Field`.
- Панель: `role="dialog"`, `aria-label`; внутри `role="group"` Calendar и его клавиатурная модель (спека Calendar, раздел 5).
- Значок и «Очистить» имеют `aria-label`; значок вне порядка Tab (стрелка вниз открывает панель), «Очистить» тоже вне порядка Tab (текст стирается клавишами).
- Esc закрывает сначала панель, потом внешний диалог (раздел 8.3 зонтичного); Tab из поля закрывает панель.

## 10. Критерии готовности

- а) клик по полю ввода открывает календарь, второй клик его не закрывает; клик по значку открывает календарь, повторный закрывает; в обоих случаях значение не меняется до выбора;
- б) открытие кликом оставляет курсор в поле, печать работает сразу; ArrowDown и Alt+ArrowDown переносят фокус в календарь;
- в) выбор дня и «Сегодня» принимают дату, обновляют текст, закрывают панель и возвращают фокус в поле; повторный выбор текущей даты тоже закрывает;
- г) набранная дата показывается в календаре до принятия; Enter и уход из поля принимают; пустое значение даёт `null`; невалидный или запрещённый текст откатывается;
- д) `min`, `max`, `isDateDisabled`, `disabled`, `readOnly`, `clearable`, `name` (значение в `FormData`) работают;
- е) внутри `Field` поле получает `id`, `aria-describedby`, `aria-invalid`; подпись по клику фокусирует поле и не открывает календарь;
- ж) панель не обрезается предками с `overflow`, `transform`, `contain` (критерий 6 д зонтичного); в диалоге Esc закрывает сначала календарь, потом диалог (6 в, 8.3);
- з) обе темы читаемы; хелперы текста покрыты тестами для `ru`, `en-US`, `de`, `ja`; `pnpm check` и `verify-package-form.sh` зелёные.

## 11. Применённые паттерны и границы абстракций

- **Композиция вместо наследования:** `PickerField` принимает содержимое панели и функции текста, DatePicker, TimePicker и DateTimePicker отличаются только ими.
- **Adapter:** ISO-строка ↔ `DateParts` ↔ текст по локали; на границе компонента преобразование один раз.
- **Strategy:** формат и разбор текста через `datePattern(locale)`; позже сюда встанет пользовательский формат.
- DatePicker зависит от Calendar и `PickerField`, Calendar от DatePicker не зависит.

## 12. Открытые вопросы (рекомендации)

1. **Клик по значку при открытой панели:** закрывает (переключатель, как шеврон Combobox). Альтернатива: только открывает. Владелец сказал «открывает»; рекомендую переключатель, иначе панель из-под значка не закрыть мышью без клика снаружи.
2. **Год из двух цифр** (`03.11.26`): не принимать, нужен год из 4 цифр (иначе `85` превращается в 2085 в датах рождения). Альтернатива: 2000–2099.
3. **Когда принимать набранный текст:** по Enter и уходу из поля, а календарь показывает набранное сразу. Альтернатива: принимать в момент, когда набран полный валидный текст (значение меняется во время печати, форма может сработать преждевременно).
4. **Маска ввода:** в первой версии нет, только подсказка и разбор любых разделителей; маска с подстановкой разделителей отдельным шагом, если понадобится.
5. **`selectOnToday` в Calendar по умолчанию `true`** (владелец согласился, 2026-11-03): «Сегодня» выбирает дату и в автономном Calendar.
6. **`clearable` по умолчанию `false`:** стереть можно клавишами (пустой текст принимается как `null`). Для форм с необязательной датой включать явно.
7. **Значок вне порядка Tab:** как у шеврона Combobox, открытие с клавиатуры стрелкой вниз. Альтернатива: значок отдельный Tab-стоп (так делает образец APG).
8. **Пользовательский формат** (`format`/`parse`) не в первой версии: формат берётся из локали.

## 13. Что не проверено

Всё, что касается браузеров, кроме Chrome: поведение клика по полю и значку на сенсорных устройствах (экранная клавиатура поднимается при открытии кликом по полю, возможно, лучше открывать без фокуса в поле на касании), IME при вводе даты (кириллическая раскладка и composition), автозаполнение браузера (`autocomplete="off"` обязателен), экранные читалки, Firefox и Safari (позиционирование панели, `:focus-within`).

## 14. Итоги реализации и приёмки (2026-11-03)

Страница playground «Выбор даты» (`playground/src/date-picker-page.tsx`, демо в `demo-date-pickers.tsx`, проверки в `date-picker-checks.ts`).

**Автопроверки в Chrome: 28 из 28** в системной, светлой и тёмной темах, повторные прогоны подряд идемпотентны (проверка формы сама приводит значение к известному). Покрыто: критерии а, б, в, г, д, ж (кроме Esc в диалоге), ширина текста в `clearable`.

**Вручную настоящими событиями мыши и клавиш:** клик по полю открывает и не закрывает повторно; клик по значку открывает и закрывает; курсор остаётся в поле; Esc закрывает и оставляет фокус в поле; набранная `05.12.2026` переключает календарь на декабрь до принятия, Enter принимает; ArrowDown переносит фокус на набранную дату; стрелки и Enter в календаре выбирают дату и возвращают фокус в поле; Tab из календаря закрывает его и возвращает фокус в поле. В диалоге панель календаря рисуется поверх диалога, первый Esc закрывает только календарь, второй закрывает диалог, фокус возвращается на кнопку открытия. Календарь в предке с `overflow` не обрезан (тёмная тема, скриншот).

**Найдено и исправлено при приёмке:** в `clearable` при ширине по умолчанию год обрезался («18.11.202»): кнопка очистки резервирует квадрат контрола справа, а ширина оставалась 10rem. Теперь у `clearable` поле шире на этот квадрат (`data-clearable`, статический признак, ширина не прыгает при появлении текста), проверка `scrollWidth <= clientWidth` добавлена в автопроверки, тест на атрибут в `picker-field.test.tsx`.

**Не воспроизведено:** в одном из ранних прогонов после правки (первая загрузка страницы, 4 прогона по темам) 9 проверок упали, при этом счётчик закрытий диалога показал 1, то есть диалог на странице открылся и закрылся без явного клика. Падения совпадали с признаком «фокус в поле внутри диалога». В 15 дальнейших прогонах на свежих загрузках (включая наблюдатель за появлением диалога и кликом по кнопке) повтора нет. Причина не установлена; если повторится, смотреть, кто вызывает `onOpenChange(false)` у закрытого `Dialog` и что открывает его при загрузке.

**Не проверено:** Firefox, Safari, сенсорные устройства, IME, экранные читалки (раздел 13).
