# Этап 4б, третья часть. Автосуммы (`totals`)

Статус: реализовано и принято 2026-11-01. Первая версия (две строки «Итого на странице» и «Итого по выборке» с подписью в первой колонке) отклонена владельцем в тот же день: «Должен быть 1 глобальный футер с глобальными автосуммами. Не нужно в ячейках писать "Итоги бла бла бла", потому что в любой ячейке могут быть данные для автосумм». Ниже итоговое решение. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md` (далее «зонтичный»), ссылки «раздел N» относятся к нему.

## 1. Рамки

Грид показывает итоговые значения, **посчитанные сервером**; сам он ничего не суммирует и не пересчитывает по загруженным строкам. Один глобальный футер под таблицей: значения `totals` по всей выборке. Страничных итогов (`pageTotals`) нет: решение владельца 2026-11-01. Групповые агрегаты (`GridGroup.aggregates`) относятся к группировке и показываются в строках групп.

**Вне объёма:** сами вычисления (сервер), итоги страницы, агрегаты по выбранным строкам, экспорт.

## 2. Публичный API

```ts
totals?: Readonly<Record<string, unknown>>;   // итоги по всей выборке, ключ — id колонки
```

- Футер есть, только если проп передан. `{}` это «итоги переданы, значений нет»: футер с пустыми ячейками (страница может зарезервировать место, пока считается итог).
- Ключ, которого нет среди видимых колонок, игнорируется; видимая колонка без ключа (или со значением `undefined`) показывает пустую ячейку. Значение первой колонки показывается как у любой другой: подписей в футере нет.
- `GridColumn.aggregate?: (value: unknown) => JSX.Element`: формат итога колонки (общий для футера и агрегатов групп). Без него значение показывается как `formatCellValue(value)`. Вызывается только для значения, которое не `undefined`.

## 3. Раскладка и вид

`<tfoot>` с одной строкой внутри той же таблицы: колонки совпадают по ширине с телом и едут при горизонтальной прокрутке вместе с ним.

- Ячейки прилипают к низу скроллера (`position: sticky; inset-block-end: 0`), слой выше ячеек тела; закреплённые колонки закреплены так же, как в теле (те же CSS-переменные, разделитель `data-sticky-last`).
- Колонка чекбоксов: пустая закреплённая ячейка.
- Фон `--s-kit-grid-footer-bg` (по умолчанию `--s-kit-color-surface-2`), верхняя граница `--s-kit-color-border-strong`, высота как у шапки (высота контрола), `font-weight: 600`, `font-variant-numeric: tabular-nums`, выравнивание по `GridColumn.align`.
- `scroll-padding-block-end` скроллера и `scrollPaddingEnd` окна рендера равны высоте футера: строка, к которой прокручивают, не уходит под него.

## 4. Состояния и доступность

- `loading`: значения заменены полосой-заглушкой (`aria-hidden`), футер остаётся.
- Пусто: футер показывается, если передан.
- `aria-rowcount` таблицы = число элементов тела + 1 (шапка) + 1 (футер); `aria-rowindex` футера = число элементов + 2. Ячейки футера обычные `td`, фокус не принимают; выбор, меню строки и двойной клик на футер не реагируют (обработчики стоят на `tbody`).

## 5. Файлы

`grid-totals.tsx` (`tfoot`), `grid-totals-row.tsx` (строка), `grid-totals-cell.tsx` (ячейка), `totals-cell-content.ts`, `has-totals-value.ts` (с тестами); изменены `grid-props.ts` (`totals`), `grid-column.ts` (`aggregate`), `grid-context.ts`, `grid.tsx`, `grid-table.tsx`, `grid.module.css`.

## 6. Критерии приёмки

- а) без `totals` в таблице нет `tfoot`; с ним одна строка, в ячейках только значения, подписей нет;
- б) формат через `aggregate`, иначе `formatCellValue`; отсутствующий ключ даёт пустую ячейку;
- в) футер прилипает к низу, закрепленные колонки остаются на месте при горизонтальной прокрутке;
- г) `loading` показывает заглушки; `aria-rowcount` и `aria-rowindex` верны; клики по футеру ничего не выбирают;
- д) последняя строка при прокрутке до конца видна целиком над футером; светлая и тёмная темы читаемы.

## 7. Итоги приёмки (2026-11-01)

Первая версия (две строки с подписью) принята в Chrome, затем заменена по решению владельца. Для нынешней версии: `pnpm check` зелёный, юнит-тесты на каждый критерий (а)–г); автопроверки playground (`runTotalsChecks`) и ручная проверка в Chrome повторяются после правки (см. итоги в конце сессии). Не проверены: Firefox и Safari (`position: sticky` у ячеек `tfoot`), экранные читалки. Ограничение: длинное значение в узкой колонке обрезается многоточием, как в теле.
