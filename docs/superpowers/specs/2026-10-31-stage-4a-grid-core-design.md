## 1. Рамки

В этапе один публичный компонент **Grid** (подпуть `@stark/solid-kit/grid`) и всё, что нужно ему внутри. Окно рендера (`createVirtualWindow` и `createFullWindow`), Checkbox, ContextMenu, `PanelHostContext` и токены уже есть из этапов 0–3.

**Решения владельца, принятые в диалоге 2026-10-31:**

1. **Клавиатура:** грид это обычная таблица без курсора строки. Tab ходит по реальным интерактивным элементам (кнопки сортировки, чекбоксы, контролы в ячейках). Контекстное меню строки открывают Shift+F10 и клавиша ContextMenu на любом элементе внутри строки; меню встаёт у этого элемента. Строка сама не фокусируется, действия «двойной клик» с клавиатуры нет. Следствие: если в строке нет ни одного фокусируемого элемента (нет `selectable`, нет контролов в ячейках), с клавиатуры до меню строки не добраться. Это принято сознательно (в не-целях зонтичного нет roving tabindex и полных ARIA-паттернов).
2. **Выбор мышью:** как в референсе, без диапазонов. Клик по строке переключает её выбор, чекбокс тоже; клик по интерактивному элементу внутри ячейки строку не трогает; Shift и Ctrl ничего не меняют.
3. **Контекстное меню строки:** `rowContextMenu(row)` возвращает JSX меню (`ContextMenu.Item`, `Sub`, `Separator`). Нового типа `MenuItem` нет.
4. **Ресайз колонок не перерисовывает грид** (требование владельца): ширина идёт через CSS-переменные на `<col>`, во время перетаскивания Solid-состояние не трогается (раздел 4.2).

Как в этапах 1–3, этап режется по частям: у каждой свой короткий план и свой коммит (или несколько), зелёная `pnpm check` обязательна перед каждым коммитом, план пишется перед выполнением своей части. Тег ставится один раз на конец этапа: `v0.5.0` (рекомендация; зонтичный даёт `v1.0.0` только после 4б).

## 2. Публичный API

Грид «глупый» и controlled (раздел 7): данные, сортировку и выбор хранит страница. Пропсы не деструктурируются (`splitProps` и геттеры).

```ts
type RowKey = string | number;

interface GridSort { columnId: string; direction: 'asc' | 'desc' }

interface GridColumn<T> {
  id: string;                          // стабильный ключ колонки
  title: string;
  value: (row: T) => unknown;          // значение по умолчанию: String(value) при отсутствии `cell`
  cell?: (row: T) => JSX.Element;
  width?: number;                      // ширина по умолчанию, px; 160, если не задана
  minWidth?: number;                   // 60
  align?: 'start' | 'end' | 'center';  // 'start'
  locked?: boolean;                    // закреплена слева (в 4а только из пропсов)
  hidden?: boolean;                    // скрыта (в 4а только из пропсов)
  sortable?: boolean;
}

interface GridProps<T> {
  rows: readonly T[];
  getRowKey: (row: T) => RowKey;       // уникальный и стабильный между загрузками
  columns: readonly GridColumn<T>[];
  loading?: boolean;
  loadingLabel?: string;               // 'Загрузка'
  emptyText?: string;                  // 'Ничего не найдено'
  emptyHint?: JSX.Element;
  onEmptyReset?: () => void;           // кнопка «Сбросить фильтры» только если передан
  sort?: GridSort | null;  defaultSort?: GridSort | null;  onSortChange?: (sort: GridSort | null) => void;
  selectable?: boolean;
  selectedKeys?: ReadonlySet<RowKey>;  defaultSelectedKeys?: ReadonlySet<RowKey>;
  onSelectedKeysChange?: (keys: ReadonlySet<RowKey>) => void;
  columnWidths?: Readonly<Record<string, number>>;  defaultColumnWidths?: Readonly<Record<string, number>>;
  onColumnWidthsChange?: (widths: Readonly<Record<string, number>>) => void;
  onRowDoubleClick?: (row: T) => void;
  rowContextMenu?: (row: T) => JSX.Element;
  selectAllLabel?: string;             // 'Выбрать все строки'
  selectRowLabel?: string;             // 'Выбрать строку'
  foundText?: (count: number) => string;  // 'Найдено N записей', объявляется после загрузки
  rowHeight?: number;                  // стартовая оценка высоты строки, px; по умолчанию высота контрола
  overscan?: number;                   // 12
  virtualized?: boolean;               // true
  'aria-label'?: string;
  class?: string;
  style?: JSX.CSSProperties;
}
```

Правила:

- `defaultColumnWidths`, `defaultSort`, `defaultSelectedKeys` — обязательные значения неконтролируемого режима внутри компонента (`{}`, `null`, пустой `Set`), как в разделе 7.
- Тип строки `T` выводится из `rows` и `columns`; `getRowKey` вызывается один раз на строку при построении плоского списка.
- **Порядок колонок:** порядок массива `columns`; закреплённые (`locked`) идут первыми, внутри своей группы в порядке массива; скрытые не рендерятся. Колонка чекбоксов (если `selectable`) всегда первая и всегда sticky.
- **Ширины:** `GridColumn.width` — исходная ширина. Итоговая ширина колонки `clamp(columnWidths[id] ?? width ?? 160, minWidth, ∞)`.
- **`onColumnWidthsChange`** вызывается один раз по окончании ресайза (`pointerup`), а не на каждый пиксель; в аргументе полный словарь ширин (все изменённые колонки).
- **`onSortChange`** вызывается по циклу `asc → desc → null`; грид сам строки не сортирует.
- **`onSelectedKeysChange`** получает новый `Set`; предыдущий не мутируется. Выбор сохраняется между загрузками (ключи не пропадают, если строк с ними нет в `rows`).
- Внешний вид корня: одна карточка с рамкой, радиусом и фоном (раздел 10.1, «корпус»), `overflow: clip`, `data-s-kit-focus-inset`.

## 3. Модель данных и состояния

Три уровня, как в списках, но проще (групп в 4а нет): `rows` → плоский список строк (`{ key, row, index }`) → окно DOM. Индексы относятся к плоскому списку; связь «ключ ↔ индекс» (`Map<RowKey, number>`) пересчитывается при смене `rows`. Выбор и контекстное меню хранятся по ключу, а не по DOM.

Состояния грида (взаимоисключающие, в порядке приоритета): `loading` (заглушки строк), `empty` (`rows.length === 0` и не загрузка), `ready`. При `loading` и непустых `rows` строки заменяются заглушками: данные прошлой загрузки не показываются (как в референсе).

Внутренний контекст `GridContext` (один класс — один файл, раздел 12) раздаёт дочерним частям: упорядоченные колонки с вычисленными ширинами, `sort`, `selectedKeys`, `selectable`, окно рендера, колбэки. Контекст создаётся в `Grid`, снаружи не виден.

## 4. Раскладка таблицы

### 4.1. Модель таблицы

- Тело грида это `<table>` с `table-layout: fixed`, `border-collapse: separate`, `border-spacing: 0`. Модель `collapse` не годится: рамки ячеек не едут вместе со sticky-ячейками.
- Разделитель колонок и нижняя линия строки рисуются границами ячеек (`border-inline-end`, `border-block-end` цветом `--s-kit-color-hairline`), `box-sizing: border-box`: ширина колонки из store равна ширине ячейки вместе с рамкой, поэтому сумма ширин колонок равна ширине таблицы без поправок.
- Шапка: `position: sticky; inset-block-start: 0` внутри скроллера, плоский фон `--s-kit-color-surface-2`.
- Скроллер (`overflow: auto`) ставит `scroll-padding-inline-start` (сумма ширин sticky-колонок) и `scroll-padding-block-start` (высота шапки): фокус и `scrollIntoView` не прячутся под липкими областями (критерий 7, раздел 5.1).
- Размер: корень занимает высоту родителя (`block-size: 100%`, `min-block-size: 0`), скролл только внутри скроллера. Если родитель высоты не задаёт, действует токен `--s-kit-grid-max-height` (по умолчанию `32rem`).
- Spacer-строки состоят из одной ячейки с `colspan` на все колонки и на ширины не влияют. Содержимое ячеек на ширину не влияет: текст обрезается многоточием с `title` (по умолчанию) или переносится, если страница задала `white-space: normal` в `cell`.

### 4.2. Ширины и ресайз без перерисовки

Единственный источник фактической ширины колонок — словарь в состоянии (controlled/uncontrolled). На корне таблицы он превращается в CSS-переменные:

| Переменная | Значение | Кто читает |
|---|---|---|
| `--s-kit-grid-w-<i>` | ширина колонки `i` в px (`i` — индекс среди видимых упорядоченных колонок) | `<col style="width: var(--s-kit-grid-w-<i>)">` |
| `--s-kit-grid-table-w` | сумма ширин всех колонок | `min-inline-size` таблицы |
| `--s-kit-grid-left-<i>` | смещение закреплённой колонки `i` (сумма ширин предшествующих sticky-колонок) | `inset-inline-start` её ячеек |

Ширина таблицы `100%` с `min-inline-size: var(--s-kit-grid-table-w)`; у последней видимой колонки `<col>` без ширины (`width: auto`): в `fixed`-раскладке она получает остаток, то есть «добирает» ширину до контейнера, и нативно, без `ResizeObserver` (расхождение с разделом 10.1, раздел 15).

Ресайз (чистая логика в `create-column-resize.ts`, Pointer Events + `setPointerCapture` на ручке заголовка):

1. `pointerdown` запоминает начальную ширину и позицию, ставит захват.
2. `pointermove` считает `next = clamp(start + dx, minWidth)` и **только** вызывает `table.style.setProperty` для `--s-kit-grid-w-<i>`, `--s-kit-grid-table-w` и `--s-kit-grid-left-<j>` закреплённых колонок правее. Сигналов, `createStore` и перерендера строк нет: `<col>` и sticky-ячейки перестраивает сам браузер.
3. `pointerup` один раз пишет итоговую ширину в состояние и вызывает `onColumnWidthsChange`. `Escape` во время перетаскивания возвращает переменные к значениям из состояния и ничего не сообщает наружу.
4. Двойной клик по ручке сбрасывает ширину колонки на `GridColumn.width` (минус запись в `columnWidths`).
5. После `pointerup` переменные из состояния приходят тем же значением, что уже записано в DOM, поэтому второй раз ничего не двигается.

Высота строк с переносом меняется после ресайза; её подхватывает `ResizeObserver` окна рендера на каждой смонтированной строке (`measure`). Отдельного ручного `measure()` на каждый пиксель нет.

Побочный эффект: когда таблица уже контейнера, уменьшение ширины **последней** колонки ниже остатка на экране не видно (она просто занимает остаток), пока ширина не превысит его.

### 4.3. Закреплённые колонки и фон

- Sticky-колонки идут первыми и имеют `position: sticky` с `inset-inline-start` из `--s-kit-grid-left-<i>`; последняя закреплённая получает более заметный правый разделитель (`--s-kit-color-border-strong`), чтобы было видно, где кончается закреп.
- Фон sticky-ячеек непрозрачный: ячейка закрывает прокручиваемое под ней содержимое. Заливки состояний строки (выбрана, наведение) у sticky-ячеек считаются непрозрачными через `color-mix(in oklch, <заливка>, var(--s-kit-grid-bg))`, а не прозрачной заливкой.
- Слои: шапка закреплённой колонки (угол) выше шапки обычной выше sticky-ячеек тела выше обычных; значения z-index токенами внутри компонента (`--s-kit-grid-z-*`), не литералами.

## 5. Виртуализация

- Окно рендера `createVirtualWindow` (этап 3) на скроллере грида, `count = rows.length`, `overscan` 12, оценка высоты — `rowHeight` или вычисленное значение `--s-kit-control-height` (а при его отсутствии `--s-kit-control-height-md`, потом 32), реальная высота измеряется (`ref={window.measure}`, строке нужен `data-index`).
- Невидимые строки заменяют две spacer-строки `<tr aria-hidden="true" role="presentation">` в `<tbody>`; таблица сохраняет семантику, `<colgroup>` и sticky-шапку.
- **Расширение контракта окна рендера (часть 1):** шапка лежит в том же скроллере, поэтому список начинается не с нуля. В `RenderWindowOptions` добавляется необязательное `scrollMargin?: Accessor<number>`, которое реализация на TanStack Virtual передаёт в опцию `scrollMargin`; `createFullWindow` его игнорирует. Значение — высота шапки (измеряется один раз и при смене размера обёртки). Существующие потребители (ListBox) не передают его и не меняются.
- `virtualized={false}` рендерит все строки подряд (`createFullWindow`), spacer-строк нет.
- Поиск браузера (Ctrl+F) строки вне окна не находит: компромисс из раздела 6.
- Цель производительности (раздел 6.3): Grid на 100 000 строк × 12 колонок, скрипт равномерно меняет `scrollTop` 10 с, не более 5 % кадров длиннее 16,7 мс, в DOM не больше окна плюс `overscan`; ресайз колонки при этом не вызывает перерендера строк (раздел 13).

## 6. Заголовок и сортировка

- `<th scope="col">` на колонку; для сортируемой колонки внутри заголовка кнопка с названием и стрелкой слева от текста (у неактивной приглушённая); `aria-sort="ascending" | "descending"` только у активной, у остальных сортируемых `aria-sort="none"`.
- Клик (и Enter, Space на кнопке) делает цикл `asc → desc → null` (`next-sort.ts`, чистая функция); смена колонки начинает с `asc`.
- Ручка ресайза: `<span class="…" role="separator" aria-orientation="vertical">` на правом краю `<th>`, зона касания 8 px (центр на границе), `cursor: col-resize`, `touch-action: none`. В Tab-порядок не входит (решение 1: клавиатурного ресайза в 4а нет). У закреплённых и обычных колонок поведение одинаковое.
- Заголовок колонки чекбоксов: главный Checkbox с `indeterminate` («все / часть / ничего», раздел 7) по ключам загруженных строк; он управляет только строками текущей загрузки (`rows`), не окном DOM и не серверным результатом.

## 7. Выбор строк

- Колонка чекбоксов включается `selectable`: первая колонка, ширина `--s-kit-grid-select-width` (по умолчанию `44px`), sticky всегда (решение по умолчанию: без этого чекбоксы уезжают при горизонтальной прокрутке, а смещения закреплённых колонок считаются от её ширины).
- Состояние выбора это `ReadonlySet<RowKey>`; чистые функции в `selection-state.ts`: `toggleKey`, `selectAllKeys(rows)`, `clearKeys(rows)` (убирает только ключи загруженных строк, ключи других загрузок сохраняются), `selectionOf(rows, keys)` → `'none' | 'some' | 'all'`.
- **Клик по строке** (по `<tr>`, но не по интерактивной цели) переключает выбор. Интерактивная цель определяется `is-interactive-target.ts`: ближайший предок до `<tr>` с `button`, `a[href]`, `input`, `select`, `textarea`, `summary`, `label`, `[role="button"]`, `[role="combobox"]`, `[role="menuitem"]`, `[contenteditable]` или `[data-grid-no-select]`. Клик по `<label>` внутри ячейки не должен выбирать строку: у чекбокса строки своя активация.
- **Двойной клик:** браузер присылает `click`, `click`, `dblclick`; два клика (два переключения) гасят друг друга, поэтому чистый выбор не меняется, и откат выбора не пишется отдельно. По `dblclick` на неинтерактивной цели вызывается `onRowDoubleClick(row)`. `onSelectedKeysChange` при этом вызывается дважды (включение и выключение): это следствие выбранного поведения (раздел 16, вопрос 2).
- Выделенная строка получает `data-selected` и `aria-selected="true"` на `<tr>`; заливка `--s-kit-color-row-selected`.
- Выбор не сбрасывается при смене `rows`: сбрасывает страница, если считает нужным.

## 8. Контекстное меню строки

- Один `ContextMenu.Root` на весь грид (`grid-row-menu.tsx`), управляемый `open` и `anchorPoint`; пока меню открыто, в состоянии лежит ключ строки, для которой оно открыто, а содержимое `rowContextMenu(row)` вызывается лениво при открытии, по строке с этим ключом (ключ, а не индекс: окно может сместиться).
- Открытие мышью: `contextmenu` на `<tbody>` (делегирование), строка определяется по `data-row-key` ближайшего `<tr>` (ключ в атрибуте строкой; `String(key)`), `preventDefault`, точка — координаты клика. Если `rowContextMenu` не передан, событие не перехватывается (браузерное меню остаётся).
- Открытие с клавиатуры: Shift+F10 и клавиша ContextMenu (`keydown` на `<tbody>`) на любом элементе внутри строки; меню встаёт у этого элемента. Если фокус вне тела (шапка), меню не открывается.
- Правый клик строку не выбирает.
- Закрытие: Esc, клик вне, выбор пункта, **прокрутка грида** и изменение размера окна (уже умеет `createCloseOnViewportChange` из этапа 2; прокрутка внутри самого меню его не закрывает).
- Фокус после закрытия возвращается на инициатор; если инициатор размонтирован (строка вышла из окна), фокус переходит на корень грида (`tabindex="-1"` на корне).

## 9. Панели и хост

- Корень грида даёт `PanelHostContext` (`Accessor<Element>` на сам корень): панели из ячеек (Select, Combobox, Popover) монтируются в корень грида, а не рядом с `<td>` (внутри `<table>` панель быть не может: `table` входит в блокирующие предки `resolvePanelHost`).
- Правило прокрутки (раздел 8.4): контекстное меню закрывается при прокрутке грида; Select и другая панель из ячейки остаются открытыми, пока её инициатор смонтирован (`autoUpdate` Floating UI держит позицию); когда строка выходит из окна рендера и размонтируется, панель закрывается через очистку компонента (`onOpenChange(false)`) без ошибок, без потери фокуса на `body`: фокус идёт на корень грида.
- Изоляция событий из этапа 2 действует без изменений: клики и двойные клики внутри панели не доходят до обработчиков строки (раздел 8.3); это проверяется критерием приёмки (раздел 13).

## 13. Критерии приёмки

Выполняются на странице «Грид» playground, в Chrome, в обеих темах:

1. **Производительность (раздел 6.3):** 100 000 строк × 12 колонок, production-сборка; равномерная прокрутка 10 с (полный проход и 20 000 px/с), не более 5 % кадров длиннее 16,7 мс; число `<tr>` в DOM не больше окна плюс `overscan`.
2. **Ресайз без перерисовки:** во время перетаскивания (замер по счётчику вызовов `cell`/`value` и по числу записей в DOM-мутациях строк) строки не перерисовываются; в юнит-тесте `create-column-resize` проверяется, что до `pointerup` состояние и колбэк не меняются, а переменные пишутся.
3. **Раскладка (раздел 10.1):** сумма ширин колонок в состоянии совпадает с `table.offsetWidth` (с учётом добора последней); длинное содержимое при прокрутке не раздвигает колонки; горизонтальная прокрутка с закреплёнными колонками без наложений и зазоров между sticky-ячейками; ресайз закреплённой и обычной колонки, скрытие колонки через пропсы; корпус: общая рамка и скругление, углы не прорезаются.
4. **Фокус (критерий 7, раздел 5.1):** кольцо фокуса у кнопки сортировки, чекбокса строки и контрола в ячейке видно целиком внутри рамки, не под sticky-шапкой и не под sticky-колонкой (Tab и Shift+Tab по таблице с прокруткой).
5. **Сценарий (а) критерия 6:** контекстное меню строки открывается правым кликом и Shift+F10 на чекбоксе, встаёт в точке или у элемента, не обрезается, закрывается прокруткой грида; клик по пункту не выбирает строку.
6. **Сценарий (г) критерия 6:** Select из ячейки открывается над таблицей (не обрезан скроллером), остаётся открытым при прокрутке, пока строка смонтирована, закрывается без ошибок при выходе строки из окна, фокус идёт на корень; клик и двойной клик по опции не выбирают строку и не вызывают `onRowDoubleClick`.
7. **Выбор:** клик по строке, по чекбоксу, главный чекбокс (все / часть / ничего), клик по контролу внутри ячейки выбор не меняет; двойной клик вызывает `onRowDoubleClick` и оставляет выбор прежним; выбор сохраняется при замене `rows`.
8. **Состояния:** загрузка (заглушки, `progressbar` с именем, `aria-busy`, фокус на корень), пусто (кнопка сброса только при `onEmptyReset`), объявление результата `aria-live`.
9. **Тесты:** чистые функции и поведение (сортировка, выбор, клики, меню, состояния) покрыты тестами `@solidjs/testing-library` с тестовым адаптером окна рендера; jsdom геометрию не считает, раскладочные проверки идут в playground.

## 15. Расхождения с зонтичным и риски

**Расхождения с зонтичным:**

- Последняя колонка добирает остаток нативно (`width: auto` у `<col>` последней колонки и `min-inline-size` таблицы), а не через `ResizeObserver` (раздел 10.1, 10.2).
- Видимость и закрепление колонок в 4а не состояние (`hidden`, `locked` только из `GridColumn`); controlled-тройки появятся в 4б вместе с меню колонок.
- `rowContextMenu` возвращает JSX, а не `MenuItem[]`.
- Колонка чекбоксов sticky всегда.
- Тег этапа `v0.5.0`.

**Риски:**

- **Ресайз и sticky:** смещения закреплённых колонок на лету меняются записью CSS-переменных; риск мигания sticky-ячеек в Safari (не проверяется, раздел 16, вопрос 4).
- **`scrollMargin` + переменная высота строк:** при смене высоты шапки (размер обёртки) смещение пересчитывается; проверяется на странице «Грид» сменой `data-s-kit-size`.
- **Объём 4а:** самое тяжёлое место это части 2 и 4. Если часть 2 разрастается, ресайз и закрепление выделяются в отдельный план.
- **Непрозрачность sticky-фона** при заливках состояния: расчёт через `color-mix` над `--s-kit-grid-bg`; при полупрозрачном `--s-kit-grid-bg` эффект «просвечивания» возможен (потребитель задаёт непрозрачный фон).

## 16. Открытые вопросы

1. **Высота грида по умолчанию:** `100%` родителя с запасным `max-block-size: 32rem` (рекомендация) или фиксированная высота. Меняется одной строкой токена.
2. **Двойной клик и выбор:** принято «клик переключает, двойной клик откатывает». Но два клика двойного клика уже гасят друг друга, поэтому отдельного отката нет, а `onSelectedKeysChange` вызывается дважды. Если в референсе клик не переключал, а выбирал (не снимал), поведение расходится; код референса недоступен, поэтому сверяется глазами владельца на странице «Грид».
3. **Sticky колонка чекбоксов:** принято «всегда sticky»; если нужен вариант «sticky только при закреплённых колонках», это правка в `column-layout.ts`.
4. **Firefox и Safari:** грид, как и прежние этапы, проверяется в Chrome; sticky при ресайзе и `light-dark()` в Safari — известный долг.
5. **Тег `v0.5.0`** на конец 4а (зонтичный не называет тег для 4а).
