# Этап 5, часть 4. DateTimePicker

Статус: принята владельцем 2026-11-03 («пиши спеку и план и выполняй»; открытые вопросы раздела 12 приняты по рекомендациям), реализация по плану `docs/superpowers/plans/2026-11-03-stage-5-date-time-picker.md`. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md`, спеки `2026-11-03-stage-5-date-picker-design.md` (DatePicker и `PickerField`), `2026-11-03-stage-5-time-picker-design.md` (TimePicker и `TimeColumns`), `2026-11-02-stage-5-calendar-design.md`. Здесь только то, чего в них нет: значение «дата и время», панель из календаря и колонок времени, их общая модель выбора, смена поведения Tab в `PickerField`.

## 1. Рамки

**DateTimePicker** это поле даты со временем: текстовый ввод, значок и одна панель с `Calendar` слева и колонками времени (`TimeColumns`) справа. Значение это ISO-строка без часового пояса `'2026-11-03T14:30'` (`YYYY-MM-DDTHH:mm`) или `null` (раздел 2 зонтичного). Часового пояса и секунд нет.

**Правила открытия те же, что у DatePicker и TimePicker (требование владельца 2026-11-03):** клик по полю открывает панель, клик по значку открывает (при открытой закрывает), ArrowDown открывает и переносит фокус в панель. Они живут в `PickerField` и здесь не переопределяются.

**Вне объёма (первая версия):** диапазон (`DateTimeRangePicker`), секунды, часовые пояса, маска ввода, пользовательский формат, ввод только времени без даты, отдельные поля даты и времени.

## 2. Что меняется в существующем

- **`PickerField`:** новый проп `panelTab?: 'close' | 'move'` (по умолчанию `'close'`, как сейчас). При `'move'` Tab и Shift+Tab внутри панели ходят по её tabbable-элементам обычным порядком, а панель закрывается (фокус в поле) только когда Tab выходит за край: Tab на последнем элементе или Shift+Tab на первом. Нужно DateTimePicker: в панели несколько областей (шапка календаря, сетка дней, колонки времени, «Сейчас»), и без этого до колонок времени не добраться с клавиатуры. DatePicker остаётся на `'close'` (принятое поведение).
- **TimePicker:** переходит на `panelTab='move'`. Это исправление расхождения с его спекой (раздел 5, таблица клавиатуры: Tab ходит между колонками и «Сейчас», закрывает панель только на выходе); при реализации TimePicker оболочка всегда закрывала панель на Tab.
- **Новое:** `src/utils/date-time/` (хелперы, раздел 6), `src/components/date-time-picker/`, подпуть `@stark/solid-kit/date-time-picker` (по правилу `./*`; проверяет `verify-package-form.sh`).
- Calendar и `TimeColumns` не меняются (подвалы «Сегодня» и «Сейчас» отключаются существующими `showToday={false}` и `showNow={false}`).

## 3. Публичный API

```ts
value?: string | null;                 // 'YYYY-MM-DDTHH:mm'
defaultValue?: string | null;
onValueChange?: (value: string | null) => void;

open?: boolean;
defaultOpen?: boolean;
onOpenChange?: (open: boolean) => void;

min?: string;                          // 'YYYY-MM-DDTHH:mm', включительно
max?: string;
isDateDisabled?: (date: string) => boolean;   // получает 'YYYY-MM-DD'
isTimeDisabled?: (time: string) => boolean;   // получает 'HH:mm', для любой даты
minuteStep?: 1 | 2 | 5 | 10 | 15 | 20 | 30;   // шаг колонки минут, по умолчанию 1

locale?: string;                       // по умолчанию 'ru'; формат текста, названия, первый день недели
hour12?: boolean;                      // по умолчанию как у локали
firstDayOfWeek?: 0 | 1 | 2 | 3 | 4 | 5 | 6;
showNow?: boolean;                     // кнопка «Сейчас» в подвале панели, по умолчанию true
placeholder?: string;
disabled?: boolean;
readOnly?: boolean;
clearable?: boolean;                   // по умолчанию false
name?: string;                         // скрытое поле с 'YYYY-MM-DDTHH:mm' для форм
size?: 'sm' | 'md' | 'lg';
labels?: Partial<DateTimePickerLabels>;
calendarLabels?: Partial<CalendarLabels>;
// остальные атрибуты input (id, aria-*, required, autofocus, onBlur, onFocus…) попадают на <input>
```

- Тройки `value` и `open` через `createControllableSignal` (имя `DateTimePicker`).
- Строка в `value`, `min`, `max` строго `YYYY-MM-DDTHH:mm`. Недопустимая: dev-предупреждение и поведение как у «пусто» (`readDateTimeProp`). `min` позже `max`: dev-предупреждение, границы игнорируются.
- `DateTimePickerLabels` (русский по умолчанию): `openPicker` («Открыть выбор даты и времени»), `clear` («Очистить»), `panel` («Выбор даты и времени»), `now` («Сейчас»), `day`, `month`, `year` («дд», «мм», «гггг»), `hourPart`, `minutePart` («чч», «мм»), `hours` («Часы»), `minutes` («Минуты»), `period` («AM/PM»).

## 4. Текст в поле

- **Формат:** текст даты по образцу локали, пробел, текст времени: `03.11.2026 14:30` (`ru`), `11/03/2026 2:30 PM` (`en-US`). Части форматируют `formatDateText` и `formatTimeText`.
- **Разбор набранного** (`parseDateTimeText`): первая часть до пробела это дата (`parseDateText`: части через `.`, `/`, `-` или 8 цифр подряд, год ровно 4 цифры), остаток это время (`parseTimeText`: те же правила, что у TimePicker). Дата без времени допустима (`03.11.2026`): время остаётся прежним, а при пустом значении `00:00` (вопрос 2). Время без даты не принимается. Разделитель частей даты пробелом (`03 11 2026`) в составном тексте не поддерживается: пробел отделяет дату от времени.
- **Принятие и откат как у DatePicker:** текст хранится отдельно от значения; принимается по Enter и уходу из поля; пустой текст принимается как `null`; невалидный или запрещённый (вне `min`/`max`, `isDateDisabled`, `isTimeDisabled`) откатывается к тексту значения. Набранная допустимая дата сразу переключает календарь на свой месяц и фокусирует её, набранное допустимое время подсвечивается и прокручивается в колонках; значение при этом не меняется.
- Внешнее изменение `value` обновляет текст, если пользователь не печатает. `Esc` при открытой панели закрывает её, при закрытой откатывает набранное.

## 5. Панель и модель выбора

**Раскладка.** `role="dialog"`. Слева `Calendar` (без своего подвала), справа колонки времени `TimeColumns` (без своего подвала), между ними разделитель; под ними один общий подвал с кнопкой «Сейчас». На узкой ширине (меньше суммы ширин) область времени переносится под календарь.

**Модель.** Панель редактирует то же значение, что поле, каждый выбор применяется сразу (как в TimePicker). Недостающая часть: время `00:00`, а если даты ещё нет, сегодняшняя дата.

| Действие | Результат |
|---|---|
| Выбор дня в календаре | значение = выбранная дата + текущее время (при пустом значении `00:00`); время подгоняется под ограничения этой даты (`fitTimeToDate`); если на дате нет допустимого времени, выбор игнорируется; панель остаётся открытой |
| Выбор часа | значение = текущая дата (при пустом значении сегодня) + выбранный час и текущие минуты; остальное как в TimePicker (подтягивание минут, период, шаг); панель остаётся открытой |
| Выбор минут (24 часа) или периода (12 часов) | значение обновляется, панель закрывается, фокус в поле (`onFinish` колонок) |
| «Сейчас» | значение = сегодня + текущее время, округлённое вниз по `minuteStep`, подогнанное под ограничения; закрывает панель; отключена, если допустимого времени сегодня нет |
| Enter в поле, уход из поля | принимают набранный текст и закрывают панель |
| Esc | закрывает панель; уже применённые выборы остаются (вопрос 1) |

**Ограничения по дате.** Для колонок времени границы берутся для текущей даты значения (при пустом значении сегодня): `min` ограничивает время только на дате `min`, `max` только на дате `max` (`timeBoundsForDate`); `isTimeDisabled` действует на любой дате. Календарь отключает дни вне `[date(min), date(max)]` и по `isDateDisabled`.

**Подгонка времени (`fitTimeToDate`).** Если при смене даты прежнее время недопустимо (раньше `min`, позже `max` или отключено предикатом), берётся ближайшее допустимое время суток с шагом `minuteStep` (при равенстве раннее). Нет допустимого времени вообще: `null`, выбор даты игнорируется.

**Клавиатура.** Внутри панели работают модели Calendar (спека Calendar, раздел 5) и колонок (спека TimePicker, раздел 5). Tab и Shift+Tab ходят по порядку: кнопки шапки календаря, сетка дней (одна остановка), колонка часов, колонка минут, (период), «Сейчас»; из последней остановки Tab закрывает панель и возвращает фокус в поле (`panelTab='move'`). ArrowDown из поля переносит фокус на выбранный (или сфокусированный) день календаря.

## 7. Вид

Оболочка поля это `PickerField`; значок календаря (как у DatePicker). Ширина по умолчанию `--s-kit-date-time-picker-width` (13rem для 24 часов, 15.5rem для 12 часов; `clearable` добавляет квадрат кнопки очистки, как у остальных). Панель: общий материал панелей; Calendar и колонки в ряд (`display: flex`, `flex-wrap: wrap`, `align-items: stretch`), между ними граница `--s-kit-color-border`; подвал по центру с отступами как у Calendar. Токены: существующие плюс `--s-kit-date-time-picker-width`. CSS с нативной вложенностью, без литералов цветов.

## 11. Критерии готовности

- а) клик по полю открывает панель, повторный клик её не закрывает; клик по значку открывает, повторный закрывает; значение до выбора не меняется;
- б) открытие кликом оставляет курсор в поле; ArrowDown переносит фокус на день календаря; Tab и Shift+Tab ходят по областям панели и закрывают её только на выходе;
- в) выбор дня и часа применяются сразу и не закрывают панель; выбор минут (периода) и «Сейчас» закрывают её, фокус в поле; значение при выборе одной части дополняется по правилам раздела 5;
- г) набранное `03.11.2026 14:30` показывается в календаре и колонках до принятия; Enter и уход из поля принимают; дата без времени принимается; время без даты, невалидный и запрещённый текст откатываются; пустой даёт `null`;
- д) `min`, `max` (с зависимостью времени от даты), `isDateDisabled`, `isTimeDisabled`, `minuteStep`, `disabled`, `readOnly`, `clearable`, `name` (значение в `FormData`) работают; смена даты подгоняет недопустимое время;
- е) 12-часовой вид (`en-US`, `hour12`): текст `11/03/2026 2:30 PM`, три колонки, значение 24-часовое;
- ж) внутри `Field` поле получает `id`, `aria-describedby`, `aria-invalid`; подпись фокусирует поле и не открывает панель;
- з) панель не обрезается предками с `overflow`, `transform`, `filter`, `contain`; в диалоге Esc закрывает сначала панель, потом диалог;
- и) обе темы читаемы; хелперы покрыты тестами; `pnpm check` и `verify-package-form.sh` зелёные;
- к) DateTimePicker стоит в ряду контролов той же высоты, критерий 7 зонтичного для него пройден.

## 12. Открытые вопросы (приняты по рекомендациям)

1. **Применение выбора.** Каждый выбор применяется сразу, Esc значения не откатывает (как в TimePicker). Альтернатива: черновик и кнопка «Готово» (надёжнее для «поправил и передумал», но лишний шаг и новая модель состояния).
2. **Недостающая часть.** При пустом значении выбор дня даёт время `00:00`, выбор времени даёт сегодняшнюю дату, набранная дата без времени даёт `00:00`; при непустом значении недостающая часть берётся из текущего. Альтернатива: значение появляется только после выбора обеих частей.
3. **Один подвал «Сейчас»** вместо двух («Сегодня» календаря и «Сейчас» колонок): выбирает и дату, и время.
4. **Раскладка в ряд**, на узкой ширине колонки времени переносятся под календарь. Альтернатива: вкладки «Дата» и «Время» (компактнее, но два шага и скрытая половина значения).
5. **Tab ходит внутри панели** (`panelTab='move'`) для DateTimePicker и TimePicker; DatePicker остаётся на «закрывать» (принятое раньше). Альтернатива: везде «двигать» (меняет принятое поведение DatePicker, поэтому отдельным решением).
6. **Время без даты не принимается** при вводе: иначе тихо выбирается сегодняшняя дата. Альтернатива: принимать как сегодня.

## 13. Применённые паттерны и границы абстракций

- **Композиция:** DateTimePicker это `PickerField` плюс `Calendar` плюс `TimeColumns`, общая модель только в нём самом.
- **Adapter:** ISO-строка `YYYY-MM-DDTHH:mm` ↔ `DateTimeParts` ↔ текст по локали, преобразование один раз на границе компонента.
- **Чистые правила отдельно от разметки:** допустимость, границы времени по дате и подгонка времени считают хелперы раздела 6 без DOM.
- DateTimePicker зависит от Calendar, `TimeColumns`, хелперов дат и времени и `PickerField`; DatePicker и TimePicker от него не зависят.

## 14. Что не проверено

Всё, что касается браузеров, кроме Chrome; сенсорные устройства (панель в две области на узком экране); IME при вводе; экранные читалки (две области в одном диалоге); локали с порядком «период перед временем» и нелатинскими цифрами; переходы на летнее время не затрагиваются: значение это стенные часы без зоны.

## 15. Итоги реализации и приёмки (2026-11-03)

**Реализовано** по плану в четыре части: `PickerField.panelTab` (TimePicker переведён на `move`, спека TimePicker поправлена), хелперы `src/utils/date-time/`, компонент `src/components/date-time-picker/`, страница «Выбор даты и времени» в playground.

**Уточнения к разделу 5, принятые при реализации:**
- Если значение пусто, а сегодняшняя дата запрещена (`min`, `max`, `isDateDisabled`), выбор часа относится к дате, показанной в календаре (если и она запрещена, выбор игнорируется). Колонки времени получают границы для этой же даты.
- «Сейчас» подгоняется под ограничения сегодняшнего дня (`fitTimeToDate`), в отличие от «Сейчас» TimePicker, которая в таком случае отключается; отключена она только когда сегодня нет допустимого времени.
- Набранная целиком дата со временем принимается только если допустима, набранная одна дата получает прежнее время, подогнанное под границы её дня.
- Календарь внутри панели монтируется без своего «Сегодня» (`showToday={false}`), колонки без своего «Сейчас» (`showNow={false}`).
- Выбор дня мышью переводит фокус на день (поведение Calendar), поэтому после него печать в поле требует клика в поле; выбор часа с фокусом в поле его оставляет там.
