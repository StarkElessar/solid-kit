# Этап 4б, вторая часть. Меню колонки: закрепление и видимость

Статус: дизайн согласован владельцем в диалоге 2026-11-01 (состав меню, модель состояния, три раздела дизайна); спек ждёт просмотра владельца. Зонтичный спек: `2026-10-28-solid-kit-umbrella-design.md` (далее «зонтичный»), ссылки вида «раздел N» относятся к нему, если не сказано иное. Предыдущая часть этапа: `2026-11-01-stage-4b-pager-design.md` (пейджер, принят и закоммичен). Спек 4а: `2026-10-31-stage-4a-grid-core-design.md`.

Этап 4б в зонтичном (раздел 13) режется на подэтапы со своими спеком, планом и приёмкой. Этот спек описывает **только меню колонки**; автосуммы и серверная группировка получают свои спеки. Тег `v1.0.0` ставится после всего 4б.

## 1. Рамки

Кнопка меню в каждой ячейке шапки Grid и меню по ней, построенное на `ContextMenu` (решение владельца 2026-10-31: меню колонок переиспользует ContextMenu, дополняя его, а не пишется отдельно). Состояние «скрыта / закреплена» становится состоянием грида с controlled-тройками.

**Решения владельца, принятые в диалоге 2026-11-01:**

1. **Состав меню:** «Закрепить / Открепить» для этой колонки и отдельный пункт-подменю «Список колонок» (решение владельца после первой версии с плоским списком) со списком всех колонок и галочками видимости. Пункт «Сгруппировать» добавляется вместе с группировкой (её в гриде пока нет). Пункты сортировки в меню не входят.
2. **Состояние:** тройки по id колонок, как `columnWidths`: наборы `hiddenColumns` и `lockedColumns`; поля `GridColumn.hidden` и `GridColumn.locked` становятся начальными значениями.
3. **Решения исполнителя, подтверждённые владельцем:** уведомление о закрытии срабатывает только при реальном изменении набора видимых колонок; скрытие колонки из её же меню закрывает меню; последнюю видимую колонку скрыть нельзя; правый клик по заголовку меню не открывает; кнопка отключается на время `loading`; меню отключается пропсом `columnMenu={false}`.

**Вне объёма:** пункт «Сгруппировать», сортировка из меню, порядок колонок (перетаскивание), поиск по списку колонок, закрепление справа, сохранение настроек (это дело страницы через колбэки), правый клик по заголовку.

## 2. Публичный API

### 2.1. Grid

К `GridProps` добавляются:

```ts
hiddenColumns?: ReadonlySet<string>;           // id скрытых колонок
defaultHiddenColumns?: ReadonlySet<string>;
onHiddenColumnsChange?: (next: ReadonlySet<string>) => void;   // на каждое изменение, новый Set
lockedColumns?: ReadonlySet<string>;           // id закреплённых колонок
defaultLockedColumns?: ReadonlySet<string>;
onLockedColumnsChange?: (next: ReadonlySet<string>) => void;
onColumnMenuClose?: (visibleIds: readonly string[]) => void;   // раздел 5.2
columnMenu?: boolean;                          // кнопки меню в шапке; по умолчанию true
columnMenuLabels?: Partial<GridColumnMenuLabels>;
```

- Тройки работают через `createControllableSignal` (имя `Grid`, предупреждение при смене режима). Без пропса начальные наборы строятся из `GridColumn.hidden` и `GridColumn.locked` и читаются один раз; если пропс передан, поля колонок игнорируются.
- Прежний набор не мутируется: колбэк получает новый `Set`.
- `GridColumnMenuLabels` (отдельный файл-тип): `button` (функция `(title: string) => string`, «Меню колонки «Заказчик»»), `lock` («Закрепить»), `unlock` («Открепить»), `columns` («Список колонок»: пункт-подменю).
- Если в наборах есть id, которых нет в `columns`, они игнорируются.
- **Оговорка:** колонка, добавленная в `columns` позже с `hidden: true`, в неконтролируемом режиме не будет скрыта (начальные значения читаются один раз); для динамических наборов колонок страница передаёт `hiddenColumns`.

### 2.2. GridColumn

Комментарии к `locked` и `hidden` меняются: «начальное значение; текущее состояние — `lockedColumns` / `hiddenColumns` грида». Тип полей не меняется.

### 2.3. ContextMenu (дополнения)

- `ContextMenu.CheckboxItem`: `checked: boolean`, `onCheckedChange?: (checked: boolean) => void`, `disabled`, `closeOnSelect` (по умолчанию **`false`**), `variant`, `class`, `style`. `role="menuitemcheckbox"`, `aria-checked`, отметка слева.
- `ContextMenu.Root`: проп `anchorElement?: HTMLElement`. Меню якорится по прямоугольнику элемента, а не по точке. Клик по самому якорю не считается dismiss (иначе повторный клик по кнопке закрыл бы меню и открыл снова): переключением занимается обработчик кнопки.
- `ContextMenu.Content`: проп `placement?: Placement` (по умолчанию `'bottom-start'`; меню колонки задаёт `'bottom-end'`).

Существующее поведение (точка клика, меню строки, подменю) не меняется.

## 3. Чистые функции

Каждая в своём файле, с таблицей тестов (`src/components/grid/`).

- `toggle-id.ts`: `toggleId(set, id)`: новый `Set` с добавленным или удалённым id; исходный не меняется.
- `ids-with-flag.ts`: `idsWithFlag(columns, flag)`: id колонок с `hidden` или `locked`, для начальных наборов.
- `apply-column-state.ts`: `applyColumnState(columns, hidden, locked)`: колонки с `hidden` и `locked`, выставленными по наборам; остальные поля и порядок сохраняются, колонки без изменений переиспользуются по ссылке.
- `visible-column-ids.ts`: `visibleColumnIds(columns, hidden)`: id видимых колонок в порядке `columns`.
- `can-hide-column.ts`: `canHideColumn(columns, hidden, id)`: `false`, если колонка последняя из видимых.
- сравнение списков id: существующая `same-items.ts` (`sameItems`).

## 4. Меню

**Одно меню на весь грид** (как `GridRowMenu`), в хосте панели, то есть в корне грида. Грид хранит цель открытого меню: id колонки, кнопка-якорь и источник открытия (`pointer` или `keyboard`). Пункты строятся по колонке в момент открытия.

**Кнопка** (`GridColumnMenuButton`): три вертикальные точки, всегда видимая; `aria-haspopup="menu"`, `aria-expanded`, `aria-label` из `labels.button(title)`. Стоит в ячейке шапки между кнопкой сортировки и ручкой ресайза; клик переключает меню этой колонки. С клавиатуры Enter и Space открывают меню с фокусом на первом пункте (`source: 'keyboard'`); мышью меню открывается с фокусом на панели, как меню строки. При `loading` кнопка отключена, как ручки ресайза. Размер кнопки фиксирован (24 px); заголовок сжимается многоточием, а не вытесняет её.

**Содержимое меню колонки X:**

1. `ContextMenu.Item`: «Закрепить» или «Открепить» (по `lockedColumns`); закрывает меню.
2. `ContextMenu.Separator`.
3. `ContextMenu.Sub` «Список колонок» (`SubTrigger` со стрелкой, открывается кликом, Enter, Space, ArrowRight и наведением): внутри по `ContextMenu.CheckboxItem` на каждую колонку из `columns` (в порядке `columns`, включая текущую), `checked` = не скрыта, `closeOnSelect={false}`. Переключатель последней видимой колонки отключён. Подменю названо по своему `SubTrigger`; длинный список прокручивается внутри панели подменю. Esc закрывает по одному слою: сначала подменю, затем меню.

Закрытие меню: Esc, клик снаружи, Tab, прокрутка грида или страницы и изменение размера окна (`createCloseOnViewportChange`, как у меню строки; правило раздела 8.4). Фокус возвращается на кнопку.

## 5. Поведение

### 5.1. Закрепление и видимость

- Закреплённые колонки идут первыми, порядок между собой сохраняется (как в `column-layout`). После изменения пересчитываются sticky-смещения, `data-sticky-last` и заглушки загрузки; пересчёт идёт от `applyColumnState`, а не от пропсов колонок.
- Скрытие и показ работают на лету: индексы CSS-переменных ширин считаются по видимым колонкам, пользовательские ширины хранятся по id и переживают скрытие.
- **Скрытие колонки из её же меню:** кнопка-якорь исчезает из DOM, поэтому меню закрывается сразу после изменения; фокус уходит на корень грида (`restoreFocusTo` получает отсоединённый инициатор и берёт область вызова).
- Закреплённая и скрытая колонка остаётся в `lockedColumns`: раскрытие вернёт её на закреплённое место.

### 5.2. `onColumnMenuClose`

В момент открытия запоминается список видимых id, в момент закрытия сравнивается с текущим (`sameItems`). Если они различаются, `onColumnMenuClose(visibleIds)` вызывается один раз, порядок id как в `columns`. В controlled-режиме сравнивается то, что страница реально применила: проигнорированные изменения колбэка не вызывают. Размонтирование грида при открытом меню колбэк не вызывает. Закрепление на этот колбэк не влияет.

### 5.3. Прочее

- Правый клик по заголовку меню не открывает (не путать с меню строки).
- `columnMenu={false}` убирает кнопки и меню; тройки состояния продолжают работать (скрытие и закрепление можно вести извне).
- Меню колонки и меню строки не открыты одновременно: открытие одного закрывает другое (слои уже изолированы стеком панелей).

## 6. Вид и раскладка

- В ячейке шапки появляется обёртка `display: flex` (сама `th` остаётся табличной ячейкой): кнопка сортировки или заголовок занимает остаток, кнопка меню справа, ручка ресайза абсолютно по краю, как сейчас.
- Кнопка меню приглушена (`--s-kit-color-muted`), при наведении и фокусе цвет текста; кольцо фокуса внутреннее (грид задаёт `data-s-kit-focus-inset`). Цвета только токенами.
- Меню: стандартная панель ContextMenu, размер `md`; длинный список колонок прокручивается внутри панели (максимальная высота от Floating UI `size`; проверяется в приёмке, при необходимости `overflow-y: auto` на панели).
- Галочка переключателя слева, подпись обрезается многоточием с `title`, как у остальных пунктов.
- CSS по правилам проекта: нативная вложенность с `&`, токены, порядок свойств Stylelint.

| № | Часть | План | Почему в этом месте |

**Критерии (Chrome, обе темы):**

1. **Поведение:** открытие кнопкой мышью и клавиатурой; закрепление и открепление; скрытие и показ колонок на лету; последняя колонка отключена; скрытие своей колонки закрывает меню и отдаёт фокус гриду; повторный клик по кнопке закрывает меню; `onColumnMenuClose` вызывается один раз и только при изменении.
2. **Фокус (критерий 7 зонтичного):** настоящие Tab и Esc, кольцо у кнопки видно целиком внутри ячейки, фокус возвращается на кнопку.
3. **Сценарии (г) и (е) критерия 6:** прокрутка грида при открытом меню закрывает его; панель меню в top layer, изоляция событий, закрытие по клику снаружи.
4. **Раскладка:** кнопка не вытесняется заголовком при `minWidth` 60 и не наезжает на ручку ресайза; закреплённая колонка с меню; узкий вьюпорт (меню разворачивается `flip` и `shift`); длинный список колонок прокручивается внутри панели.
5. **Грид:** критерии 1 и 4 спека 4а и пейджера сохраняются: перф-замер не требуется, пока виртуализация и тело не менялись; достаточно прокрутки с открытием меню без пропусков кадров.
6. **Тесты:** `pnpm check` и `verify-package-form.sh` зелёные.

## 10. Расхождения с зонтичным и риски

**Расхождения:**

- Вместо `onColumnVisibilityChange` (разделы 7, 10.1, 13 и 14 зонтичного) введены `onHiddenColumnsChange` и `onLockedColumnsChange`: состояние по id и для видимости, и для закрепления; `onColumnMenuClose(visibleFields)` сохраняется как `onColumnMenuClose(visibleIds)`. Зонтичный поправляется вместе с этим спеком.
- «Сгруппировать» из описания меню в зонтичном переносится в спек группировки.

**Риски:**

- **Обёртка в ячейке шапки:** перенос сортировки внутрь flex-контейнера меняет разметку и тесты шапки; ручка ресайза и sticky не должны сдвинуться. Проверяется тестами и сравнением в Chrome (приёмка, критерий 4).
- **Пересчёт раскладки при скрытии:** `layout` зависит от видимых колонок; список колонок для шапки и ячеек не должен пересоздаваться при ресайзе (инвариант 4а). Покрывается тестом на живущие между ресайзами узлы.
- **Высота панели при многих колонках:** см. раздел 6.
- **Якорь исчезает:** скрытие текущей колонки и размонтирование строки/ячейки: меню закрывается явно (раздел 5.1), покрыто тестом.

**Заметка для финального анализа общего** (решение владельца 2026-10-31: объединять ContextMenu и ListBox после всех компонентов): `ContextMenu.CheckboxItem` с `closeOnSelect={false}` и мультивыбор в ListBox/MultiSelect пересекаются по фичам: отметка, `aria-checked` против `aria-selected`, оставание панели открытой, группа с подписью. Фиксируем совпадения, не объединяем.
